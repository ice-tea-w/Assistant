### 核心决策（与设计文档的偏差，都有理由）

1. **传输抽象成 `ITransport`，主线只做 `FolderTransport`。** 直连通道要 NAT 穿透/中继，
   成本与运维不可控；把"搬运"外包给网盘（OneDrive / 坚果云 / Syncthing）后，程序只负责
   "判断谁改了什么"，**新增第三方依赖 0**（Qt6Network 早已链接）。
2. **共享目录只放一份 `.sync/manifest.json`，不按设备分文件。** 设计文档原写
   `manifest-<deviceId>.json`，问题在于：纯下载方（B 只读 A 推的文件）会一直读到 A 的**陈旧**
   清单，算出哈希不一致 → 每轮都重新下载 A 上次推的东西。改成单一清单后，谁推谁更新，
   两端共用一份真相。
3. **冲突时"赢家"由 (mtime, hash) 确定性决定，不是"本地优先"。** 本地优先会来回乒乓。
4. **"改"优先于"删"**：一边删、一边改 → 保留改。
5. **安全阀**：对端清单为空但基线非空时**不执行删除**，直接判 `RemoteUnreachable`。
   防的是"网盘没同步完 → 本机以为对方删了所有文件 → 把本地清空"这种灾难。
6. **工作线程自带独立 `QSqlDatabase` 连接名**（`sync_worker`）。QSqlDatabase 连接不可跨线程，
   文档里 `setEngine(&syncEngine)` 的写法改成"工作线程内建引擎 + 按值捕获参数"。

### 自审揪出的两个真缺陷（都不在测试范围里，靠读代码发现）

1. **扫描不防 junction。** 引擎自己的目录递归只判了 `isDir()`，没判 `isSymLink()/isJunction()`，
   踩的正是 A1 踩过的同一个坑（`QDir::NoSymLinks` 挡不住 junction）。加 `kMaxScanDepth = 64`
   深度上限 + 跳过 reparse point。
2. **基线写入不是 compare-and-swap。** 若文件在比对之后、写基线之前又被改一次，会把这个
   改动记进基线 → **下次同步看不到它，永久丢更新**。改成写完基线后复核文件状态，不一致就不写。

### 另外三个靠"真跑"才发现的问题

1. **QML `TextField` 的 `background` 在原生 style 下会报警告**：
   `The current style does not support customization of this control`。
   项目既有写法是 **外层 `Rectangle` 画底色 + 控件 `background: null`**（见 `NotesPage.qml:199-207`），
   同步页已照此改。三个 TextField 改完，启动零警告。
2. **构建时报 `LNK1168: 无法打开 Assistant.exe 进行写入`** —— 上一个实例还在跑。
   编译前先 `Stop-Process Assistant`。
3. **`QTemporaryDir` 在测试结束时报 "Unable to remove ... read-only files"** —— 无害，
   SQLite WAL 文件句柄尚未完全释放。测试文件的临时目录改用显式管理工作目录。

## 五、单机演示双设备：两个必须补的口子

设计文档写的演示路线是「单机开两个实例」，真去跑才发现原样跑不通，补了两处：

1. **`--instance <名字>` 启动参数**（`src/main.cpp`）。数据目录由
   `QStandardPaths::AppConfigLocation` 决定，而它又由应用名决定 —— 两个进程同名就共用
   同一个 `config.json`，于是 `localRoot` 只能是同一个，压根不是"两台设备"。
   加上这个参数后，`Assistant.exe --instance B` 会用
   `%LOCALAPPDATA%\AssistantTeam\Assistant-B\`（独立 config + 5 个 db），实测成立。
2. **托盘菜单加「主面板」**（`TrayManager`）。原来打开主面板的**唯一**入口是搜索浮窗右上角
   的 🏠 按钮，而搜索浮窗只能靠全局热键唤出 —— 全局热键是独占的，第二个实例注册不上，
   于是它的「设备同步」页根本点不到。托盘菜单是它唯一的入口。

### 双实例真机验收（自动同步间隔 1 分钟，均为实测日志）

```
A（台式机, D:\synctest\pc1）  16:25:54  通道=共享目录 上传=1 下载=0 冲突=0
B（笔记本, D:\synctest\pc2）  16:25:57  通道=共享目录 上传=0 下载=1 冲突=0
两边再同步                    16:26:5x  上传=0 下载=0            ← 基线生效，不重复搬运
```

冲突路径（两边同时改成不同内容后再各自同步）：

```
B  16:27:57  上传=0 下载=1 冲突=1
产出：pc2\报告 (冲突副本 来自笔记本 20261015-162757).txt
      pc1 / shared 同款副本
```

两侧文件都在，没有一份被覆盖掉 —— 这就是"各改各的，事后合并"要的效果。
