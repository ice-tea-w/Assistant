# 2026-11-05（二）设备同步：一键开共享 / 一键连接

> 计划见 `docs/architecture/设备同步-一键共享实施计划.md`。上面 25 个 Step 已全绿，只剩 Task 6 的真机走查。

## 1. 起因

队友在设备同步页遇到「共享目录不可访问或不可写」，而这句提示只有 12 个字：

```
共享目录不可访问或不可写：<路径>
```

`probe()` 里四道关（路径空 / 不存在 / 建 `.sync` 失败 / 写不进 `.sync`）全部折成一个 `bool`，
用户无从判断是网络不通、权限不够，还是路径填错。同时教程里那条命令把路径写死成 `E:\SyncHub`，
和输入框里填的目录根本没有关系；`/grant:everyone,full` 也只管 SMB 共享权限，NTFS 那一半没人提。

结论是两件事一起做：**让失败说清楚原因，让成功不需要手敲命令。**

## 2. 做了什么

| 层 | 变化 |
|---|---|
| 纯函数 | 新增 `include/core/sync/SyncCommands.h` + `src/core/sync/SyncCommands.cpp`（namespace `Sync`） |
| 传输 | `FolderTransport` 加 `probeError()`，`probe()` 逐关写下失败原因 |

| 界面 | 主机模式加「一键开共享」+ 授权账号；连接方模式加「账号 / 密码」+「一键连接」；教程命令按当前界面值现算 |

## 3. 关键实现点

### 3.1 一次 UAC，两条命令

`net share` 需要管理员，`icacls` 也常常需要，所以不分开提权 —— 生成一个 `.bat` 一次跑完，
只弹一次 UAC：

```bat
@echo off
chcp 65001 >nul
net share <名>="<路径>" /grant:<账号>,change
if errorlevel 1 exit /b 1
icacls "<路径>" /grant "<账号>:(OI)(CI)M"
exit /b %errorlevel%
```

- `chcp 65001`：脚本按 UTF-8 写盘，不切代码页的话中文共享名会被 `cmd` 读成乱码。
- 先 `if errorlevel 1 exit /b 1`：共享没建成就不必再去改 ACL，失败原因也更准。
- 用 `change` 不用 `full`：同步只需要读写，`full` 会连改权限一起给出去。

### 3.2 提权返回值

`ShellExecuteExW` + `lpVerb="runas"` + `SEE_MASK_NOCLOSEPROCESS`，等进程结束取退出码。
UAC 被取消时 `GetLastError()` 是 `ERROR_CANCELLED(1223)`，这里映射成 `-1000`（`kElevationCancelled`），
界面据此提示「已取消」而不是「失败」——这两件事对用户的意义不一样。

### 3.3 连接方不需要提权

`net use \\主机\共享 /persistent:yes` 是当前用户级操作，直接 `QProcess` 参数列表调用，
不做 shell 拼接（路径里有空格和中文都不怕）。留空账号密码＝用当前登录凭据。

**已知代价**：密码会出现在 `net use` 的进程命令行里，本机管理员可见。界面上如实写了这一句。
代价换的是「不落盘持久化凭据」——把密码写进配置文件或 `cmdkey` 更糟。

### 3.4 `probe()` 语义没变

`probe()` 仍然只返回「能不能用」，新加的 `probeError()` 在同样四关里逐关记录文案，
`probe()` 直接复用它的结果。这样既没有改动既有调用方（`SyncEngine` 选通道），
也避免了「两个函数各判一套、结论打架」。

### 3.5 界面显示的命令只给 SMB 一半

折叠教程里展示的是 `net share ... /grant:...`，因为这是用户能看懂、也能单独执行的那一步；
`icacls` 由脚本自动补，写在说明里而不是塞进展示命令，避免一行太长看不清。
展示命令的目录/共享名/账号全部取界面当前值（`shareCmdText()`），不再是 `E:\SyncHub`。

## 4. 踩的坑

- **`miniz` 缺失**：合并 main 带进了插件市场依赖，本机 vcpkg 没有。vcpkg 下载器走代理失败，
  按 2026-11-04 记录的办法手动 `Invoke-WebRequest` 下 tarball 到 `D:\vcpkg\downloads\` 再装，
  SHA512 与 portfile 对得上。
- **`assistant_tests` 是显式源列表**：新 `.cpp` 不加进 `CMakeLists.txt` 就静默不参与编译，
  然后链接期才报 undefined reference。主程序那边是 `file(GLOB_RECURSE)`，两者行为不同。
- **most vexing parse**：`FolderTransport t(QString());` 被解析成函数声明，编译期没报错但行为莫名；
  改 `FolderTransport t{QString()};`。
- **PowerShell `-like '- [ ] **Step*'` 匹配不到**：`[ ]` 在通配符里是字符集，只匹配单个空格。
  要判断字面前缀就老实用 `.StartsWith()`。
- **`--page=N` 是死开关**：`MainPanel` 从 `selectedIndex` 改成 `selectedKey` 之后，
  `main.cpp:269` 的 `panelWindow->setProperty("selectedIndex", page)` 已经不生效（属性不存在，
  赋了也没人读）。这次走查临时把 `selectedKey` 默认值改成 `"sync"` 才进得去，改完又改回来了。
  以后要用这个开关，得把它换成 page → key 的映射。

单机（不需要第二台机器，本机已有 `SyncHub → E:\SyncHub` 共享）：

1. 主机模式，共享目录填 `E:\SyncHub`，共享名 `SyncHub`，账号留空 →「一键开共享」→ UAC 里点「是」→
   状态行给出 `\\<主机名>\SyncHub`，「复制地址」能拿到它。
2. 故意把账号填成 `alice`（一个不存在的账号）→ 应该失败，且失败文案指向 `net share` 而不是「网络不通」。
3. 切成连接方模式，填 `\\localhost\SyncHub` →「一键连接」→ 应成功并自动复检（绿点 + 清单存在）。
4. 连接方模式填一个不存在的 `\\localhost\NoSuchShare` → 失败文案应提到 445 / 网络路径 / 凭据。
5. UAC 弹窗里点「否」→ 状态应显示「已取消」，不重试、不报错成失败。
