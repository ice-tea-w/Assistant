# 2026-10-22 同步支持多个本地文件夹（多根 + 别名）

## 一、要解决什么

用户问「为什么不能支持自定义共享文件夹，想共享哪个都可以」。

设计文档 `docs/architecture/设备同步功能-设计文档.md` 的 **FR2** 原文就是
「用户可配置**一个或多个**共享目录（含增删改）」—— 首版实现只留了一个输入框，
是没做完，不是有意收窄。

拆成三种读法问过用户，选定 **只做「能同步多个本地文件夹」**：

| 读法 | 是否做 |
|---|---|
| 多个本地文件夹一起同步 | ✅ 本次做 |
| 点按钮选文件夹（目录选择对话框） | 顺带做了（`FolderDialog`，否则加文件夹要手打路径） |
| 多个共享目录 / 多个中转站 | ❌ 不做。单中转站仍然是最简单能讲清的模型 |

## 二、设计：别名是共享目录里的命名空间

```
本地                                    共享目录（中转站）
D:\文档\  ──┬── 别名「文档」──▶   <共享>/
D:\论文\  ──┘                     ├─ 文档/  ← D:\文档 里的一切
                                  └─ 论文/  ← D:\论文 里的一切
```

- 新增 `SyncRoot { QString localPath; QString alias; }`，引擎吃 `QList<SyncRoot>`。
- 共享目录里的相对路径一律是 `<别名>/<原相对路径>`；下载落地时把别名那一段剥掉，
  写进对应的本地文件夹。
- **为什么必须有别名**：两个目录里都有 `报告.docx`，搬进同一个共享目录只会互相覆盖。
  别名就是那层命名空间。别名默认取目录名，可在界面上改。

**一个必须讲明白的约束**：两台机器要把**同一个逻辑文件夹**配上**同一个别名**，
否则各占一棵子树，永远碰不上。这不是缺陷，是这套模型的定义 ——
别名就是「这两台机器的这两个目录是同一个东西」的声明。反过来也带来一个好处：
某台机器只参与部分子目录时，其余子树它直接略过，不报错也不搬运。

## 五、只有真跑才暴露的问题

1. **清空共享目录后再也同步不了**。安全阀（对端清单为空 + 本地有基线 → `RemoteUnreachable`）
   本意是防"网盘没挂载导致把本地删光"，但共享目录被真清空时也命中，而且状态文案没说怎么办。
   改成把补救办法写进 `SyncResult::message`：删 `sync.db` 后重启。
2. **本机没参与的子目录会被记成失败**。旧逻辑对共享目录里每个文件都做判定，
   没有对应本地文件夹的下载无处落地 → 每轮 `failed++`。改成按别名先过滤，
   静默略过（引擎循环开头的那段）。
3. **同步失败原来完全不落日志**，只改界面一行状态 —— 用户回头查不出为什么没同步。
   `onSyncFinished()` 现在按成功/失败分别写 info / warn；`syncNow()` 的提前返回也写 warn。
4. **`Q_OBJECT` 头不列进 `add_executable` 就是一堆 `LNK2001/LNK2019`**
   （`ConfigManager::metaObject`、`qt_metacast`、7 个信号…）。
   项目 `CMakeLists.txt` 里原本已经写了这条注释，我还是踩了一次。
   另外 `#include "test_sync.moc"` 必须**独立一行**，被粘到 `QTEST_MAIN(...)` 后面时
   AutoMoc 报的是「contains a Q_OBJECT macro, but does not include test_sync.moc」，
   看着像 moc 没生成，其实是包含没生效。
