## 三个坑

### 1. vcpkg 下载 miniz 失败（代理/证书）

`vcpkg install miniz:x64-windows` 在 `vcpkg_from_github` 阶段失败：

```
CMake Error at scripts/cmake/vcpkg_download_distfile.cmake:136 (message):
  Download failed, halting portfile.
```

但同一台机器 `Invoke-WebRequest` 直接下 GitHub Release 是 200。vcpkg 自带的下载器受代理设置影响，
不值得为它调环境。做法是**手动把 distfile 放进 vcpkg 缓存**，让哈希校验替我们确认来源：

```powershell
$url = "https://github.com/richgel999/miniz/archive/3.1.2.tar.gz"   # 端口里的 REF
Invoke-WebRequest $url -OutFile "C:\vcpkg\downloads\richgel999-miniz-3.1.2.tar.gz"
(Get-FileHash "C:\vcpkg\downloads\richgel999-miniz-3.1.2.tar.gz" -Algorithm SHA512).Hash
# 必须等于 ports/miniz/portfile.cmake 里的 SHA512，否则 vcpkg 仍会拒绝
vcpkg install miniz:x64-windows
```

> 换机器时如果复现，先看 `C:\vcpkg\ports\miniz\vcpkg.json` 的 `version`，再按
> `richgel999-miniz-<version>.tar.gz` 命名下载。

### 2. 插件单测 25 项失败，根因不在代码

首轮 `assistant_core_tests.exe` 报 `checks: 611 failures: 25`，失败全部集中在 `PluginLoader` /
`PluginManager` 的"加载成功"类断言：

```
Cannot load library C:\vcpkg\installed\x64-windows\Qt6\qml\QtQml\qmlplugin.dll: 找不到指定的模块。
```

**不是插件代码的问题**：测试 exe 只把直接依赖的 DLL 拷到输出目录，`qmlplugin.dll` 的传递依赖
（Qt6Quick 等）没在 PATH 里，QML 引擎加载插件失败。把 vcpkg 的 `bin` 加进 PATH 后：

```powershell
$env:PATH = "C:\vcpkg\installed\x64-windows\bin;" + $env:PATH
build\plugin_tests\Release\assistant_core_tests.exe
# checks: 625  failures: 0   RESULT: PASS
```

（注意检查数从 611 涨到 625：加载失败时后续断言根本没跑到。）

### 3. TLS 后端这次反过来了

两周前 `schannel` 报 `SEC_E_NO_CREDENTIALS`、必须 `-c http.sslBackend=openssl`；这次
`openssl` 报 `unable to get local issuer certificate (20)`，而**默认的 schannel 正常**。
结论：这是机器/网络环境的状态问题，不是仓库配置问题；`git fetch` 失败时两种后端都试一遍，
不要急着改全局配置。

### 冲突怎么解的（按文件）

- **CMakeLists.txt**：两边的测试块都保留——A2–A4 的 `golden/a3/bench` 与 QTest 的 `assistant_tests` 共存。
  `a3_migrate`/`sync_unit` 的测试环境 PATH 改为 `${VCPKG_INSTALLED_DIR}/${VCPKG_TARGET_TRIPLET}/bin`，
  不再硬编码 `C:/vcpkg`（另一台机器 vcpkg 在 `D:\vcpkg`）。
- **ConfigManager.h / .cpp**：`fileIndex*` 与 `sync*` 两组配置并存。合并工具把同步默认值塞进了
  `normalizedEngine()` 的 `return` 之后、还吃掉了 `setFileIndexHardLimitEntries` 的闭合花括号，
  编译时暴露成两条 C1075/C2601 报错，手工挪回 `applyDefaults()` 与补花括号后通过。
- **MainPanel.qml**：这是唯一有设计取舍的冲突。保留插件市场的 `Loader + selectedKey` 导航
  （页面数量运行时才知道），把 qianju 的 **palette 块**（深色主题下 Quick Controls 的文字颜色）
  与「设备同步」入口并进来；`StackLayout` 那段整体丢弃。
- **main.cpp**：只冲突在 include 区，两边装配都在（`PluginManager` 在面板引擎前构造，
  `SyncBridge` 在 DB 之后、`TrayManager` 之前）。
