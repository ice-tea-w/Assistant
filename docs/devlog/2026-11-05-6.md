## 关键实现点

- **服务端线程有自己的事件循环**。`QSslSocket` 的信号要靠线程内的 `exec()` 派发；`startNetServer()` 里建 `QEventLoop` 并 `loop.exec()`，`stopNetServer()` 往该线程投一个 lambda：`server->close()` 然后 `loop.quit()`。
- **口令只以内存快照进入服务端线程**。`QSqlDatabase` 连接是主线程的，服务端线程碰不得 → `startNetServer()` 把 `devices` 全表抄进 `QHash<QString, QByteArray> m_netSecrets`（`QMutex` 保护），`SecretLookup` 只查这张表。
- **配对回调必须异步回主线程**。配对是在主线程「阻塞等 `openPairingWindow()`」期间完成的（`BlockingQueuedConnection`），如果落库再用 `BlockingQueuedConnection` 就是主线程等主线程 → 死锁。所以 `setPairSink` 里先同步写内存口令表（服务端线程内，后续认证立刻可见），再用 `Qt::QueuedConnection` 回主线程写 `devices` 表、刷新列表。
- **`syncNow()` 不再强制要求共享目录**：只判断「有同步根 &&（有共享目录 || 有配对凭据）」，共享目录为空时只挂 `NetTransport`。
- `deviceId` 懒生成（`dev-<16 位 hex>`），存 `sync.deviceId`；换主机重配对时先清空 `peerFingerprint` 再连，否则会被旧指纹挡住在握手阶段。

- 主机的本地文件夹目前**不参与**直连同步：`NetTransport` 只是把本机文件推到共享根，主机自己的根目录仍靠 `FolderTransport` 参与。对称拓扑要等 `LocalDirTransport`。

## 备用通道折叠（同日追加）

用户看到直连卡片后问「以前的共享功能还在，感觉不需要了」。判断：`ITransport` 是并列接口，共享目录那条不只是 SMB 一键共享，还同时是**投递区**（拖拽 → `_投递/` → 对端轮询领取）、**网盘路线**（真异地且双方都无公网地址时唯一形态）、**host 自己的文件夹**（`LocalDirTransport` 未做）的载体。所以不删，只降权。

- `resources/qml/SyncPage.qml` 新增 `property bool showLegacyShare: false`；连接卡片（角色单选 / 共享目录 / 检查·保存·浏览 / 一键开共享 / 一键连接 / 让对方连我 / UNC 教程）整块 `visible: syncPage.showLegacyShare`。
- 卡片上方加一行说明与按钮：`"用共享目录…" / "收起共享目录卡片"`，文字随状态切换。
- 自动展开：`Component.onCompleted` 里 `if (saved.length > 0 && !sync.peerPaired) showLegacyShare = true` —— 已配共享目录、又还没配对直连的机器不会以为入口丢了。

验证：`cmake --build ... --target Assistant` exit 0；带 Qt 插件 PATH 启动 6 秒，stderr **0 行**（QML 加载无错，之前 128 条 `Unqualified access` 属于 lint 噪声）。为看折叠效果，把自动展开条件临时改成 `if (false)` 重建截了两张图（`E:\图片\agent_截图\syncpage_direct_20261109.png` 展开态、`syncpage_collapsed_20261109.png` 收起态），随后已还原并重建。**折叠后的排版仍未经人眼确认**：本会话没有可用的视觉模型（modlens 报 `claude-cli provider failed`），OCR 对 12px 灰字几乎无效，只认出了侧栏条目。
