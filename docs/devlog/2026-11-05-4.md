# 2026-11-05（四） 公网直连 N1：设备身份 + 回环 TLS + 挑战应答认证

接 `2026-11-05-3.md`（N0 帧编解码）。N1 原本是"回环 TLS + 双向 mTLS 指纹固定"，
最后落成**单向 TLS + 应用层挑战应答**，中间换了三套密钥 API。记下来是因为三步都是被实测逼出来的，
不是设计偏好。

## 做了什么

| 文件 | 内容 |
|---|---|
| `include/core/net/Identity.h` · `src/core/net/Identity.cpp` | 自签 RSA-2048 身份：CryptoAPI 生成 → PEM 落 `identity/`，`loadOrCreateIdentity()` 幂等 |
| `include/core/net/DeviceAuth.h` · `src/core/net/DeviceAuth.cpp` | HMAC-SHA256 挑战应答（RFC 4231 向量验证） |
| `tests/test_net_identity.cpp` | 7 用例（生成 / 重载指纹不变 / PEM 文件 / 指纹格式 / 空目录拒绝） |
| `tests/test_net_auth.cpp` | 6 用例（RFC 4231 / 字段绑定 / 严格比对 / 随机数长度） |
| `tests/test_net_tls.cpp` | 4 用例（监听 / 客户端认 host 指纹 / host 拿不到客户端证书 / TLS 上跑挑战应答） |

## 关键实现点

- **证书走 CryptoAPI，不走 CNG**：`CryptGenKey(AT_SIGNATURE, 2048)` + `CertCreateSelfSignCertificate`，
  容器名随机（`AssistantSyncIdentity-<hex>`）且用完 `CRYPT_DELETEKEYSET`，不在用户 profile 留私钥。
- **私钥自己拼 PKCS#8**：CAPI 只能导 `PRIVATEKEYBLOB`（小端，含 CRT 参数），逐项反转成大端、
  转 DER INTEGER，拼 PKCS#1 九项再套 PrivateKeyInfo。`QSslKey::toPem()` 不能用 —— 它输出的是
  `BEGIN RSA PRIVATE KEY`（PKCS#1），而我们要 PKCS#8。
- **认证 = 单向 TLS + 应用层挑战应答**：`Hello{deviceId}` → `Challenge{32 字节 nonce}` →
  `Auth{HMAC-SHA256("ASYN-AUTH-V1" ‖ deviceId ‖ nonce ‖ 服务端指纹)}`。字段各带 u32 长度前缀，
  否则 `"device"+"a"` 与 `"devicea"+""` 会算出同一个值（测试里有这条）。
- **比对不提前返回**：`verifyChallengeResponse()` 定长累加异或。

## 踩坑

1. **Schannel 打 PKCS#12 只接受 RSA/DSA**。EC 私钥做完单元测试全绿，一进 TLS 握手就
   `Q_ASSERT(key.algorithm() == QSsl::Rsa || key.algorithm() == QSsl::Dsa)` —— 断在
   `qsslsocket_qt.cpp:140` 的 `_q_PKCS12_key()`。Schannel 后端把证书+私钥打包成 PFX 再
   `PFXImportCertStore`，那个打包器只认 RSA/DSA。→ 证书改 RSA-2048。
2. **CNG 的 RSA PKCS#1 签名在本机恒失败**：`BCryptSignHash` 长度查询成功、实际签名返回
   `0xC000000D`（STATUS_INVALID_PARAMETER）。PSS 能签、PKCS#1 不能，导出再导入也不能。
   → 整条生成链改走 CryptoAPI（`CertCreateSelfSignCertificate` 一次拿到证书 DER）。
3. **Schannel 不支持"可选客户端证书"**：`qtls_schannel.cpp` 的 `getContextRequirements()` 里只有
   `VerifyPeer → ISC_REQ_MUTUAL_AUTH`，注释原文 `// There doesn't seem to be a way to ask for an
   optional client cert :-(`；且没有 `ISC_REQ_USE_SUPPLIED_CREDS`，客户端塞进 `SCH_CREDENTIALS`
   的证书根本不会被用。回环实测：host 的 `peerCertificate()` 恒为 null。→ 放弃双向 mTLS，
   改应用层认证（这也是设计文档 §4.3 现在的写法）。
4. `loadOrCreateIdentity(QString())` 时 `QDir("").exists()` 为 true，会把密钥生成到进程 cwd；
   入口直接拒绝空路径。
5. PowerShell here-string 整块 `-replace` 因 CRLF 不匹配静默失败（`TLS BLOCK NOT FOUND`），
   改用 `(?s)` 正则分组替换。
