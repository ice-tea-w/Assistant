# 2026-11-12 直连页：监听地址列出全部网卡 + 网络现状实测

## 做了什么

用户问「监听地址怎么只有一个，能不能都列出来」。原来 `SyncBridge::netAddress` 只取
`localIpv4()` 返回的第一个非回环 IPv4，多网卡顺序不确定（本机优先命中 Tailscale）。

- `include/ui/SyncBridge.h`：新增 `Q_PROPERTY(QVariantList netAddresses)`、getter、私有
  `QVariantList addressCandidates(quint16 port) const`、成员 `m_netAddresses`。
- `src/ui/SyncBridge.cpp`：`addressCandidates()` 遍历 `QNetworkInterface::allInterfaces()`，
  跳过 down/loopback、跳过非 IPv4 与 link-local，按地址去重，每项 `{name, address}`
  （`address` 已带 `:<端口>`）；`startNetServer()` 的 listen 成功回调里填充它，
  线程 `finished` 里与 `m_netAddress` 一起清空。
- `resources/qml/SyncPage.qml`：原来「本机地址 + 复制」单行换成 `Repeater` 列表，
  每行 `网卡名 / IP:端口 / 复制`；未监听时仍显示一行提示。
- 保留 `netAddress`（首选地址）给状态行「正在监听 %1 · 本机指纹 %2」用。

## 顺带测到的两件事（影响真机走查）

1. **WLAN 没有 IPv6**：`IPv4Connectivity = Internet` 但 `IPv6Connectivity = NoTraffic`、
   无 `::/0` 默认路由、`Test-NetConnection 2400:3200::1:443` = False，地址只有 `fe80::`。
   → 该 SSID 只跑 IPv4，公网 IPv6 直连这条路在当前网络不成立（不是没认证，IPv4 已通外网）。
2. **没有 45871 的入站防火墙规则**，且 `i-HDU 2` 的 NetworkCategory 是 `Public`。
   → 当主机前必须放行，否则外部连接一律被拦：
   `New-NetFirewallRule -DisplayName "Assistant 直连 45871" -Direction Inbound -Protocol TCP -LocalPort 45871 -Action Allow -Profile Private,Public`

## 仍未验证

两台真机从没跑过，全部链路验证仍是同进程回环（`net_engine` 用例）。
## 同日追加：一键放行防火墙 + 自检 + 虚拟网卡标注

  监听 / 地址 / 防火墙 / IPv6 / 配对。IPv6 判定抽成 `isUsableGlobalIpv6()`，

- `addressCandidates()` 每项加 `kind`（有线/无线/虚拟/其它，来自 `QNetworkInterface::type()`）

## 单文件直发与待发队列（同日追加）

起因：用户要「发一个文件给队友」，而现在的同步是**整目录对应**（别名 + 三方基线），
旧投递区又绑在共享目录上、已随直连升主路径一起隐藏。所以补一条「投递」路径。

### 做了什么

| 层 | 改动 | 提交 |
|---|---|---|
| 数据库 | `sync.db` 加 `outbox` 表 + `idx_outbox_rel` 唯一索引；`enqueueOutbox` / `dueOutbox` / `outboxItems` / `markOutboxSent` / `markOutboxFailed` / `removeOutbox` / `outboxCount` | `d91fd86` |
| 引擎 | `Sync::isReservedDeliveryPath()`（任意段等于 `_inbox` / `_投递` 即保留）；`scanLocal()` 与决策循环都跳过 | `c888785` |
| 服务端 | `splitRel()` 首段 `_inbox` → 映射到**第一个根**，不要求别名；`collectFiles()` 对投递箱不下发别名前缀 | `9004146` |
| 桥 | `queueSend` / `sendQueuedNow` / `removeQueuedItem` / `fetchIncoming` / `refreshOutbox` + `outboxCount` / `outboxList` | 本次 |
| QML | 「发送文件」卡从隐藏改常显：选择文件 / 立即发送 / 收取投递 / 收件箱 + 队列列表 | 本次 |

### 关键实现点

- **投递路径**：`_inbox/<设备名>-<deviceId 前 8 位>/<yyyyMMdd-HHmmss>_<原名>`。
  加 deviceId 前缀是因为两台设备可能叫同一个名字，只用设备名会串进同一个目录。
- **为什么引擎必须跳过**：投递箱在服务端第一个根里，`collectFiles()` 会把它当普通文件列出来；
  不跳过的话对端会下载它、下一轮又当成本地新增推回去，两台机器互相搬。
- **为什么服务端要特例**：多根模式下 relPath 必须带别名（`share/a.txt`），投递没有别名概念，
  不加首段特例则 `_inbox/...` 永远 `BAD_PATH`。
- **线程分工**：`QSqlDatabase` 只归主线程。工作线程只做网络（`push` / `listRemote` / `fetch`），
  结果经 `QueuedConnection` 回主线程落库；`peerForDelivery()` 在主线程取配置再按值捕进线程。
- **失败退避**：`nextAttemptAt = now + min(60 × (attempts+1), 600)` 秒。定时同步 tick 与
  `pollInbox()` 都会顺手补发，队友一上线就自动送达，不需要用户手动点。
- **领取**：筛 `_inbox/` 前缀 → `fetch` 到临时文件 → `placeIncoming()` 落收件箱（重名自动加序号）
  → `markReceived` 记一笔 → `removeRemote`（服务端扔进自己的 `.sync/trash`，不是真删）。

### 与计划的偏差

- 计划里的 `flushOutbox()` / `removeOutboxItem()` 落地叫 `sendQueuedNow()` / `removeQueuedItem()`，
  与既有 `syncNow()` / `sendFiles()` 的命名风格一致。
- 计划里「未配对时只提示、不入队」改成**照样入队**：卡上写「文件先存在队列里，配对后自动发出去」，
  比让用户配对完重选一遍顺手。代价是队列里可能长期躺着发不出去的条目（列表可见、可移除）。

## 收件箱可以自己选了（同日追加）

用户问「为什么不能自己选择收件箱」。查下来不是没有能力：`SyncBridge::inboxPath()`
早就优先用配置里的 `sync.inboxDir`，空则落 `文档/Assistant 收件箱`。
缺的是入口 —— `SyncBridge` 没把 `setSyncInboxDir` 包成 `Q_INVOKABLE`，
QML 那行只读路径又跟着隐藏的旧卡片一起看不见了。

- `include/ui/SyncBridge.h`：`Q_INVOKABLE void setInboxDir(const QString &)`、`resetInboxDir()`
- `src/ui/SyncBridge.cpp`：`setInboxDir` 先 `QDir().mkpath()`，建不出来只报错不改配置；
  成功后写 `m_config->setSyncInboxDir()` + `emit inboxDirChanged()`；`resetInboxDir()` 写空串回落默认
- `init()`：自定义目录若不存在且建不出来 → **回落默认并 warn**（换机器 / 换用户目录会失效）
- `resources/qml/SyncPage.qml`：「发送文件」卡加「收件箱 <路径> [更换…][默认]」一行 +
  `FolderDialog{ id: inboxDialog }`

验证：`build` exit 0、`ctest` 14/14、`assistant_tests` 64 passed、stderr 0 行；
截图 `E:\图片\agent_截图\inbox_row.png`，默认路径显示为本机 `C:/Users/idea/OneDrive/文档/Assistant 收件箱`
（`QStandardPaths` 认 OneDrive 重定向后的文档目录）。

**已知取舍**：换目录只影响之后领到的投递，旧收件箱里的文件不会迁移。
