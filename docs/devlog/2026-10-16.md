# 2026-10-16 v0.4.0 Phase A / A2 结构与并发

按 `docs/architecture/v0.4-实施清单.md` §A2 落地「门面 + COW 快照 + 后台扫描」。
目标写的是**查询能力与旧版等价（不追求变快）**，所以这一版的重点是**结构**和
**一条随时能退回去的路**，不是性能。

三条验收全过（均为实测，含真机 + 合成 20 万条两轮 golden 对比），并且顺手量出了
A4 baseline 最需要的那个数字。

## 一、A2 做了什么

| 新增 | 内容 |
|---|---|
| `include/core/FileSnapshot.h` | **不可变只读快照** + 内嵌 `Builder`（写入端）。只读接口只有 `size / nameAt / lowerAt / pathAt / sizeAt / mtimeAt`；v1 物理表示 = `std::vector<FileEntry>`（3 个 QString + 2 个标量），**藏在接口之后** |
| `include/core/SnapshotManager.h` / `src/core/SnapshotManager.cpp` | **COW 发布**：`current()` 取一份 `shared_ptr` 即用（读侧整轮查询无锁）、`publish()` 一次性替换；原语 `std::atomic<std::shared_ptr<const T>>` |
| `include/core/FileIndex.h` / `src/core/FileIndex.cpp` | **门面**（薄）：`startAsync / refresh / query / stats` + 两个注入点（`setSnapshot` / `setEntryLimit`）；后台扫描 = 进程内 `ScanWorker`（QThread） |

| 改造 | 内容 |
|---|---|
| `src/main.cpp` | `FileSearcher::buildIndex()` → `fileIndex.startAsync()`（仍在 `engine.load()` 之前，但**不再阻塞**）；`fileIndex.engine` 决定走哪条路 |
| `include/ui/AppBridge.h` / `src/ui/AppBridge.cpp` | `setFileIndex()`；`search()` 经 `FileIndex::query()` 取文件结果；索引就绪 → 重跑上次查询（没敲过字就刷新默认状态） |
| `include/core/ConfigManager.h` / `src/core/ConfigManager.cpp` | `fileIndex.engine = "legacy" \| "v2"`（非法值收敛为 legacy），**默认已切 `v2`** |

一处**顺手修掉的真 bug**：索引就绪时如果用户一个字都没敲过，状态栏会一直停在
「正在建立索引…」。现在 `indexReady` 在没有 `m_lastQuery` 时改调 `activate()`。

## 二、先决验证：MSVC 支不支持 `std::atomic<std::shared_ptr<const T>>`

计划里特意标了「10 分钟，别跳过」。写了 3 行 snippet 用本机工具链编译 + 运行：

```
value=42 refs=4
```

**支持**，所以不启用 `std::shared_mutex` 降级方案（`SnapshotManager.h` 里已写明依据）。
探针留在 `_probe/atomic_probe.cpp`。

## 三、验收（三条全过）

### ① 冷启动窗口立即可见

launcher 窗口默认是隐藏的（托盘应用），没有东西可点，所以用探针
`PostMessage(WM_HOTKEY, id=1000)` —— 这就是 `RegisterHotKey` 生效后系统做的事，
整条链（`nativeEventFilter` → `HotkeyManager::hotkeyPressed` → `AppBridge::toggleWindow`
→ QML `onVisibleChanged` → `AppBridge::activate`）都是真的。

```
03:42:52.121 FileIndex: engine = v2
03:42:53.312 UI loaded — fileIndex v2 ready=false scanning=true entries=0   ← 窗口已起来，索引还在扫
03:42:53.324 HotkeyManager: registered Alt+Space (id: 1000)                 ← 热键已可用
03:42:53.664 AppBridge::status '正在建立索引…'                               ← 状态栏（真实消息链触发）
03:42:54.670 FileIndex: pruned 665 excluded dir(s) (node_modules etc.)
03:42:54.671 FileIndex: published snapshot #1 — 31810 files in 2546 ms
```

同一次改动下的 legacy 对照：

```
03:43:17.499 FileSearcher: index capped at 20000 files
03:43:17.499 FileSearcher: indexed 20000 files in 956 ms      ← 索引同步建完
03:43:18.195 UI loaded — fileIndex legacy (20000 files indexed synchronously)
```

顺序反过来就是全部意义：**v2 是"先能用、后校正"，legacy 是"建完索引才起来"。**

### ② `engine=legacy` 与 A1 完全一致

legacy 分支**一行未改**，日志逐条对齐（`pruned 164 excluded dir(s)`、
`index capped at 20000 files`、`indexed 20000 files in 956 ms`）。

### ③ golden 对比逐条一致（`assistant_golden`，132 项检查 0 失败）

`tests/golden_file_index.cpp` 分两段：

- **合成语料 20 万条**（`--n=200000`）：快照直接注入（不碰磁盘），与"旧 `search()` 算法"
  的参考实现在**同一候选集**上比 —— 结果集（条数 / 顺序 / 名字 / 分数 / id / path）
  27 遍全表比对全部逐条相同；空查询、空白查询、`limit = 0/1/5/1000` 边界同样一致。
- **真机数据**（`--real`）：把 v2 上限压到 20000 与旧引擎同候选集，**100 条真实查询**
  （每条文件的完整名 + 前半截，即精确命中与前缀命中两档）逐条相同。
  这同时证明了 **A2 的遍历与 A1 的遍历收敛到同一集合**。

> 为什么必须"同一候选集"：v2 刻意**不再套 2 万条任意截断**（P0-3），
> 真机上两者的候选集本来就不同 —— 那是设计意图，不是回归。

## 四、量出来的数字（A4 的 baseline 要用）

| 项 | 实测 | 说明 |
|---|---|---|
| **单遍全表扫描，真机 31810 条** | **326 ms** | 走 v2 路径。**这就是每次按键的当前代价** |
| 单遍全表扫描，合成 20 万条 | **13154 ms** | 语料更长、命中更多（含排序） |
| 全量扫描 31810 条 | 1736 ms（后台） | legacy 扫 20000 条 976 ms；v2 每文件慢约 12% |
| 索引规模 | **31810 vs 20000** | v2 不截断 —— **P0-3 在 v2 路径上已经修掉** |

**最重要的一条**：架构文档里写的"现状 2 万条的 5–15 ms"（当时标注"未实测"）
**低了 20 倍以上**。当前 `FuzzyMatcher::score()` 每次调用要 `toLower` 两次
（query 一次、text 一次）+ 词边界分支里 `t.mid(i)` 的子串分配 —— 2 万条一遍就是 333 ms。
A4 的「tier 判定 + 子序列 DP + top-K 堆」不是锦上添花，是这个数量级的差距。

顺带：**31810 条的 326 ms 与 20000 条的 333 ms 几乎一样**，所以没有理由为了速度
把 11810 个文件挡在索引外面 —— 默认 engine 因此切到 `v2`。

## 五、踩坑 / 环境（本次新踩的）

1. **受限沙箱下只有"工作区根目录"可写。** 起因是会话开始时沙箱为自己的写授权
   (`grantWrite(E:\Assistant)`) 失败：根目录缺 `WRITE_OWNER`。补上之后根目录可写了，
   但 `docs/`、`src/`、`build/`、`.git/` 依然被拒 —— 而它们的 DACL 明明写着
   `Authenticated Users: Modify`。**DACL 给了写权限却写不进，就只剩强制完整性标签能解释**：
   沙箱进程是 Low 完整性，只有根目录被打上了 Low 标签（子目录没有，按 Windows 默认视为
   Medium），于是"向上写"被拒。这不是权限问题，改权限没用；DSH 自带的文件工具不受影响。
2. **验收工具必须先能区分"慢"和"挂"。** 第一版 golden 跑 75 遍全表扫描 × 20 万条，
   14 分钟没有任何输出（stdout 重定向后是全缓冲）—— 我误判成挂死并杀掉了它。
   真相是它只是在慢（一遍 13 秒）。教训：**长时间跑的验收工具要有进度输出**，
   并且**别在验收跑的同时编译**（会污染正在记录的时间数字）。
3. **PowerShell 执行策略会挡住 `.ps1` 探针**：`& script.ps1` 报「未进行数字签名」。
   用 `powershell -NoProfile -ExecutionPolicy Bypass -File script.ps1`。
4. **读日志要 `Get-Content -Encoding UTF8`**。文件里的中文/破折号本身是对的，
   按 ANSI 读会显示成 `鈥?`，看起来像编码 bug，其实只是读取端。
5. **强杀丢 debug 日志**（A1 已记过）：这次没踩到 —— debug 行后面还跟着 info 行，
   `flush_on(info)` 把它们一起刷进文件了。但还是别指望它。
6. **`_probe/` 是本地探针目录**（A1 的做法，已 gitignore）：探针脚本、编译 snippet 都放这儿。
