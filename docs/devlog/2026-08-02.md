## Step 4 — AppBridge（QML ↔ C++ 通信桥梁）

### 新增文件

| 文件 | 职责 |
|------|------|
| `include/ui/AppBridge.h` | 统一后端 QObject：属性、Q_INVOKABLE 方法、信号 |
| `src/ui/AppBridge.cpp` | 搜索过滤匹配、命令分发（calc/notepad/explorer/cmd/settings/google/screenshot/lock/recycle/m sinfo）|

### 架构：C++ 与 QML 的双向通道

| 方向 | 机制 | 用途 |
|------|------|------|
| QML → C++ | `Q_INVOKABLE` | `search(text)` `executeCommand(idx)` `hideWindow()` `toggleWindow()` |
| C++ → QML | `Q_PROPERTY` + NOTIFY | `searchResults` → ListView, `statusText` → 状态栏, `visible` → 窗口显隐 |
| C++ → QML | Connections{} | `onVisibleChanged()` → 居中聚焦, `onCommandExecuted()` → 自动隐藏 |
| QML → C++ | 属性绑定 | `visible: backend.visible` 使窗口显隐由 C++ 属性单向驱动 |

### 通信流程示例

```
用户输入 "calc"
  → QML: onTextChanged → backend.search("calc")
    → C++: AppBridge::search() → emit searchResultsChanged()
      → QML: ListView.model 自动刷新，显示 "Open Calculator"

用户按 Enter
  → QML: Keys.onReturnPressed → backend.executeCommand(0)
    → C++: AppBridge::executeCommand() → QProcess::startDetached("calc.exe")
    → C++: emit commandExecuted("Open Calculator")
      → QML: Connections.onCommandExecuted → backend.hideWindow()
        → C++: AppBridge::setVisible(false)
          → QML: visible 属性绑定更新 → 窗口隐藏
```

### main.cpp 重构

移除直接 `QWindow*` 操作和 `SearchEngine`，统一通过 `AppBridge` 通信：

```cpp
// 旧：直接操作窗口指针
horror: window->setVisible(true);
horror: window->setPosition(x, y);

// 新：通过 bridge
backend.toggleWindow();        // 切换显隐
backend.visible → QML 绑定    // 状态同步
```

```json

    "hotkey": { "modifiers": "Alt", "key": "Space" },
    "theme": "dark",

```

### QML 主题绑定

```qml
readonly property bool isDark: config.theme === "dark"
```

## 窗口拖动实现

双层 `MouseArea` 叠放：底层捕获拖动，上层控件优先消费点击。

```
Rectangle (外层)
├── MouseArea          ← ① 全窗口拖动（空白区域）
├── ColumnLayout       ← ② 控件层（优先消费点击）
│   ├── searchBar
│   │   ├── MouseArea  ← ③ 搜索栏拖动（图标/边距）
│   │   └── RowLayout  ← ④ TextInput（优先输入）
│   ├── ListView
│   └── StatusBar
```

## 踩坑记录

### 1. CMake GLOB_RECURSE 不自动发现新文件

**现象：** 新增 `AppBridge.cpp` 后编译报 `LNK2019`，链接不到符号。

**根因：** `file(GLOB_RECURSE SOURCES src/*.cpp)` 在 configure 时求值，新增文件不会触发 CMake 重新扫描。需要手动 `cmake -B build ...` 重新 configure。

**修复：** 每次添加/删除源文件后，重新执行 `cmake -B build -S . ...` 或在 CMakeLists.txt 中添加 `CMAKE_CONFIGURE_DEPENDS`。

### 2. MOC 不生成 AppBridge 的元对象代码

**现象：** 重配置后 `AppBridge.obj` 存在但没有 `moc_AppBridge.cpp`，`staticMetaObject` 等符号未定义。

**根因：** `CMakeCache.txt` 中的旧 AUTOMOC 状态未清除，增量 configure 没有触发重新扫描。

**修复：** 删除 `build/CMakeCache.txt` 和 `build/CMakeFiles` 后完整重配置 → 编译成功。

### 3. nlohmann_json 单头文件与 CMake 包路径

**vcpkg 安装后：**
- include 路径：`C:/vcpkg/installed/x64-windows/include/nlohmann/json.hpp`
- Config 文件：`C:/vcpkg/installed/x64-windows/share/nlohmann_json/nlohmann_jsonConfig.cmake`
- Target 名：`nlohmann_json::nlohmann_json`（下划线，非连字符）

### 4. ConfigManager 使用 nlohmann/json 而非 Qt JSON

Qt 自带的 `QJsonDocument` / `QJsonObject` 也可以读写 JSON，但项目 GUIDE.md 中技术选型明确选用 nlohmann/json。两者互不冲突，共用 `QFile` 做 I/O。
