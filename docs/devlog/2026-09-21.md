## 三、顺带修掉的两个真问题

1. **`Style.qml` 属性命名踩 QML 的坑（本次自造，冒烟才发现）**
   `readonly property color onAccentColor` → QML 把 `on` + 大写开头的标识符当**信号处理器**解析，
   直接报 `Cannot assign a value to a signal (expecting a script to be run)`；
   连带 `MainWindow.qml` 报 `Type Style unavailable` → `rootObjects().isEmpty()` → 程序 `return -1` 秒退。
   改名 `accentTextColor` 后恢复。**教训：QML 里属性名不要以 `on` 开头。**

2. **4 个数据库析构顺序错误（既有问题）**
   `~*Database()` 先 `removeDatabase(name)` 之后才销毁 `QSqlDatabase`，Qt 报
   `connection 'history'/'todo'/'notes'/'clipboard' is still in use`，且连接实际没被清理。
   改为**先 delete `m_db` 再 removeDatabase**。这条警告违反本项目"stderr 为空"的冒烟标准，所以顺手修。

## 五、环境/踩坑（重要，下次直接用）

1. **编译与运行都需要 `danger-full-access`**：
   - 编译：`workspace-write` 下 CMake/AUTOMOC 派生 `moc.exe` 子进程被拒（`libuv process spawn failed: operation not permitted`）。
   - **运行**：应用必须写 `%LOCALAPPDATA%/AssistantTeam/Assistant/`（日志/配置/4 个 DB），受限模式下写入被拒 →
     `Logger::init` 失败退回 console-only，**日志文件不落盘**（本次一开始被这个骗过一次）。
2. **重定向 stdio 时不要用 stdout 判断启动是否成功**：spdlog 的 console sink 在重定向后是全缓冲的，
   进程被强杀会丢掉未 flush 的输出。**看 `%LOCALAPPDATA%\...\logs\assistant.log` 才可靠**。
3. `$p.HasExited` 判断进程存活前先 `$p.Refresh()`。
