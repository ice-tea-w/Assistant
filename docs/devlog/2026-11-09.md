# 2026-11-09 直连升为主路径（方案 A：多根直连 + 前端以直连为主）

## 起因

用户定调：「现在直连是主设计，你应该根据直连来做前端页面，而且以前的文件共享根本不能用，还有必要留着吗」。

事实核对后同意这个判断：共享目录那条路依赖 SMB/UNC，用户的实际网络是校园网 `10.252.x`，
跨网段被隔离，连「同局域网」都不成立；此前只在 `\\localhost` 上验证过。它同时是三条东西的载体
（SMB 一键共享 / 网盘路线 / 投递区），所以分三阶段退场：

- **A（本次）**：多根直连 + 前端以直连为主，旧通道代码不再接线
- **B**：直连版投递区（`_delivery/<recipient>/` + outbox）、单文件直发
- **C**：删 `FolderTransport` / `DeliveryNaming` / SMB 命令与用例，旧设计文档标废弃

## 关键实现点

- **relPath 规则**：多根时 `relPath = <别名>/<相对路径>`，单根且无别名时就是相对路径本身。
  `splitRel()` 取第一段当别名做大小写不敏感匹配；匹配不到回 `BAD_PATH`，不用「猜」。
- **别名兜底**：`startNetServer()` 里别名为空时取文件夹名，避免用户不填别名就整棵树都进不去。
- **多根校验**：每个 `localPath` 必须存在；别名去重（`toCaseFolded`）；多根时不允许首根别名为空
  （否则它和别人的子树撞在一起）。
- **`refreshChannel()` 不再 probe 共享目录**：否则界面上永远显示「通道：共享目录」，
  和 `syncNow()` 实际挂的通道矛盾。
- **服务端线程仍然只碰内存**：口令快照 `m_netSecrets`（`QMutex`）、配对回调用 `QueuedConnection`
  回主线程写库——线程规则的坑上次已经踩过，这次没再改。

## 踩坑

- **PowerShell `Set-Content -Encoding utf8` 会写 BOM**：改 `MainPanel.qml` 一行后发现整个文件头多了 `\ufeff`，
  `git diff` 显示第一行被改。临时改文件走 `git checkout` 复原；需要改 QML 时用 edit 工具，别用 `Set-Content`。
- **CRLF 让正则失配**：Python 脚本读文件时 `split("\n")` 会在每行尾留 `\r`，
  `^\s*RowLayout\s*\{\s*$` 永远不匹配，报 `AssertionError: toggle row not found`。
  改成「匹配用去尾的行、写回保留原行」才成功。
- **插入型 edit 的锚点必须原样重写**：上次插函数时把 `handleList` 的签名行吞掉，这次删卡片改用脚本整体删，
  避免大段 old_string。
