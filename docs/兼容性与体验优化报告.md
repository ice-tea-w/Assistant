# 兼容性与体验优化报告（v0.5.0）

> 目标：让模块在**换机、弱网云盘、大文件、异常错误**这四类真实场景里"不折腾用户"。
> 本次不动密码学核心，只改文件路径映射、进度反馈、错误文案和云盘兼容——属于"低风险高感知"的一轮优化。
> 范围：`backup.py`、`scan.py`、`fsutil.py`、`errors.py`、`cli.py`、`service.py`、`tests/test_extras.py`。

## 1. 优化清单

| # | 问题（用户视角） | 优化 | 落点 |
| --- | --- | --- | --- |
| 1 | 换机器后备份能恢复，但**原路径不存在**（`C:\Users\alice\...` → 新机是 `D:\data`），一恢复就报"路径不存在" | `restore --dest-root` + `--strip-prefix`：把旧绝对路径映射到新根目录 | `backup.restore` / CLI / RPC |

| 4 | 扫描整个 OneDrive 目录会**触发几十 GB 下载**（云盘"仅在线"文件一读就拉取） | 识别云盘占位文件，默认跳过正文（仍按文件名提示），`--include-cloud` 显式读取 | `fsutil.is_cloud_placeholder`、`scan` |

## 2. 跨机/异地还原（`--dest-root` / `--strip-prefix`）

**语义**：

- `--dest-root DIR`：把"原机器上的绝对路径"去掉**盘符/UNC 前缀**后，挂到 `DIR` 下：
  `C:\Users\alice\docs\a.txt` → `<DIR>\Users\alice\docs\a.txt`；
- 配合 `--strip-prefix OLD`：先裁掉旧机器上的前缀再映射：
  `--strip-prefix C:\Users\alice` → `<DIR>\docs\a.txt`；
- `--dest-root` 与 `--dest` 互斥（一个目录、一个精确文件，避免歧义）；
- 目录不存在会自动创建（沿用解密时的原子写 + 父目录创建逻辑）。

**使用示例**（换机 / U 盘异地恢复）：

```bash
# 旧机器：把整个备份库拷到 U 盘（内容寻址 + 加密，可直接拷）
# 新机器：导入备份库后，把旧路径映射到新位置
python -m file_guard backup restore "C:\Users\alice\docs\a.txt" ^
    --dest-root "D:\restore" --strip-prefix "C:\Users\alice"
# → 恢复成 D:\restore\docs\a.txt
```

HTTP 服务参数：`{"method":"restore","params":{"path":"...","dest_root":"D:\\restore","strip_prefix":"C:\\Users\\alice"}}`。

**小提醒**：备份索引里存的是"原绝对路径"；跨机时用 `--dest-root` 即可，不需要改索引。

## 3. 进度反馈（不再"没反应"）

- `backup.backup_file(path, progress=...)` / `backup_paths(..., progress=...)` 透传到 `crypto.encrypt_file`；
- CLI 在交互终端显示一行式百分比（`加密 a.bin  42%`），完成/失败后擦除，不污染 `--json` 输出；
- 非 tty（重定向、CI、服务调用）自动关闭，不会多出任何字符；
- 目前覆盖：`encrypt` / `decrypt` / `backup add`；扫描原有进度保留。

## 4. 友好错误提示

新增 `errors.describe_os_error(OSError)`，CLI 与本地服务共用：

| WinError | 提示 |
| --- | --- |
| 5 | 拒绝访问：文件可能被系统保护、目录只读，或需要更高权限 |
| 32 / 33 | 文件正被其他程序占用/锁定：请关闭占用它的程序后重试 |
| 112 | 磁盘空间不足 |
| 206 | 路径过长：请缩短路径，或启用 Windows「长路径支持」 |
| 123 | 文件名或路径包含非法字符 |
| 19 | 磁盘写保护 |
| 3 | 路径不存在 |

非 Windows 语义（`PermissionError` / `FileNotFoundError` / `TimeoutError`）同样给出中文提示。HTTP 侧对 `OSError` 单独返回 409 + 友好文案，主程序可以直接展示。

## 5. 云盘占位文件兼容（OneDrive/SharePoint）

| 场景 | 改前 | 改后 |
| --- | --- | --- |
| 扫描含"仅在线"文件的目录 | 读取每个文件 → 触发云端下载，慢且耗流量 | 识别占位属性（`FILE_ATTRIBUTE_OFFLINE` / `RECALL_ON_DATA_ACCESS`），**跳过正文**，note 标注"云盘占位文件（内容未下载）"，仍按文件名做风险提示 |
| 确实要读 | 无开关 | `--include-cloud`（CLI）/ `include_cloud: true`（RPC） |
| 云盘"打开即召回"的小文件 | — | 属性 `RECALL_ON_OPEN` 不跳过，正常读取 |

说明：`is_reparse_point` 仍然不把 OneDrive 占位当"越界链接"处理（它在授权目录内），两个判断互不干扰。

## 7. 兼容性说明

- 旧备份库、旧审计日志、旧配置**无需迁移**（本次只加可选参数与返回值，不改格式）；
- `restore` 新增参数均为可选，默认行为与 v0.4.0 一致（除冲突保护——那是上一版引入的默认收紧）；
- 进度输出只在交互终端出现，脚本/JSON 调用方无感知；
- 云盘跳过只影响"正文检测"，文件名规则、风险分级、报告结构都不变。

## 8. 残余风险与后续

| 项目 | 说明 |
| --- | --- |
| Windows 长路径（>260 字符） | 尚未启用 `\\?\` 长路径前缀；目前给出明确错误提示，建议开启系统长路径支持，或后续在 `crypto`/`backup` 的文件打开处统一加扩展前缀 |
| 云盘检测依赖文件属性 | 仅 Windows 生效；非 Windows 平台 `is_cloud_placeholder` 恒为 `False` |
| 进度粒度 | 按分块（1 MiB）刷新，超大单文件也足够；如需 ETA 可后续加时间窗估算 |
| 跨机还原的权限 | 映射后的目标目录需要当前用户有写权限；ACL 过严时仍会被系统拒绝（会显示友好提示） |
