# file_guard 安全评审与加固报告

> 评审对象：`file_guard/`（桌面助手「文件安全模块」参考实现，v0.2.0）
> 评审方式：逐文件人工代码审计 + 针对每条疑点写可复现用例验证 + 修复后回归
> 评审范围：`crypto.py` / `audit.py` / `backup.py` / `scan.py` / `watch.py` /
> `service.py` / `cli.py` / `config.py` / `integrity.py` / `errors.py`
> 结果：**发现 20 项可复现问题（4 项严重 / 8 项中等 / 8 项低危健壮性），已全部修复；
> 新增 33 条回归用例，全量 115 个测试通过（1 条因当前账户无法创建符号链接而跳过）。**

---

## 1. 结论摘要

这个模块的密码学**主体设计是对的**：分块 AEAD、每块 AAD 绑定头/块号/末块标记、
PBKDF2 随机盐、原子替换、HMAC 哈希链这些关键点都做对了。问题集中在三类：

1. **"看起来做了、实际没生效"**：备份里"源文件被改"的校验读了一个永远不存在的字段；
   日志 meta 号称防篡改但根本没签名；`os.walk(followlinks=False)` 挡不住 Windows 目录联结。
2. **边界处的信任假设**：扫描/监听/备份枚举路径时没有真正守住"只碰授权目录"；
   本地服务对 Host/Origin/token 文件权限没有做纵深防御；备份索引里的路径被无条件信任。
3. **密码学细节**：审计日志的 nonce 由"固定前缀 + 自增序号"拼成，日志被回滚后继续写会
   复用 nonce —— 在 AES-GCM 下这同时泄露明文异或值和认证密钥（可伪造审计记录）。

修复遵循一个原则：**不改对外接口语义，能兼容旧数据的一律兼容**（旧审计日志可读、
旧备份对象可恢复），并给每一条修复配可复现的回归测试（`tests/test_security.py`）。

## 2. 问题清单（按严重度）

### 2.1 严重

| # | 位置 | 问题 | 影响 | 修复 |
| --- | --- | --- | --- | --- |
| S1 | `audit.py` 全类 | 日志 nonce = `固定前缀 ‖ seq`。攻击者把日志回滚/删除后程序继续追加（或把旧 `meta.json` 覆盖回来）时，同一密钥 + 同一 nonce 会加密不同明文 | AES-GCM nonce 复用：泄露明文异或值，并可恢复 GHASH 认证密钥进而**伪造任意审计记录**，审计"防篡改"承诺失效 | 记录格式升级 v2：**每条记录独立 12 字节随机 nonce**，nonce 同时进 AAD 与哈希链；旧 v1 记录保持可读，新写入一律 v2。用例 `test_each_record_uses_fresh_random_nonce`、`test_legacy_v1_log_still_readable_and_appends_v2` |
| S2 | `scan.py::collect`、`watch.py::_iter_files`、`backup.py::backup_paths`、`crypto.py::iter_files` | 用 `os.walk(followlinks=False)` 以为能挡住链接；但 Windows **目录联结（junction）** 不是符号链接，`is_symlink()==False`，会被正常遍历 | 在授权目录里放一个联结即可让扫描/监听/备份跑到 `C:\Users` 等未授权位置 —— 直接违反"只扫用户指定目录"的隐私红线 | 新增 `fsutil.is_reparse_point()`（`lstat` + `islink` + `os.path.isjunction`），四条枚举路径统一跳过链接类入口；显式把链接当根传入仍视为用户授权。用例 `test_directory_junction_is_not_traversed`（实测能创建联结并证明旧逻辑会越界） |
| S3 | `scan.py::_read_office_text` | 先 `zf.read(name)` **完整解压**再判断 `len(raw) > 4MB` | 一个 10KB 的 docx（高压缩比 XML）即可让进程吃掉数 GB 内存，扫描/服务进程被拖死 | 先看 `getinfo().file_size` 再决定读，读取用 `ZipExtFile.read(上限+1)` 兜底（声明大小可造假），并限制单文件累计解压量 8MB。用例 `test_office_zip_bomb_is_skipped`（6MB 膨胀 XML 被安全跳过） |
| S4 | `audit.py::append` | 追加前不验证密码。用错误密码（或错误密钥文件）追加会写出一条**永远解不开**的记录，随后 `log verify` 全部报错；且旧实现会继续在损坏链上写 | 审计日志被"合法操作"写坏即等于审计失效；也是 S1 的攻击前置条件之一 | 追加前先解密最后一条记录校验密码；meta 签名不匹配也拒绝。错误密码现在得到明确报错且日志字节不变。用例 `test_wrong_password_cannot_corrupt_log` |

### 2.2 中等

| # | 位置 | 问题 | 影响 | 修复 |
| --- | --- | --- | --- | --- |
| M1 | `backup.py::backup_file` | 传 `hash_plaintext=False` 却检查 `result["sha256"]`，该字段恒为 `None` → "备份过程中源文件被修改"的完整性检查是**死代码** | 并发修改时会把"内容与索引哈希不符"的坏对象写进备份库，直到恢复时才发现 | 传 `hash_plaintext=True` 并比对；不一致时删除刚写的对象再抛 `IntegrityError`。用例 `test_backup_detects_source_change_via_plaintext_hash` |
| M2 | `backup.py::backup_file` | 版本号取 `len(versions)+1`；保留策略（`keep_versions`）清掉旧版本后长度变小 → **版本号被重复使用** | 同一路径出现两个 `version=2`，`restore --version 2` 语义不确定，purge 可能删错版本 | 改为 `max(现有版本)+1`。用例 `test_version_number_not_reused_after_purge` |
| M3 | `backup.py::object_path` | 备份对象文件名 = `SHA-256(明文)` | 泄露"这份内容是否在备份库里"；低熵文件（密码本、短配置）可被离线暴力确认；可定向删除某个文件的对象 | 改成**密钥化哈希** `HMAC(子密钥, SHA-256(明文))`，去重能力不变但不知道密码算不出对象名；旧对象名仍按索引记录的名字读取，恢复不受影响。用例 `test_object_name_does_not_leak_plaintext_hash` |
| M4 | `backup.py::restore/verify` | 索引里的 `object` 字段直接拼进路径使用，不校验 | 备份目录被拷贝/伪造（例如别人给的"备份包"）时，`object: "../../x.fgc"` 可让恢复逻辑读写 `objects/` 之外的位置 | 强制 `^[0-9a-f]{2}/[0-9a-f]{64}\.fgc$` 且 `resolve()` 后必须仍在 `objects/` 内；原始路径必须是绝对路径。用例 `test_malicious_index_cannot_escape_objects_dir` |
| M5 | `audit.py` meta/锁 | `meta.json` 无签名，且首次创建没有原子保护 | 改 `nonce_prefix`/`salt` 可造成不可解密（DoS），也是 S1 的放大器；两个进程首次同时使用会各写一份盐，日志随机不可读 | meta 增加 HMAC 签名（密码派生，密钥化）与 `next_seq` 高水位；创建用 `O_EXCL`、更新用 tmp+replace 原子写；高水位与日志不一致即报"被回滚/截断"。用例 `test_meta_tamper_is_detected`、`test_rollback_is_detected_on_append_and_verify` |
| M6 | `service.py` | 默认允许 `--host 0.0.0.0`；不校验 `Host`/`Origin`；token 文件只 `chmod(0o600)`（Windows 上不生效） | ①误绑到局域网 = 把"代用户加解密"能力暴露出去；②DNS rebinding/恶意网页可向 `127.0.0.1` 发请求（CSRF 触发副作用）；③同机其他用户可读 token | 非回环地址必须显式 `--allow-remote`（否则拒绝启动）；校验 Host 必须是回环、出现 `Origin` 一律 403；token 用 `icacls` 收紧到"当前用户+SYSTEM+Administrators"；无 token/短 token 拒绝启动。用例 `test_refuses_non_loopback_bind`、`test_rejects_foreign_host_header`、`test_rejects_browser_origin` |
| M7 | `watch.py::auto_encrypt_idle` | 默认"加密后删除明文"，但删除前**没有验证容器能解密回来** | 磁盘满、密钥不对、写坏容器时，源文件被删 = 数据永久丢失 | 删明文前 `verify_file()` 校验并比对明文哈希，失败则保留明文并报告。用例 `test_auto_encrypt_keeps_source_when_verify_fails` |
| M8 | `crypto.py::generate_keyfile` | 先 `exists()` 再 `write_bytes()`，竞态下会**覆盖已有密钥文件**（覆盖=旧密文永久打不开） | 两个进程同时 `keygen`，或主程序与 CLI 并发时，密钥被静默换掉 | 改 `O_CREAT|O_EXCL` 原子创建；顺带修了 Windows 文本模式把随机 0x0A 翻译成 CRLF 导致 32 字节密钥写出 33/34 字节的问题（间歇性测试失败的真凶）。用例 `test_keyfile_generation_never_overwrites` |

### 2.3 低危 / 健壮性

| # | 位置 | 问题 | 修复 |
| --- | --- | --- | --- |
| L1 | `crypto.py` 临时文件 | `mkstemp` 关闭 fd 后再按文件名 `open()`，共享目录下存在符号链接替换的 TOCTOU | 改为直接用 `mkstemp` 返回的 fd 打开（`os.fdopen`） |
| L2 | `crypto.py::encrypt_file` / `rekey_file` | 加密期间源文件变大时，多出内容被静默丢弃；`rekey` 不检查容器尾部垃圾 | 加密后 `read(1)` 必须 EOF 否则报错；rekey 同样校验尾部。用例 `test_source_growth_during_encrypt_is_detected`、`test_rekey_rejects_trailing_garbage` |
| L3 | `audit.py` | 崩溃留下的半截行会让日志永久无法追加；同秒两次 `log clear` 归档会互相覆盖；`h` 字段非 hex 直接抛未捕获 `ValueError`；`read_all` 把整个日志读进内存 | 半截尾行自愈（截断后继续）；归档名自动加序号；哈希字段格式校验；改为逐行流式读取。用例 `test_torn_tail_is_repaired`、`test_clear_in_same_second_does_not_overwrite_archive` |
| L4 | `config.py` | `Config.load` 对任意 key 做 `setattr`：配置里出现 `audit_dir` 会撞 property 抛 `AttributeError`；`iterations` 被改成 `5` 会把 KDF 强度归零；类型错误直接 `TypeError` | 只接受 dataclass 字段、逐项校验类型/范围。用例 `test_out_of_range_config_is_rejected`、`test_non_integer_config_is_rejected`、`test_unknown_and_property_keys_are_ignored` |
| L5 | `integrity.py` | 畸形清单（`iterations: 10亿`、非法 base64 salt）会跑超大 KDF 或抛底层异常 | 先做零算力结构校验再派生密钥。用例 `test_absurd_manifest_iterations_are_rejected_fast`、`test_malformed_manifest_salt_is_rejected` |
| L6 | `service.py` | 无 socket 读超时、无并发上限、畸形 `params` 返回 500 | 连接 30s 超时、并发 16 上限（超出 429）、参数统一校验返回 400。用例 `test_bad_params_return_400` |
| L7 | `cli.py` | `--password` 留在命令行/进程列表且无提示；目录批量 `--out` 把所有文件平铺，同名互相覆盖 | 使用 `--password` 时打印警告；批量输出保留相对子目录结构 |
| L8 | `crypto.py::DpapiVault` / `audit.py::_FileLock` | 保险箱文件 ACL 未收紧；锁的"过期抢占"只看 mtime，可能抢走慢进程的锁 | 保险箱写入后收紧 ACL；抢锁前确认持有者 pid 已退出（Windows 用 `OpenProcess`，POSIX 用 `kill(pid,0)`） |

## 5. 残余风险（本次不修 / 需要更大改造）

| 风险 | 说明 | 建议 |
| --- | --- | --- |
| 完整回滚无法本地自证 | 攻击者把"日志 + meta"整体替换成更早的**一致快照**再让程序继续写，任何本地文件都区分不了（等于恢复虚拟机快照） | 用 `log head` 把链头哈希定期抄到注册表/另一台设备，`log verify --expected-head` 比对；或把链头写进 TPM/Windows 证书存储 |
| 模块自校验可被同权限攻击者绕过 | `integrity.py` 是"防误改/防低级篡改"；攻击者能改代码就能改校验逻辑 | 正式发版用 Authenticode 代码签名（`signtool`），主程序启动时校验 exe/安装包签名 |
| 硬链接绕不过 | 同卷硬链接不是重解析点，无法在扫描/监听时识别，可把目录外内容"带进来" | Windows 上创建硬链接需要写权限；如需强隔离，用文件系统 ACL + 专用保护目录 |
| 密码/密钥无法保证从内存擦除 | Python 的 `str`/`bytes` 不可控，DPAPI 解出的密码会驻留 | 高安全场景改为进程内短生命周期 + 独立服务进程；不要把密码写进 argv/env |
| 本地服务仍是本机信任边界 | 任何能读到 token 的本机进程都能调用加解密 | 桌面助手建议**直接 import**（同进程）或改用命名管道/stdio JSON-RPC，不走 TCP |
| 单进程假设 | 备份索引有内存缓存（为性能），多进程同时写备份库时版本号可能冲突 | 备份操作用单进程（服务模式天然满足）；多进程场景加文件锁 |
| 弱口令离线爆破 | PBKDF2 600k 次对强口令足够，对 `123456` 无意义 | UI 加强度提示/禁止弱口令；后续可换 Argon2id（改 `crypto.derive_key` 一处即可） |
| PDF/图片内容未检测 | 设计内（二期接 `pypdf` / OCR） | 见 `docs/从设计方案到代码.md` 扩展点 |
| "打开"事件缺失 | 轮询拿不到 open 事件 | 桌面助手在打开文件时主动 `audit.record("open", ...)`；生产接 ETW |

## 6. 接入桌面助手（PyQt / tkinter）的安全建议

你选的是 Python 主程序，最省事也最安全的接法是**同进程直接 import**：

```python
from file_guard import encrypt_file, decrypt_file, SensitiveScanner, AuditLog, BackupStore

# 密码用 QInputDialog / getpass 现取，绝不放进 argv、日志、文件
password = self._prompt_password()
encrypt_file(path, password=password, progress=lambda d, t: self.progress.setValue(d * 100 // t))
```

要点：

1. **密码入口**：用 `QInputDialog.getText(..., QLineEdit.Password)` / `getpass`，不要拼接
   `python -m file_guard --password ...`；需要免密就用 `init` 的 DPAPI 保险箱（绑定当前 Windows 用户）。
2. **别阻塞 UI 线程**：扫描/备份/加密大文件放 `QThread` / `Worker`，扫描用
   `ScanControl` 暴露暂停/继续/停止，`progress` 回调驱动进度条。
3. **长任务用服务模式做崩溃隔离**：`python -m file_guard serve` 独立进程 + `127.0.0.1` +
   token，主程序只处理 `{"ok": false}`；服务挂了重启即可，不影响 UI。
4. **托盘场景"临时解密 → 自动重新加密"**：解密打开文件时 `audit.record("open")`，
   关闭后调 `watch.auto_encrypt_idle(..., remove_source=True)`（已内置"删明文前先校验"）。
5. **首启初始化**：`file_guard init --no-vault`（不想用 DPAPI 缓存时）或让用户设密码；
   初始化后跑一次 `integrity init`，主程序启动时 `integrity check` 做自检告警。
6. **打包**：PyInstaller 单文件后 `.py` 哈希清单意义下降，改为对整个 exe 做 Authenticode 签名校验。
