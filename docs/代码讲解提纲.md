# 代码讲解提纲（怎么把 file_guard 讲清楚）

> 这份文档解决一个问题：**站在人前，怎么用 5 / 15 / 30 分钟把这套代码讲明白，并且让人相信它是安全的。**
> 配套素材：README、`docs/从设计方案到代码.md`、`docs/安全评审与加固.md`、
> `docs/框架临时验证报告.md`、`docs/运行截图/`、`tests/`。

## 0. 先定三件事（讲之前 1 分钟想清楚）

| 问题 | 错误做法 | 正确做法 |
| --- | --- | --- |
| **听众是谁** | 对领导念 `AESGCM.encrypt` | 领导听"边界、风险、验证"；同事听"分层、时序、坑"；评审听"威胁模型、失败路径、测试证据" |
| **听完要记住什么** | 讲完 20 个函数 | 只留 3 句：本地离线、一次一密、所有删除前先证明能恢复 |
| **凭什么信你** | "我们测试过了" | 报数字 + 现场跑：126 个测试、52 项验收、33 条攻击回归、20 项评审问题已修 |

**讲解顺序铁律**：不按目录讲（不要 crypto → scan → audit…），**按数据流讲**（一次加密/一次攻击/一次恢复），文件只是在流程里被顺带点到。

## 1. 三档时长怎么切

### A. 5 分钟电梯版（对领导 / 非技术）

1. 一句话定位：桌面助手的"文件保险柜 + 监控 + 备份"，纯本地，不联网。
2. 一张架构图（五层，见 README 第 1 节）。
3. 演示一条主流程（加密→篡改→解不开→还原）。
4. 三个数字：126 测试通过、52 项验收通过、20 项安全问题已修。
5. 一句话边界：忘密码就解不开（不设后门）；要更强防篡改需代码签名 + 外部锚点。

### B. 15 分钟技术版（对同事 / 接手的人）

1. 3 分钟：目标与威胁模型（防什么、不防什么）。
2. 5 分钟：**一次加密请求的端到端时序**（本文第 2 节），顺带讲容器格式。
3. 4 分钟：三个关键设计（随机 nonce 审计、密钥化对象名、边界隔离），每个都讲"不这么做会怎样"。
4. 3 分钟：并发/失败模型 + 演示 `run_acceptance.py`。

### C. 30–40 分钟代码走读版（评审 / 答辩）

按下面第 3 节的"讲解单元"表走，每个单元固定四句话（见第 4 节）。
中途穿插"现场验证"：每讲完一个防线，跑对应测试或命令。

## 2. 讲一条主线：一次加密（15 分钟版的骨架）

按顺序讲这 6 步，**每一步只指一个文件、一个函数**：

| 步骤 | 代码位置 | 讲解要点 | 一句话证据 |
| --- | --- | --- | --- |
| ① 口令从哪来 | `cli.resolve_password` | 五种来源优先级；`--password` 会警告；密码不落盘 | `test_log_is_encrypted_at_rest` 断言磁盘 grep 不到口令 |
| ② 派生密钥 | `crypto.derive_key` | PBKDF2-HMAC-SHA256、随机 16B 盐、600k 次；参数进容器头 | `test_deterministic_and_salt_sensitive` |
| ③ 造容器头 | `crypto._build_header` | 80 字节；头部哈希 + 头部参与每块 AAD | 改头 → `test_header_tamper` |
| ④ 分块加密 | `crypto._encrypt_stream` | 1 MiB/块；nonce=前缀‖块号；AAD=头‖块号‖末块标记 | 改字节/截断/换序 → `TamperTest` 全灭 |
| ⑤ 安全落盘 | `crypto._open_temp` + `os.replace` | mkstemp 的 fd 直写防符号链接替换；失败删 `.part` | `test_failed_decrypt_leaves_no_partial_file` |
| ⑥ 留痕 | `audit.EncryptedLog.append` | 写前先验 meta 签名、口令、高水位 | 错口令写入被拒 → `test_wrong_password_cannot_corrupt_log` |

讲完这条线，听众已经能理解容器格式、失败路径、和"为什么不能自己随便搓 AES"。

## 4. 讲任何一段代码，固定四句话（最重要）

不要念代码。每段代码只讲这四句：

```
1) 它解决什么问题？        —— 业务视角一句话
2) 输入 / 输出 / 失败时怎样？—— 边界与错误码
3) 关键的 2~3 行在做什么？   —— 只指真正有信息量的行
4) 凭什么证明它对？        —— 对应测试名或现场命令
```

**示范讲解词（`audit.EncryptedLog.append`，约 90 秒）**：

> "每写一条审计，先做三件自检：meta 签名对不对、给定口令能不能解开最后一条、日志长度有没有低于 meta 的水位（低就是被回滚了）。都过了才生成 12 字节**随机 nonce** 加密这条记录，并用 `h_i = HMAC(chain_key, h_{i-1} ‖ nonce_i ‖ ct_i)` 接到链上。为什么 nonce 必须随机而不是'前缀+序号'？因为日志一旦被回滚，前缀+序号会复用 nonce，AES-GCM 下会同时泄露明文异或值和认证密钥。证据是 `test_each_record_uses_fresh_random_nonce` 和 `test_rollback_is_detected_on_append_and_verify`。"

**示范讲解词（`crypto._encrypt_stream`，约 60 秒）**：

> "大文件不能整体读——内存爆、还没法防截断。所以按 1 MiB 分块，每块独立 nonce 和 GCM tag；AAD 里绑定'头部、块号、是否最后一块'，于是改密文、换块序、截断、追加垃圾都会在解密时失败。块号在 AAD 里而不是明文里，攻击者挪动位置就解不开。"

## 5. 三个"最能体现工程能力"的设计（挑两个讲）

1. **审计日志的 nonce 与回滚检测**：随机 nonce + meta 签名 + 水位线（对应 33 条安全回归里的 S1/M5）。
2. **备份对象名密钥化**：为什么不用明文 `SHA-256` 当文件名（会泄露"某内容是否在备份里"，还能定向删对象）。
3. **边界隔离**：`os.walk(followlinks=False)` 挡不住 Windows 目录联结，必须 `fsutil.is_reparse_point` + `os.path.isjunction`。

讲这三个时统一用句式：**"看起来做了 → 实际没生效 → 我们怎么发现的 → 怎么修 → 哪条测试盯着"**。这比背 API 有说服力得多。

## 6. 现场演示脚本（按顺序敲，5 分钟）

```bash
# 0) 环境与自检
python -m file_guard doctor

# 1) 加密 → 看头 → 校验 → 解密
python -m file_guard init
python -m file_guard encrypt "合同.docx"
python -m file_guard info "合同.docx.fgc"
python -m file_guard verify "合同.docx.fgc"
python -m file_guard decrypt "合同.docx.fgc" --force

# 2) 篡改演示（改 1 字节 → 解不开且不留半截明文）
#    现场用 PowerShell 改文件最后 1 字节再 decrypt，看 exit 3

# 3) 检测（真实合同命中合同/手机号/邮箱，样本打码）
python -m file_guard scan "合同.docx" --min-risk medium

# 4) 审计链（改一行/删一行后 verify 变红）
python -m file_guard log list --limit 5
python -m file_guard log verify

# 5) 备份 → 删源 → 恢复 → 回滚旧版本
python -m file_guard backup add "合同.docx"
python -m file_guard backup restore "合同.docx" --version 1

# 6) 一次性证据：验收 + 测试
python scripts/run_acceptance.py
python -m unittest discover -s tests -q
```

> 演示前先 `init` 到一个临时 `--home`，别污染真实数据目录；密码用环境变量，避免录屏泄露。

## 7. 必背的 10 个问答（评审很爱问）

| 问题 | 回答要点 |
| --- | --- |
| 密码忘了怎么办？ | 不设后门；设计上就没有找回通道（`docs/从设计方案到代码.md` 明确写了这条约束） |
| 为什么不用现成加密库封装？ | `cryptography` 只提供原语；容器格式、AAD 绑定、原子写、密钥管理是安全边界，必须自己写并测 |
| 为什么不整文件一次加密？ | 内存爆炸 + 无法防截断；分块后每块独立认证、AAD 绑定块号与末块标记 |
| 为什么审计链用 HMAC 不用 SHA-256？ | 裸哈希攻击者可改一行再重算后面全部；没有密码算不出 HMAC |
| 日志被整体回滚怎么办？ | 本地无法自证；用 `log head` 把链头抄到注册表/另一台设备，`verify --expected-head` 比对 |
| 本地服务为什么敢开端口？ | 只绑回环、token（ACL 收紧）、Host/Origin 校验、并发与超时上限；主程序是 Python 时更推荐直接 import |
| 备份对象名为什么不是 sha256？ | 明文哈希会泄露"内容是否在库里"、可离线暴力、可定向删对象；改成密钥化 HMAC，去重能力不变 |
| 换机能用吗？ | 加密容器可迁移（盐和迭代次数在头里）；`~/.file_guard` 的 DPAPI 保险箱绑定当前 Windows 用户，需要重新 init |
| 性能如何？ | PBKDF2 600k ≈ 0.2~0.4s/次（只解密时要算一次）；5 MiB 加密约 0.18s；扫描 200 小文件约 0.3s |
| 怎么证明安全？ | 126 个测试（含 33 条攻击回归：nonce 复用、目录联结越界、zip 炸弹、恶意索引、回滚/篡改、Host/Origin）+ 20 项评审问题闭环 + 52 项端到端验收 |

## 8. 讲解避坑清单

- ❌ 从 `import` 和目录树开始讲 → ✅ 从"用户点一下加密会发生什么"开始。
- ❌ 逐行念代码 → ✅ 一段代码只讲"输入输出 + 2~3 行关键逻辑 + 失败路径"。
- ❌ 说"这里我也没太看懂/大概是" → ✅ 不确定就现场跑测试，让证据说话。
- ❌ 只讲成功路径 → ✅ 主动讲失败路径（改字节、错密码、回滚、越界），这才是安全模块的重点。
- ❌ 把 TODO 藏起来 → ✅ 主动说残余风险（完整回滚需外部锚点、硬链接、内存擦除、代码签名），显得可信。
- ❌ 讲完就结束 → ✅ 留 1 分钟现场跑 `run_acceptance.py`，把"52 项通过"的终端画面留在屏幕上。
