# v0.4 文件子系统重构实施清单（Phase A：把搜索做稳）

> 配套文档：`文件检索重构方案.md`（基础架构）、`文件治理功能设计.md`（Phase B–E）
> 本文只覆盖 **Phase A = A1–A8**，目标是"每步都能独立编译、独立提交、独立验收"，且**旧代码始终有一条能用的退路**。
> 原则：**架构一次设计完整，功能分阶段落地**。本文提到的接口是 A 阶段的**最小可编码版本**；治理相关字段/能力留到 Phase B 再加（但要保证加得进去）。
> **版本归属**：本文占用 GUIDE.md 中空置的 **v0.4.0**（v0.3.0 = Phase 3 主面板，v0.5.0 = GUIDE Phase 4 插件+发布）。

## 0. 三条贯穿全程的约定

1. **新增/删除源文件后必须重新 configure**（项目用 `file(GLOB_RECURSE)`，已有踩坑记录 `docs/troubleshooting/cmake-glob-recurse-新文件不编译.md`）。
2. **每步一个提交范围**：A1 单独 patch；A2–A4 一个 feature 分支；A5–A7 一个分支。
3. **性能优化全部 gated**：位图预筛、细化缓存、SoA/UTF-8、并行查询**都不在 A 阶段做**，等 A4 的 baseline 数据说话（基础架构 §9 第一步）。A 阶段只保留一个"不算优化"的改动：`nameLower` 预计算（消除每按键 N 次 `toLower()` 分配，属于修 P1-2 缺陷）。

## A1 — 止血（独立 patch，`fix(file-search):`）✅ 已落地 2026-09-24

**目标**：不改变任何架构，只修三个已在代码中确认的缺陷。

| 改动 | 文件 | 具体做法 | 状态 |
|---|---|---|---|
| 不跟随符号链接/junction（P0-1） | `src/core/FileSearcher.cpp` | ~~`QDirIterator` 过滤器加 `QDir::NoSymLinks`~~ → **无效**，见下方修正。实际：自己控制递归（`walkDir()` 前序 DFS）+ `info.isSymLink() \|\| info.isJunction()` | ✅ 已修 |
| 去掉热路径上的字符串分配（P0-2） | `src/core/FileSearcher.cpp` | 不再逐条文件回看整条路径；改为**目录级剪枝**：目录名命中 `kSkippedDirs` 就整棵子树不进 | ✅ 已修 |
| 搜索不再写库（P1-5） | `src/ui/AppBridge.cpp` | 删除 `search()` 末尾的 `recordSearch`；改到 `executeCommand()` 成功分支里记录（历史语义变更见 §0.4） | ✅ 已修 |
| 输入防抖 + IME 拦截（P1-6） | `resources/qml/MainWindow.qml` | `onTextChanged` 改为 `debounceTimer.restart()`（`Timer{ interval:40 }`）；开头加 `if (searchInput.inputMethodComposing) return;` | ✅ 已修 |

> **计划修正（2026-09-24 实测）**：`QDir::NoSymLinks` **挡不住 Windows junction**。
> ①Qt 的 `isSymLink()` 只认 `IO_REPARSE_TAG_SYMLINK`，junction 是 `IO_REPARSE_TAG_MOUNT_POINT`
> （Qt 6.2 为此补了 `isJunction()`）；②`QDirIterator` 的过滤器只决定"返回哪些条目"，
> **不决定"是否递归"**，即 `Subdirectories` 模式下没有"不下降进某子目录"的开关。
> 实测加了这个 flag 后索引里仍有 126 条 63 层叠罗汉路径。
> 所以 P0-1/P0-2 都只能在**是否递归**这一层修 —— 遍历必须自己控制（A3 换成 Win32 迭代栈）。
> 详见 `docs/troubleshooting/qt-nosymlinks-挡不住junction.md`。

**不做**（留给 A3）：把 `QDirIterator` 换成 Win32 迭代式 DFS（A1 用 Qt API 顶一下，
顺序保持前序 DFS 以免截断结果改变）；上限策略调整（本机 Desktop 3.5 万文件、索引
20000 全是 Desktop 的，`Documents`/`Downloads` 一个都没进来 —— 这条的实际优先级比原计划高）。

**验收（2026-09-24 实测）**：
① junction 不重复、不递归 —— 索引全路径 dump 后 grep，含 `/loop/` 的条目 126 → **0**，探针文件恰好 2 条；
② 连打 8 个字符只触发 1 次 `search` —— debug 日志只出现 1 行 `AppBridge::search 'abcdefgh'`；
③ 打字过程中 `history.db` 无新增行 —— 43 → **43**；再补正向对照：输 `1+2` 按 Enter 后 43 → **44**。

**回退**：单 commit，`git revert` 即可，无接口变化。

**已定：旧数据清空（已执行）。** `search_history` 的语义从"每次按键"变为"每次执行"，
旧记录（前缀垃圾）无保留价值。2026-09-24 在开发机执行 `DELETE FROM search_history;`
（44 → 0），`command_history` / `app_launch_history` 未动。等 A3 的 `DatabaseMigrator`
上线后，同类变更才走迁移通道。

## A2 — 结构与并发（`feat(file-index):` 起点）

**目标**：立起门面 + 快照 + COW 发布 + 后台扫描线程，**查询能力与旧版等价**（不追求变快）。

**新增**：

```
include/core/FileSnapshot.h        // 只读快照：数据 + 访问器（物理表示藏在这里）
include/core/SnapshotManager.h/.cpp// 持有/发布当前快照（COW）
include/core/FileIndex.h/.cpp      // 门面（薄，见基础架构 §2.2）
```

**关键接口（最小版）**：

```cpp
// FileSnapshot.h —— 唯一允许查询层接触的表示（基础架构 §3.1 的硬约束）
class FileSnapshot {
public:
    int            size() const;
    QString        nameAt(int i) const;        // 展示用
    QString        lowerAt(int i) const;       // 匹配用（预折叠小写）
    QString        pathAt(int i) const;        // 定位用
    qint64         sizeAt(int i) const;
    qint64         mtimeAt(int i) const;
private:
    struct FileEntry { QString name, nameLower, path; qint64 size, mtime; };  // v1 简单表示
    std::vector<FileEntry> m_entries;          // 20 万条 ≈ 50–70 MB（未超预算）
};

// SnapshotManager.h —— COW 发布
class SnapshotManager {
public:
    std::shared_ptr<const FileSnapshot> current() const;   // 读侧：取一份即用，无需加锁
    void publish(std::shared_ptr<const FileSnapshot> s);   // 写侧：构建完一次性发布
};

// FileIndex.h —— 门面只做 4 件事
class FileIndex {
public:
    void startAsync();                                  // 建库→载入→建快照→起后台扫描
    void refresh();
    QList<SearchResult> query(const QString &text, int limit);
    IndexStats stats() const;                           // { entries, ready, scanning, msLastScan }
};
```

**修改**：`src/main.cpp`（`FileSearcher::buildIndex()` → `fileIndex.startAsync()`，放在 `engine.load()` **之前**但不再阻塞）；`src/ui/AppBridge.cpp`（持有 `FileIndex*`，`search()` 里改调 `FileIndex::query()`）；`include/ui/AppBridge.h`（加 setter，与 `setHistoryDatabase` 同风格）；`include/core/ConfigManager.h`（加 `fileIndex.engine`）。

**先决验证（10 分钟，别跳过）**：MSVC 是否支持 `std::atomic<std::shared_ptr<const T>>`（C++20）。写个 3 行 snippet 编译一次；**不支持就换 `std::shared_mutex`**（本场景读极多写极少，性能足够），别为它绕路。

**回退开关**：`fileIndex.engine = "legacy" | "v2"`。A2 期间默认 `legacy`，验收通过后再切 `v2`——这样任何异常都能一行配置退回去，**旧 `FileSearcher` 此阶段完全保留**。

**验收**：① 冷启动窗口立即可见（后台再建索引，状态栏显示"正在建立索引…"）；② `engine=legacy` 时行为与 A1 完全相同；③ 20 万条合成语料下查询结果与旧版**逐条一致**（golden 对比）。

## A3 — 采集层（Win32 扫描 + 持久化 + 迁移框架）

**目标**：真正的目录级剪枝与差量持久化。

**新增**：

```
include/core/FileScanner.h/.cpp              // 迭代式 DFS（FindFirstFileExW）+ QThread worker
include/database/FileIndexDatabase.h/.cpp    // files / dirs / roots + 差量事务
include/database/DatabaseMigrator.h/.cpp     // PRAGMA user_version 前向迁移（基础架构 §3.6）
```

**扫描器要点**（基础架构 §3.2）：`FindFirstFileExW(FindExInfoBasic + FIND_FIRST_EX_LARGE_FETCH)`；目录级剪枝（进入目录时一次判定，命中即整棵子树跳过）；不跟随 reparse point；长路径 `\\?\`；权限拒绝逐目录跳过并计数；路径用栈式缓冲区避免逐条拼接分配。

**持久化要点**：
- 差量：`diskSet` vs `dbSet` 三方差集（`added`/`removed`/`changed`，按 `size+mtime`），单事务批量写（`BEGIN IMMEDIATE`，每 1000 行一提交）。
- **迁移框架先于字段增补落地**：`user_version` 从 1 起；`migrate_1_to_2()` = `ALTER TABLE files ADD COLUMN cat_mask/flags/root_id/origin_id` + `CREATE INDEX idx_files_sizemtime`（基础架构 §3.5/§3.6）。
- `file_index.db` 是**派生数据**：迁移失败直接重建（删文件重扫），但代码路径仍走 `DatabaseMigrator`，保持与 `downloads.db` 一致。

**验收**：① 20 万条全量扫描耗时进 baseline 表；② 含 `node_modules` 的工程目录条目数下降 ≥ 95%（记录前后对比到 `docs/devlog/`）；③ **迁移用例**：拿 A2 生成的旧库启动新版本 → 加列成功且原有数据行数不变；④ 杀一次进程再启动，差集正确收敛（无重复行、无残留行）。

## A5 — 增量与事件（`FileWatcher` + `FileSystemEvent`）

**新增**：

```
include/core/FileSystemEvent.h            // struct（不要全局 EventBus）
include/core/FileWatcher.h/.cpp           // ReadDirectoryChangesW（每根一句柄、递归子树）
include/core/FileEventDispatcher.h/.cpp   // 极轻量：注册消费者的 vector + 分发
```

```cpp
struct FileSystemEvent {
    enum Type { Added, Removed, Renamed, Modified, Overflow };
    Type    type;
    QString path;        // 新路径（Removed 时是旧路径）
    QString oldPath;     // Renamed 时有效
    qint64  timestamp;
};
```

**要点**：`bWatchSubtree=TRUE`；`FILE_NOTIFY_CHANGE_FILE_NAME|DIR_NAME|SIZE|LAST_WRITE`；**`ERROR_NOTIFY_ENUM_DIR` → 发一个 `Overflow` 事件 → 该根全量重扫**（不是静默丢事件）；事件按路径 200 ms 合并去重（OneDrive/编译输出抖动）；每个消费者独立注册，**`FileWatcher` 不认识任何具体模块**。

**验收**：① 新建/改名/删除文件 ≤ 100 ms 可在搜索里看到；② 用脚本快速制造大量变更触发溢出，日志出现 `Overflow` 且索引最终收敛正确。

## A6 — 冷启动与 frecency

**目标**：从"每次启动重扫"改成"先可用、后校正"。

- `startAsync()` 顺序：**载入 DB → 构建快照 → 发布（此时即可查询）→ 后台差量扫描 → 扫描结果增量补丁**（基础架构 §3.5 两阶段流程）。
- frecency：`files.frecency` 载入快照；**只在执行时**更新（`AppBridge::executeCommand`），异步写库、不重建快照。
- 空查询返回 frecency top-8 作为「最近使用」分组（不是把文件混进默认列表）。

**验收**：冷启动到可查询 < 300 ms（20 万条）；杀掉进程重启后冷启动路径仍走 DB（日志可证）。

## A7 — 融合与收尾（删除兼容层）

- `include/core/ISearchProvider.h`：`query(text, limit) -> QList<SearchResult>`。
- `AppBridge::search()`：防抖 + 世代号 + **k-way merge**（各 provider 取 top-K 后归并，替掉现在的"拼大列表再全排序" `AppBridge.cpp:120-125`）。
- Calculator **门禁**：只在"含数字 + 含运算符"时才跑解析器（现在是每次按键都跑）。
- 加**打分日志开关**（`fileIndex.debugScore`），能解释"为什么这个排第一"。
- 删除 `FileSearcher::buildIndex/search/size` 兼容层与 `engine` 开关（`v2` 为唯一实现）。
- QML：Ctrl+Enter 打开所在文件夹、Shift+Enter 复制路径。

**验收**：结果与 A6 一致或更优；`FileSearcher` 相关代码全部删除后仍能编译运行；`CLAUDE.md` 模块表更新（Phase A 落地）。
