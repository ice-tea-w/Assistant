# 快捷同步与投递区 · 设计文档

> 2026-11 立项。目标：把「设备同步」从"手动点同步"升级成"拖一下就发过去、改一下就自动同步"，
> 补齐共享目录的 UNC 用法和并发安全。
> 前置文档：`docs/architecture/设备同步功能-设计文档.md`（三方差集、通道接口、`.sync/manifest.json` 布局）。

## 1. 目标与范围

### 要做

1. **拖拽即发**：把文件拖进同步页的投递区（或点「选择文件」），对端程序在线时约 3 秒内收到，
   拷进本地收件箱并弹托盘通知；不在线就留在共享目录里，下次启动自动领取。
2. **变化即同步**：本地同步根里的文件一改就自动跑一轮同步，不需要手动点；另留定时兜底。
3. **文件级并发安全**：两台机器同时同步时，共享目录里只有一份 `manifest.json`，
   读-改-写会互相覆盖条目。加同步锁把两端串行化。
4. **UNC 共享目录**：共享目录可填 `\\对端IP\共享名`，并提供「检查共享」自检，
   能看出可访问/可写/对端设备名/最后同步时间/文件数。

### 不做

- TCP 直连通道（`LanTransport`）与配对码握手——异地/局域网直连要 NAT 穿透与中继，不做。
- 自动创建 Windows 文件夹共享（需管理员权限；由用户手动开一次，程序只给命令模板）。
- 投递历史列表（先只给状态行与托盘通知，后续看使用情况再说）。

## 2. 现状与复用

| 已有 | 位置 | 复用方式 |
|---|---|---|
| 三方差集引擎 | `include/core/sync/SyncEngine.h`, `src/core/sync/SyncEngine.cpp` | 不动判定表，只在 `sync()` 入口拿锁、出口释放 |
| 共享目录通道 | `include/core/sync/FolderTransport.h`, `src/core/sync/FolderTransport.cpp` | 加锁实现、加 manifest 设备字段 |
| 传输接口 | `include/core/sync/ITransport.h` | 加 `tryLock`/`unlock` 默认空实现 |
| 同步 DB | `include/database/SyncDatabase.h`, `src/database/SyncDatabase.cpp` | 加 `received` 表 |
| 面板桥 | `include/ui/SyncBridge.h`, `src/ui/SyncBridge.cpp` | 加发送/领取/检查共享/自动触发 |
| 同步页 | `resources/qml/SyncPage.qml` | 加投递卡、检查共享、收件箱、自动同步开关 |

**关键现状（实现时不要踩）**：

- `src/core/sync/FolderTransport.cpp:193-203 FolderTransport::updateManifestEntry` 是
  read-modify-write，跨进程不原子。`writeManifest`（:155-191）本身是 tmp+rename 原子替换，
  但"读到旧清单 → 改 → 写回"这一段没有互斥，两端同时 push 不同文件会丢掉对方刚写的条目。
- `src/core/sync/SyncEngine.cpp:314-334` 的 compare-and-swap 只重新核对**当前这一个文件**的
  对端状态，不防整张清单被覆盖。
- 丢条目的后果链：A 推 X 写清单 → B 基于旧清单推 Y 写清单，X 条目消失 → A 下一轮扫到
  `L 有、S 有、R 无` → 判定 `DeleteLocal` → X 被移进 `%LOCALAPPDATA%/AssistantTeam/Assistant/sync-trash`。
  文件能找回，但用户不知道发生了什么，这是必须堵的洞。
- `SyncEngine::sync()` 有多个提前 return 点，锁必须用 RAII 释放。

## 3. 设计

### 3.1 同步锁

**接口**（`include/core/sync/ITransport.h`）：

```cpp
virtual bool tryLock(int waitMs = 0) { Q_UNUSED(waitMs); return true; }
virtual void unlock() {}
```

默认空实现 = 直连通道将来自己决定，不影响现有代码。

**FolderTransport 实现**：

- 锁文件 `<共享目录>/.sync/lock.json`，内容 `{"device":"...","pid":123,"time":1700000000}`。
- 获取：`QFile::open(QIODevice::WriteOnly | QIODevice::NewOnly)` —— Windows 上映射为
  `CREATE_NEW`，SMB 上由服务器保证原子性。拿不到说明别人持有。
- 持有者判定：读锁文件，取 `QFileInfo::lastModified()`（SMB 上是文件服务器时间，跨机器可信）
  与当前时间差；超过 **30 秒** 视为进程崩溃残留，`QFile::rename` 到 `.sync/lock.stale` 后
  删除并重试一次。
- 等待：`sleep 3 秒`（`QThread::msleep`）重试直到 `waitMs` 用尽；`sync()` 里给 5000ms。
- 释放：删除锁文件。删除失败只记 warn，不抛错。
- 失败路径：`tryLock` 返回 false → `sync()` 返回新状态 `SyncResult::Busy`，
  文案「另一台设备正在同步，稍后自动重试」，由定时器/去抖自动再来。

**为什么不用 Windows 命名互斥量**：跨机器无效，SMB 上的文件创建才是两端都能看到的互斥点。

### 3.2 投递区与自动领取

**目录与命名**：

- 投递目录 `<共享目录>/_投递/`。它不在任何同步根的别名子树下，也不写进 manifest，
  所以完全不参与三方差集。
- 文件名：`<发送者>_<yyyyMMdd-HHmmss>_<原名>`。解析只切前两段，原名里含 `_` 不受影响。
- 发送者 = 本机设备名，按 Windows 非法字符表替换 `<>:"/\|?*` 为 `-`，空则用 `device`。
- 同一秒同发送者同名重名：追加 `_2`、`_3`。
- 写入：先写 `<最终名>.part`，写完 `QFile::rename` 成最终名。领取端跳过 `.part`。

**发送侧**（`SyncBridge`）：

- `Q_INVOKABLE bool sendFiles(const QStringList &paths)`：复制到 `_投递/`。
  走工作线程（`QThread::create`），避免大文件卡 UI；逐个文件发 `sendProgress`.
- QML：`DropArea`（接收 `urls`）+「选择文件…」按钮（`FileDialog` 多选）。

**领取侧**：

- 固定 3 秒轮询 `_投递/`（不用 QFileSystemWatcher：UNC 与网盘目录的变更通知不可靠）。
- 新文件判定：`_投递` 下所有非 `.part` 文件名与 `sync.db` 的 `received.relPath` 做差集。
- 新鲜度门槛：文件 mtime 距今 < 2 秒则本轮跳过（对方可能还在跨机器复制）。
- 领取：复制到收件箱，去掉前缀恢复原名；重名加序号。成功后写 `received`，并
  `TrayManager` 气泡「收到 N 个文件」。
- 收件箱：`QStandardPaths::DocumentsLocation + "/Assistant 收件箱"`，配置键
  `syncInboxDir` 可覆盖（空 = 默认）。
- 投递区副本默认**保留**（发送方还能看到已投递），不做自动删除。

### 3.3 自动同步触发

三条触发源，任一命中都走同一个「去抖后请求同步」入口：

1. **本地根目录变化**：`QFileSystemWatcher` 递归注册各同步根的子目录（上限 1000 个目录，
   超出记 warn，该根退化为定时兜底）；事件 → 去抖 2 秒。
2. **共享目录清单变化**：watcher 监视 `<共享目录>/.sync` 的 `manifest.json`；UNC 上
   watcher 可能失效，再加 3 秒轮询 `manifest` 的 `(mtime, size)` 作为补充。
3. **兜底定时器**：沿用 `syncAutoIntervalMinutes`（0 = 关闭），默认 5 分钟。

**同步中再触发**：记 `m_pending`，本轮结束后 3 秒再跑一次。不做"永久防抖"：第二轮引擎发现
无变化就是 0 动作、不再写盘，循环自然收敛；冲突副本是真实变化，应当再跑一轮。

**配置**：新增 `syncWatchFiles`（bool，默认 true，Q_PROPERTY `watchFiles`）。
`syncAutoIntervalMinutes` 语义改为"兜底间隔"，不改名。

**QML**：自动同步区块加「文件变化时自动同步」开关，ComboBox 保留四档作为兜底间隔。

### 3.4 UNC 与检查共享

- 共享目录输入接受 `\\server\share`；`FolderTransport` 构造时用
  `QDir::fromNativeSeparators` 后保留 `//server/share` 形式（Qt 与 Win32 API 都接受正斜杠 UNC）。
- `probe()` 已有 `.write-probe` 实写验证，UNC 下同样有效，无需改。
- `Q_INVOKABLE QVariantMap checkShared()` → `{ok, writable, hasManifest, device,
  updatedAt, fileCount, message}`。实现：构造临时 `FolderTransport` 跑 `probe()`、
  `readManifest()`、`remoteDevice()`、`manifestUpdatedAt()`。
- QML：共享目录输入框旁加「检查共享」按钮，结果显示在下方 Label（可写/对端设备/最后同步时间/文件数）。
- 帮助文案：一行说明 + 「复制命令」按钮，内容
  `net share Assistant=E:\要共享的目录 /grant:everyone,full`。

### 3.5 manifest 设备字段

`writeManifest` 增加：

```json
{"version": 2, "device": "本机设备名", "updatedAt": 123, "files": [...]}
```

老版本读到 `version=2` 与多余字段会忽略，向后兼容；新版本读到 `version=1` 无 `device`
时按空处理。`FolderTransport` 增加 `QString remoteDevice() const` 与
`qint64 manifestUpdatedAt() const`（读清单时顺带解析，或独立读一次小文件）。

状态条「对端」列改为：`manifest.device` 为空则「未知」，否则 `设备名（最后同步 mm:ss）`。

### 3.6 数据模型

`sync.db` 新增表：

```sql
CREATE TABLE IF NOT EXISTS received (
    relPath    TEXT PRIMARY KEY,   -- 投递区里的文件名（去掉前缀前的原始名）
    hash       TEXT NOT NULL,      -- 领取时的 SHA-256，便于排查
    receivedAt INTEGER NOT NULL
);
```

`SyncDatabase` 增加 `bool isReceived(const QString&)`, `void markReceived(const QString&, const QString&)`,
`QSet<QString> receivedPaths()`。

注意：这张表与三方差集的 `sync_state` 无关，删 `sync.db` 会重置领取记录（会重复领取一次，
可接受，设计文档里写明）。

### 3.7 UI 变更（`resources/qml/SyncPage.qml`）

1. 顶部新增「发送文件」卡片：`DropArea` + 说明文字 +「选择文件…」+ 发送进度/结果行。
2. 「共享目录」区块加「检查共享」按钮 + 结果 Label + 共享命令提示（可折叠）。
3. 「自动同步」区块加「文件变化时自动同步」开关。
4. 状态条「对端」列显示 `manifest.device`。
5. 新增「收件箱」一行：路径 + 「打开文件夹」按钮。
6. 「对端名称 / 配对」文案改为「本机设备名 / 保存」（现在那个按钮只写设备名，不存在配对握手）。

## 5. 测试与验收

### 自动化（QTest，51 例全绿）

本轮新增 6 例：

1. `folderTransportLockHeld`：A 持锁时 B 拿不到；A 释放后 B 能拿到。
2. `folderTransportLockTakeover`：人为造一个 40 秒前的 `lock.json`，新实例能接管而不是卡死。
3. `deliveryNameRoundTrip`：`发送者_时间戳_原名` 命名、设备名非法字符（含 `_`）清洗、空设备名兜底、超长原名截断到 120 字符且保留扩展名、前缀还原。
4. `deliveryPlaceIncoming`：投递文件落进收件箱时还原原名；同名再进来生成 `(2)` 副本，不覆盖。
5. `databaseReceived`：`received` 表去重，重复标记不炸。
6. `configWatchInboxRoundTrip`：`watchFiles` / `inboxDir` 配置往返。

未自动化（由真机验收覆盖，属 QML / 线程边界）：

- `sendFiles` 的 `.part` 先写后改名（在 `SyncBridge`，依赖工作线程）。
- 领取侧「mtime < 2 秒跳过」（轮询逻辑在 `SyncBridge`）。
- 去抖间隔（`QTimer` 直接实现，抽不出可单测的纯函数）。
- 清单 `device` 字段往返（`FolderTransport::readManifest` 是私有方法）。

### 真机验收

1. 单机双实例：A 拖一个文件 → B 收件箱出现 + 托盘通知，耗时 < 5 秒。
2. 崩溃/超时路径：手动造一个 40 秒前的 `lock.json`，同步能接管而不是卡死。
3. 并发验收：A、B 同时改不同文件 → 两端都完成同步，`sync-trash` 为空。
4. UNC：本机开共享，两实例共享目录都填 `\\localhost\共享名`，跑通首次同步 + 拖拽。
5. 自动同步：改一个本地文件不点任何按钮，5 秒内对端文件更新。

## 6. 风险与权衡

| 风险 | 处置 |
|---|---|
| 锁文件跨机器时钟偏差 → 误判残留 | 用文件 `lastModified`（服务器时钟）而非锁内时间戳判定年龄 |
| 同步锁把两台机器串行化，慢网下等待变长 | 超时 5 秒后返回 `Busy` 让上层下一轮再试，不阻塞 UI |
| 3 秒轮询投递区在 UNC 上产生持续 SMB 流量 | 目录列表很轻；只 `entryInfoList` 一层，不递归 |
| watcher 递归注册超过 1000 个目录 | 超出记 warn，该根只用定时兜底，功能降级不影响正确性 |
| 删 `sync.db` 后重复领取投递区文件 | 已接收文件会再进一次收件箱（重名加序号），可接受；文档写明 |
| 收件箱重名加序号可能与已有文件撞名 | 序号递增到不存在为止 |
