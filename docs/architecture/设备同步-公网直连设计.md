# 设备同步 · 公网直连通道设计（IPv4 端口映射 / IPv6 直连）

> 状态：**设计稿** · 2026-11-05
> 范围：**只做直连**。不做中继服务器、不做 NAT 打洞（明确决策，见 §11）
> 替代关系：`FolderTransport`（共享目录）不再是主通道；`设备同步功能-设计文档.md` §4.4 的明文 ASYN v1 升级为本文的 ASYN v2 + TLS
> 技术前提：Qt 6.11（`QSslServer` 可用）、vcpkg OpenSSL、Win32 防火墙 / UAC

## 0. 结论先行

1. **拓扑**：单主机 Hub。一台设备监听并持有唯一“规范树”，其余设备连它；`SyncEngine` 的三方差集与冲突判定**一行不改**。
2. **传输**：TCP + **TLS**（1.2+，优先 1.3），默认端口 `45871`。明文只允许出现在 `127.0.0.1` 的协议单测里。
3. **可达性**：
   - **IPv6 优先**：主机有公网 GUA（`2000::/3`）即可直连，不需要映射。
   - **IPv4**：必须有公网 IP + 路由器端口映射；**CGNAT 环境不可用**，UI 必须明确告知，而不是让用户反复点“重试”。
4. **发现**：不做 mDNS/UDP 广播（公网场景没有意义），地址手动填 `host:port` / `[v6]:port` / 域名。
5. **安全**：自签证书 + 指纹固定 + 6 位配对码（SAS 比对）；服务端 `PathGuard`；认证失败限速。
6. **不做**：中继、STUN/TURN、UPnP 自动映射（列为后续）、对称 P2P 多主机。

## 1. 拓扑与角色

```
┌──────────────┐        TLS/TCP 45871        ┌───────────────────────────┐
│ 客户端 A      │ ──────────────────────────▶ │ 主机 SyncServer            │
│ NetTransport │                             │  ├ 共享根（规范树）         │
└──────────────┘                             │  ├ 会话 / 写锁              │
┌──────────────┐                             │  └ .assistant-sync/trash   │
│ 客户端 B      │ ──────────────────────────▶ │                            │
└──────────────┘                             └───────────────────────────┘
```

- **Host**：监听端口、认证对端、提供 `List / Get / Put / Delete / Lock` 五个原语。
- **Client**：`NetTransport` 实现现有 `ITransport`，驱动 `SyncEngine` 完成三方差集。
- **Host 自己也是同步节点**：它的 `SyncEngine` 直接扫共享根，`R` 就是自己的磁盘。
- 角色由配置 `sync.role = "host" | "client"` 决定，运行时可切换（切换会断开现有会话）。
- Host 必须常开；离线时客户端只能失败，不存在“另一台顶上”（那是多主机，见 §11）。

## 2. 地址与可达性

### 2.1 端口

- 默认 `45871`（沿用现有 `syncPort` 默认值），可在设置页改；**端口映射要求固定**，不建议随机。
- 监听：`QSslServer::listen(QHostAddress::Any, port)`。Windows 上 `Any` 通常是双栈（`IPV6_V6ONLY=0`），但**启动时要把实际绑定的地址族写进日志**；若只绑到 v6，再补一个 `AnyIPv4` 实例。
- 端口被占用：`listen` 失败 → 状态栏提示“端口 45871 被占用”，不自动换端口（换了映射就失效）。

### 2.2 IPv6 直连（首选）

| 项 | 要求 |
|---|---|
| 地址 | ISP 下发公网 GUA（`2000::/3`），`ipconfig` 可见 |
| NAT | 无，不需要映射 |
| 防火墙 | 入站放行 TCP 45871 |
| 地址稳定性 | IPv6 隐私扩展会轮换临时地址 → host 建议关闭临时地址（`netsh interface ipv6 set privacy state=disabled`），或用 DDNS 域名代替字面量 |
| 客户端填法 | `[2408:xxxx::1]:45871`（**必须带方括号**才能带端口） |

### 2.3 IPv4 + 端口映射

**前提**：WAN 侧是公网 IPv4，不是运营商 CGNAT。

配置步骤（写进 UI 帮助与用户手册）：

1. 给 host 固定内网 IP（路由器 DHCP 保留，或系统静态 IP）。
2. 路由器 → 端口映射/虚拟服务器 → `TCP 45871` → `host 内网 IP:45871`。
3. Windows 防火墙放行入站 TCP 45871（见 §9）。
4. 客户端填 `公网IP:45871` 或 `ddns.example.com:45871`。

**动态公网 IP**：用 DDNS（花生壳/Cloudflare 等）把域名指过来，或每次手改 `peerAddress`。`syncPeerAddress` 接受域名。

**CGNAT 判定**（程序无法 100% 自动识别，给用户三步法）：

| 检查 | 结论 |
|---|---|
| 路由器 WAN IP 落在 `100.64.0.0/10` | 基本确定是 CGNAT |
| 路由器 WAN IP ≠ 外网看到的 IP（在线查 IP 的网站/手机流量访问） | CGNAT 或多层 NAT |
| 手机用蜂窝网络 `Test-NetConnection <公网IP> -Port 45871` 超时 | 映射没生效或仍被 NAT 挡住 |

CGNAT 下**直连不可行**：要么找运营商要公网 IP / 改桥接，要么用 IPv6，要么换方案（中继，本设计明确不做）。UI 在这一步要给出明确结论，不要让用户无限重试。

**设计取舍**：不做 UPnP / NAT-PMP 自动映射——自动改路由器配置会引入安全面与兼容性问题，且不少路由器默认关闭。列为后续可选项。

### 2.4 地址解析

新增纯函数 `Sync::parsePeerAddress(QString, quint16 defaultPort) -> {host, port, ok, error}`：

| 输入 | 解析结果 |
|---|---|
| `1.2.3.4:45871` | v4 + 端口 |
| `[2001:db8::1]:45871` | v6 + 端口 |
| `[2001:db8::1]` | v6 + 默认端口 |
| `nas.local:45871` | 域名 + 端口 |
| `nas.local` | 域名 + 默认端口 |
| `2001:db8::1`（无方括号） | **拒绝**（有歧义，提示加方括号） |
| 空 / 超长 / 含控制字符 | 拒绝 |

### 2.5 自检面板（连接页顶部）

显示并复制：

- 角色、监听状态（地址族 / 端口 / 是否双栈）
- 本机地址列表（v4 / v6 分开，标出哪些是公网、哪些是私网）
- 共享根路径、证书指纹（前后各 8 位）
- 最近一次握手错误（`TLS_FAILED / AUTH_FAILED / CERT_MISMATCH / TIMEOUT`）
- 一键复制给对方的“连接串”：`[IPv6]:45871` 或 `IPv4:45871`

## 3. 协议 ASYN v2

### 3.1 帧格式

小端序，固定 16 字节头 + 变长载荷：

```
 0      4     5     6      8       12       16           16+len
 +------+-----+-----+------+-------+--------+------------------+
 | magic| ver | type| flags| reqId | len    | payload          |
 |"ASYN"|0x02 | u8  | u16  | u32   | u32    | JSON 或 裸字节    |
 +------+-----+-----+------+-------+--------+------------------+
```

- `len` 上限：控制帧 64 KiB，文件块 64 KiB；超过直接断连（防内存打爆）。
- `flags`：bit0 = JSON 载荷，bit1 = 文件块，bit2 = 最后一块。
- `reqId`：请求/响应配对；多路复用时可并发多个读请求。
- **半包/粘包**：接收端维护缓冲区，攒够 16 字节解析头、再攒够 `len` 解析体；长度非法立即 `Error + close`。

### 3.2 消息表

| type | 名称 | 方向 | 载荷 |
|---|---|---|---|
| 0x01 | Hello | C→S | `{deviceId, deviceName, protocolVer, clientNonce}` |
| 0x02 | Challenge | S→C | `{serverNonce, fingerprint, serverName}` |
| 0x03 | Auth | C→S | `{hmac}` |
| 0x04 | HelloAck | S→C | `{accepted, reason, capabilities}` |
| 0x10/0x11 | List / ListResp | C→S / S→C | `{}` / `{files:[{relPath,size,mtime,hash}]}` |
| 0x20/0x21/0x22 | Get / Chunk / End | C→S / S→C / S→C | `{relPath,offset}` / 裸字节 / `{hash}` |
| 0x30/0x31/0x32 | Put / PutChunk / PutAck | C→S | `{relPath,size,hash}` / 裸字节 / `{ok,hash}` |
| 0x40/0x41 | Delete / DeleteAck | C→S / S→C | `{relPath}` / `{ok}` |
| 0x50/0x51 | Lock / LockAck | C→S / S→C | `{}` / `{ok,holder}` |
| 0x60/0x61 | Ping / Pong | C→S / S→C | `{}` / `{serverTime}` |
| 0xFF | Error | 双向 | `{code,message,reqId}` |

认证前只接受 `Hello / Auth / Error`，其余消息一律 `AUTH_FAILED` 后断开。

### 3.3 分块、校验与续传

- **Get**：客户端带 `offset` 请求；服务端从该偏移发 64 KiB 块；客户端写 `dest.part`；收到 `End{hash}` 后算 SHA-256，一致才 `rename` 成正式文件，不一致删 `.part`。
- **续传**：连接断了，客户端从已写入字节数继续 `Get(offset)`；服务端无状态，天然支持。
- **Put**：客户端先发 `Put{relPath,size,hash}`，服务端建 `relPath.part`，逐块写入并累计；收满 `size` 后校验哈希，通过才 `rename`，失败删 `.part` 并回 `HASH_MISMATCH`。
- **Put 断线**：v1 不做跨连接续传（服务端删 `.part`），整文件重传；后续可加 `resumeToken`。
- 单文件上限暂定 **4 GiB**（`size` 用 u64）。

### 3.4 错误码

| code | 含义 |
|---|---|
| `AUTH_FAILED` | 配对密钥不对 / 未认证就发业务消息 |
| `CERT_MISMATCH` | 对端证书指纹与配对记录不符 |
| `BUSY` | 另一台设备持有写锁 |
| `NOT_FOUND` | `relPath` 不存在 |
| `PATH_REJECTED` | 越界/非法相对路径 |
| `DISK_FULL` | 服务端磁盘写失败 |
| `HASH_MISMATCH` | 文件校验失败 |
| `PROTOCOL` | 帧非法 / 状态不允许 |
| `TLS_FAILED` | 握手失败（版本/证书/算法） |
| `TIMEOUT` | 超时 |

### 3.5 超时与并发

| 项 | 值 |
|---|---|
| TLS 握手 | 5 s |
| Hello → Auth | 10 s |
| 空闲 | 30 s 断开 |
| 单块传输 | 30 s |
| 最大并发连接 | 8 |
| 写会话 | 全局 1 个（`Lock`），读可并发 |

## 4. 安全

### 4.1 身份

- `deviceId`：128 位随机数，首次启动生成，存配置。
- 密钥：ECDSA P-256；自签证书（`CN=deviceName`，SAN 含主机名），有效期 10 年，存 `%LOCALAPPDATA%/AssistantTeam/Assistant/identity/`。
- `fingerprint` = `SHA-256(DER)` 的十六进制小写。

### 4.2 配对（SAS）

1. Host 显示 6 位配对码（或二维码 `assistant://pair?host=...&fp=...&code=...`）。
2. Client 输入后计算：
   `pairSecret = HKDF-SHA256(ikm=code, salt=clientFP||serverFP, info="assistant-sync-pair")`
3. 双方屏幕显示 `SAS = SHA256(pairSecret)[0..6]`，用户比对一致才写入 `devices` 表。
4. 之后连接只认 `pairSecret` + 指纹，不再需要配对码。

> 中转/截图泄露配对码的风险由 SAS 比对兜底；v1 若嫌麻烦，至少要做“指纹确认框”。

### 4.3 认证

`Auth = HMAC-SHA256(pairSecret, clientNonce || serverNonce || deviceId)`。

- 失败计数按 IP：5 次 → 锁 60 s，之后指数退避（内存表，重启清空）。
- 认证失败只回 `AUTH_FAILED`，不回细节。

### 4.4 证书固定

`devices` 表存对端 `fingerprint`。握手中指纹不符 → `CERT_MISMATCH` 并断开，**不提供“仍然继续”**。

### 4.5 传输层

- `QSslSocket`，TLS 1.2+（优先 1.3），禁压缩。
- 证书校验走**固定指纹**，不依赖系统 CA（自签证书本来也过不了 CA）。
- 不做 TLS 会话票据持久化（每次全握手，v1 够用）。

### 4.6 服务端防护

- 所有 `relPath` 过 `PathGuard::resolveUnder(sharedRoot, relPath)`；拒绝绝对路径、`..`、保留名、符号链接穿越。
- 不向客户端暴露 `.assistant-sync/`（`List` 不列出，`Get/Put` 拒绝）。
- 单帧、单文件、文件名长度都设上限。
- 错误消息不回显完整本地路径。
- 建议（后续）：非默认端口、IP 白名单、失败告警。

## 5. 服务端实现（SyncServer）

### 5.1 类与职责

```cpp
// include/core/net/SyncServer.h
class SyncServer : public QObject {
    Q_OBJECT
public:
    bool start(quint16 port, const QString &sharedRoot, QString *error);
    void stop();
    bool isListening() const;
signals:
    void sessionStateChanged(const QString &peerName, const QString &state);
    void clientFinished(const QString &peerName, bool ok, const QString &message);
    void serverError(const QString &message);
};
```

内部：`QSslServer` + 每连接一个 `Session`（持有 socket、状态、缓冲区）。`Session` 不碰 `SyncEngine`。

### 5.2 会话状态机

```
TlsHandshake → HelloReceived → ChallengeSent → AuthVerified → Ready → Locked → Closing
```

| 状态 | 允许的消息 | 超时 |
|---|---|---|
| TlsHandshake | — | 5 s |
| HelloReceived | Auth | 10 s |
| Ready | List/Get/Put/Delete/Lock/Ping | 空闲 30 s |
| Locked | Get/Put/Delete/Unlock | 空闲 30 s |
| Closing | — | 3 s |

任何非法消息 → `Error{PROTOCOL}` → 正常关闭（先 `disconnectFromHost`，3 s 后 `abort`）。

### 5.3 共享根布局

```
<sharedRoot>/
├── 用户文件…
└── .assistant-sync/
    ├── trash/          # Delete 移到这里，不真删
    └── sessions.log    # 可选：最近 100 条会话摘要
```

`List` 的结果 = 共享根下除 `.assistant-sync/` 之外的全部普通文件（递归，跳过 junction / 符号链接，复用 `SyncEngine` 的扫描规则）。

### 5.4 线程模型

- `SyncServer` 跑在**自己的 QThread**（带事件循环）；所有 socket 在该线程。
- 文件读写在 `QThreadPool` 任务里做，结果回到 server 线程发送，避免大文件阻塞事件循环。
- 客户端 `NetTransport` 的 socket 在 `SyncBridge` 的同步工作线程内创建（Qt 要求 socket 与线程事件循环一致）。

### 5.5 启动与崩溃恢复

- 启动时清理 `.assistant-sync/` 下超过 24 h 的 `.part` 文件。
- `stop()`：停止监听 → 给所有会话发 `Error{SERVER_SHUTDOWN}` → 等 3 s → 强制断开。

## 6. 客户端（NetTransport）

```cpp
// include/core/net/NetTransport.h
class NetTransport : public ITransport {
public:
    NetTransport(const QString &peerAddress, quint16 port, const QByteArray &pairSecret,
                 const QString &expectedFingerprint, const QString &deviceId);
    bool probe() override;                     // 连接 + TLS + 认证 + Ping，3 s
    QList<RemoteFileInfo> listRemote() override;
    bool fetch(const QString &relPath, const QString &destPath) override;
    bool push(const QString &localPath, const QString &relPath) override;
    bool removeRemote(const QString &relPath) override;
    bool tryLock(int waitMs) override;
    void unlock() override;
    QString probeError() const;                // 失败原因（给 UI）
};
```

| `ITransport` | 协议 |
|---|---|
| `probe` | TLS + Hello/Challenge/Auth + Ping |
| `listRemote` | `List` |
| `fetch` | `Get(offset=0)` 循环，直到 `End` |
| `push` | `Put` + 连续 `PutChunk` |
| `removeRemote` | `Delete` |
| `tryLock` / `unlock` | `Lock` / `Unlock` |

- 一次同步复用一条连接；断开后重连 1 次，仍失败则本轮 `failed`。
- 所有失败的 `probeError()` 都要能落到 UI（当前 `probe()` 只返回 bool，这是已知缺口）。

## 9. 部署与自检（用户视角）

### IPv6

```powershell
ipconfig            # 找 2000::/3 的地址
Test-NetConnection -ComputerName 2408:xxxx::1 -Port 45871
```

### IPv4 端口映射

1. 路由器 → 端口映射 → `TCP 45871` → host 内网 IP。
2. 确认 WAN IP 不是 `100.64/10`，且与“查 IP”网站一致。
3. 手机流量 `Test-NetConnection 公网IP -Port 45871`。

### 防火墙

```powershell
# 管理员
netsh advfirewall firewall add rule name="Assistant Sync" dir=in action=allow protocol=TCP localport=45871
```

首次监听时 Windows 也会弹授权框；两者取其一。

### 端到端验证

手机开热点（关 Wi-Fi）→ 客户端填 host 的 IPv6 或公网 IPv4 → 能完成握手并 `List` 即公网可达。

## 10. 里程碑与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| **N0** | 协议编解码：帧、半包/粘包、畸形帧、大小上限；`parsePeerAddress` | 单测全绿；随机切片能还原帧 |
| **N1** | 回环 TLS：`SyncServer` + `NetTransport` 同进程、临时目录 | `List/Get/Put/Delete/Lock` 全通；`../` 被拒；错哈希丢弃 `.part` |
| **N2** | 配对与固定：6 位码、SAS、指纹存储 | 错码/错指纹被拒；Wireshark 看不到明文；5 次失败锁定 |
| **N3** | 两台真机局域网 | 500 MB 文件中断后从 offset 续传；GUI 不卡 |
| **N4** | 公网直连 | ① IPv6：手机流量连家里主机成功；② IPv4：端口映射后成功；③ CGNAT 环境明确提示“不可用” |
| **N5** | 移除默认共享目录通道 | 配置里不再出现共享目录；`FolderTransport` 仅测试保留 |

N4 是唯一依赖真实网络环境的阶段，必须用**手机蜂窝网络**做客户端侧验证，不能只在本机回环。

## 11. 风险与非目标

### 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| CGNAT 用户无法直连 | 相当一部分家庭宽带不可用 | UI 明确判定与提示；文档写清；不做中继是已定决策 |
| 公网端口暴露 | 扫描、爆破 | TLS + 指纹固定 + 失败限速；建议非默认端口 |
| 动态公网 IP / IPv6 前缀变化 | 客户端连旧地址失败 | DDNS 或手改；错误提示区分“超时/拒绝” |
| Windows 防火墙 / UAC | 监听无入站 | 首次启动提权加规则（复用 `Os::runElevated` 方案） |
| Qt OpenSSL 部署 | `QSslSocket` 不可用，N2 卡死 | 先写 `QSslSocket::supportsSsl()` 自检并在启动日志打印 |
| 主机常开 | 主机离线即不可同步 | 明确产品语义；多主机列为后续 |

### 非目标

中继服务器、STUN/TURN、UDP 打洞、UPnP/NAT-PMP 自动映射、对称 P2P、多主机、传输层之外的元数据保护。

## 12. 开放问题

1. 是否提供“一键防火墙规则”（需提权，与 qianju 的 `Os::runElevated` 计划合并）。
2. 配对是否上二维码（`assistant://pair?...`）。
3. 端口被占用时是否允许自动改端口并同步修改映射提示（当前决定：不自动改）。
4. 是否把 `devices` 表扩展成“多主机列表”（为将来对称 P2P 留口）。
