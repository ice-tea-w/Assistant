# 设备同步 · 公网直连通道设计（IPv4 端口映射 / IPv6 直连）

> 状态：**设计稿** · 2026-11-05（补 §13 缺口清单：按现有代码逐条核对后修订）
> 范围：**只做直连**。不做中继服务器、不做 NAT 打洞（明确决策，见 §11）
> 替代关系：`FolderTransport`（共享目录）不再是主通道；`设备同步功能-设计文档.md` §4.4 的明文 ASYN v1 升级为本文的 ASYN v2 + TLS
> 技术前提：Qt 6.11.2（`QSslServer` 可用）、**Windows Schannel TLS 后端**、Win32 防火墙 / UAC。
> TLS 后端已实测：`QSslSocket::supportsSsl()` 为真，后端 `schannel`（版本 `Secure Channel`），可用后端 `cert-only, schannel`；
> **不需要 OpenSSL，也不需要重编 qtbase**。代价是打包必须带上 `Qt6/plugins/tls/qschannelbackend.dll`（见 §13 打包项）。

## 0. 结论先行

1. **拓扑**：单主机 Hub。一台设备监听并持有唯一“规范树”，其余设备连它；`SyncEngine` 的三方差集与冲突判定**一行不改**。
2. **传输**：TCP + **TLS**（1.2+，优先 1.3），默认端口 `45871`。明文只允许出现在 `127.0.0.1` 的协议单测里。
3. **可达性**：
   - **IPv6 优先**：主机有公网 GUA（`2000::/3`）即可直连，不需要映射。
   - **IPv4**：必须有公网 IP + 路由器端口映射；**CGNAT 环境不可用**，UI 必须明确告知，而不是让用户反复点“重试”。
4. **发现**：不做 mDNS/UDP 广播（公网场景没有意义），地址手动填 `host:port` / `[v6]:port` / 域名。
5. **安全**：自签证书 + **双向 mTLS** + 双向指纹固定；首配用 6 位配对码（一次性、短 TTL、host 主动开窗口、SAS 比对），配完即丢弃，不做长期 HMAC。服务端 `PathGuard`；认证失败限速。
6. **并发语义**：**全局串行**，一次只有一条连接在做同步。不做"读可并发"——`SyncEngine::sync()` 在入口 `tryLock`、出口 `unlock`，整个 List+Get+Put 都在锁内（`SyncEngine.cpp:245-255`），读也被串行化。
7. **清单必须分页**：控制帧上限 64 KiB 装不下全树清单。`List/ListResp` 带 `cursor` / `hasMore`，由 `NetTransport` 内部翻页，`ITransport::listRemote()` 的返回值不变。
8. **不做**：中继、STUN/TURN、UPnP 自动映射（列为后续）、对称 P2P 多主机。

## 1. 拓扑与角色

```
┌──────────────┐        TLS/TCP 45871        ┌───────────────────────────┐
│ 客户端 A      │ ──────────────────────────▶ │ 主机 SyncServer            │
│ NetTransport │                             │  ├ 共享根（规范树）         │
└──────────────┘                             │  ├ 会话 / 写锁              │
┌──────────────┐                             │  └ .assistant-sync/trash   │
│ 客户端 B      │ ──────────────────────────▶ │                            │
└──────────────┘                             └───────────────────────────┘
```

- **Host**：监听端口、认证对端、提供 `List / Get / Put / Delete / Lock / Unlock` 六个原语。
- **Client**：`NetTransport` 实现现有 `ITransport`，驱动 `SyncEngine` 完成三方差集。
- **Host 自己也是同步节点**，但它**不能**把共享根直接当成自己的本地根：引擎里 `relPath` 一律带别名前缀（`SyncEngine.cpp:152-154`），而 `SyncEngine.cpp:316-318` 会把「没有别名前缀」或「别名对不上本机根」的路径直接 `continue`。host 若以 `<sharedRoot>` 为本地根，它的 `L` 是 `a.txt`、客户端的 `R` 是 `别名/a.txt`，两边永远碰不上。
  因此采用**对称拓扑（方案 A）**：host 的本地根是一个普通目录，另加 `LocalDirTransport`（`listRemote()` 扫共享根，`fetch/push/removeRemote` 即本地复制/移除），host 与客户端走同一套 `L / S / R`，`SyncEngine` 一行不改。代价是多一份拷贝与磁盘占用；省空间的方案（host 本地根就落在 `<sharedRoot>/<别名>`、不做拷贝）会让"文件夹到底在哪"说不清，不采用。
- **别名对齐是硬约束**：两端同一个逻辑文件夹必须用同一别名，否则各占一棵子树、永远碰不上。
- 角色由配置 `sync.role = "host" | "client"` 决定。切换角色 = **强制断开所有会话、释放锁、重启监听**，不是热切换。
- Host 必须常开；离线时客户端只能失败，不存在“另一台顶上”（那是多主机，见 §11）。

## 2. 地址与可达性

### 2.1 端口

- 默认 `45871`（沿用现有 `syncPort` 默认值），可在设置页改；**端口映射要求固定**，不建议随机。
- 监听：`QSslServer::listen(QHostAddress::Any, port)`。Windows 上 `Any` 通常是双栈（`IPV6_V6ONLY=0`），但**启动时要把实际绑定的地址族写进日志**；若只绑到 v6，再补一个 `AnyIPv4` 实例。
- 端口被占用：`listen` 失败 → 状态栏提示“端口 45871 被占用”，不自动换端口（换了映射就失效）。

### 2.2 IPv6 直连（首选）

| 项 | 要求 |
|---|---|
| 地址 | ISP 下发公网 GUA（`2000::/3`），`ipconfig` 可见 |
| NAT | 无，不需要映射 |
| 防火墙 | 入站放行 TCP 45871 |
| 地址稳定性 | IPv6 隐私扩展会轮换临时地址 → host 关闭临时地址：`Set-NetIPv6Protocol -UseTemporaryAddresses Disabled`（PowerShell 语义明确；`netsh interface ipv6 set privacy state=disabled` 在 Win11 上行为不完全可控），或用 DDNS 域名代替字面量 |
| 客户端填法 | `[2408:xxxx::1]:45871`（**必须带方括号**才能带端口） |

### 2.3 IPv4 + 端口映射

**前提**：WAN 侧是公网 IPv4，不是运营商 CGNAT。

配置步骤（写进 UI 帮助与用户手册）：

1. 给 host 固定内网 IP（路由器 DHCP 保留，或系统静态 IP）。
2. 路由器 → 端口映射/虚拟服务器 → `TCP 45871` → `host 内网 IP:45871`。
3. Windows 防火墙放行入站 TCP 45871（见 §9）。
4. 客户端填 `公网IP:45871` 或 `ddns.example.com:45871`。

**动态公网 IP**：用 DDNS（花生壳/Cloudflare 等）把域名指过来，或每次手改 `peerAddress`。`syncPeerAddress` 接受域名。

**CGNAT 判定**（程序无法 100% 自动识别，给用户三步法）：

| 检查 | 结论 |
|---|---|
| 路由器 WAN IP 落在 `100.64.0.0/10` | 基本确定是 CGNAT |
| 路由器 WAN IP ≠ 外网看到的 IP（在线查 IP 的网站/手机流量访问） | CGNAT 或多层 NAT |
| 手机用蜂窝网络 `Test-NetConnection <公网IP> -Port 45871` 超时 | 映射没生效或仍被 NAT 挡住 |
| 有公网 IPv6 GUA、但没有公网 IPv4 | 家宽当下最常见的组合；走 §2.2 的 IPv6 直连，不必折腾映射 |

CGNAT 下**直连不可行**：要么找运营商要公网 IP / 改桥接，要么用 IPv6，要么换方案（中继，本设计明确不做）。UI 在这一步要给出明确结论，不要让用户无限重试。

**设计取舍**：不做 UPnP / NAT-PMP 自动映射——自动改路由器配置会引入安全面与兼容性问题，且不少路由器默认关闭。列为后续可选项。

### 2.4 地址解析

新增纯函数 `Sync::parsePeerAddress(QString, quint16 defaultPort) -> {host, port, ok, error}`：

| 输入 | 解析结果 |
|---|---|
| `1.2.3.4:45871` | v4 + 端口 |
| `[2001:db8::1]:45871` | v6 + 端口 |
| `[2001:db8::1]` | v6 + 默认端口 |
| `nas.local:45871` | 域名 + 端口 |
| `nas.local` | 域名 + 默认端口 |
| `2001:db8::1`（无方括号） | **拒绝**（有歧义，提示加方括号） |
| 空 / 超长 / 含控制字符 | 拒绝 |

### 2.5 自检面板（连接页顶部）

显示并复制：

- 角色、监听状态（地址族 / 端口 / 是否双栈）
- 本机地址列表（v4 / v6 分开，标出哪些是公网、哪些是私网）
- 共享根路径、证书指纹（前后各 8 位）
- 最近一次握手错误（`TLS_FAILED / AUTH_FAILED / CERT_MISMATCH / TIMEOUT`）
- 一键复制给对方的“连接串”：`[IPv6]:45871` 或 `IPv4:45871`

## 3. 协议 ASYN v2

### 3.1 帧格式

小端序，固定 16 字节头 + 变长载荷：

```
 0      4     5     6      8       12       16           16+len
 +------+-----+-----+------+-------+--------+------------------+
 | magic| ver | type| flags| reqId | len    | payload          |
 |"ASYN"|0x02 | u8  | u16  | u32   | u32    | JSON 或 裸字节    |
 +------+-----+-----+------+-------+--------+------------------+
```

- `len` 上限：控制帧 64 KiB，文件块 64 KiB；超过直接断连（防内存打爆）。
- **控制帧 64 KiB 是硬约束**：`List` 的全树清单一定会超（每条 `{relPath,size,mtime,hash}` 约 150 B，几百个文件就顶到上限）。所以 `List/ListResp` 必须分页（见 §3.2），**不接受"一次返回全树"**。
- `flags`：bit0 = JSON 载荷，bit1 = 文件块，bit2 = 最后一块。
- `reqId`：请求/响应配对。**v1 每条连接串行**（一请求一响应），`reqId` 只保留字段、不用于多路复用；并发默认禁止（理由见 §3.5）。
- **半包/粘包**：接收端维护缓冲区，攒够 16 字节解析头、再攒够 `len` 解析体；长度非法立即 `Error + close`。

### 3.2 消息表

| type | 名称 | 方向 | 载荷 |
|---|---|---|---|
| 0x01 | Hello | C→S | `{deviceId, deviceName, protocolVer}`（客户端证书在 TLS 层已验，这里只做身份对齐） |
| 0x02 | Challenge | — | **v2 不使用**（号段保留，HMAC 认证方案已废弃，见 §4.3） |
| 0x03 | Auth | — | **v2 不使用**（同上） |
| 0x04 | HelloAck | S→C | `{accepted, reason, capabilities, serverFingerprint}` |
| 0x10/0x11 | List / ListResp | C→S / S→C | `{cursor,limit}` / `{files:[…],nextCursor,hasMore}`，files 每项 `{relPath,size,mtime,hash}` |
| 0x20/0x21/0x22 | Get / Chunk / End | C→S / S→C / S→C | `{relPath,offset}` / 裸字节 / `{hash}` |
| 0x30/0x31/0x32 | Put / PutChunk / PutAck | C→S / C→S / **S→C** | `{relPath,size,hash}` / 裸字节 / `{ok,hash}`（**整文件收完才发一次**，不是每块一 ack） |
| 0x40/0x41 | Delete / DeleteAck | C→S / S→C | `{relPath}` / `{ok}` |
| 0x50/0x51 | Lock / LockAck | C→S / S→C | `{}` / `{ok,holder}` |
| 0x52/0x53 | Unlock / UnlockAck | C→S / S→C | `{}` / `{ok}` |
| 0x60/0x61 | Ping / Pong | C→S / S→C | `{}` / `{serverTime}` |
| 0xFF | Error | 双向 | `{code,message,reqId}` |

TLS 握手完成即视为传输层身份已验（客户端证书 + 双向指纹固定，见 §4.3）。业务层在收到 `Hello` 之前不接受任何消息；状态机不匹配的消息一律 `Error{PROTOCOL}` 后断开。

### 3.3 分块、校验与续传

- **`.part` 命名固定**：`<目标路径>.assistant-part`。它和正式文件同目录，但**不占用正式文件名**。
- **与 `ITransport.h:22` 契约的关系（必须先讲清）**：契约要求「`fetch`/`push` 失败不得留下不完整的落盘文件」。这里的解释是 —— 正式目标路径（`destPath` / `relPath`）**永远只出现完整文件**；`.assistant-part` 是内部临时文件，失败时允许留在磁盘上供续传，但：(a) 正常收尾（成功或最终放弃）由 `NetTransport` / `SyncServer` 删除；(b) 超过 24 h 的残留由启动时清理（§5.5）；(c) 不得被 `List` 列出，也不得被当成同名文件参与三方差集。
- **Get**：客户端带 `offset` 请求；服务端从该偏移发 64 KiB 块；客户端写 `.assistant-part`；收到 `End{hash}` 后算 SHA-256，一致才 `rename` 成正式文件，不一致删临时文件。
- **Get 途中源文件被改**：服务端以打开时的 `size + mtime` 作为快照，传输中发现 `mtime` 变化 → 回 `Error{SOURCE_CHANGED}`，客户端丢弃本次结果、下一轮重来（不拼半个文件再校验失败）。
- **续传**：连接断了，客户端从已写入字节数继续 `Get(offset)`；服务端无状态，天然支持。
- **Put**：客户端先发 `Put{relPath,size,hash}`，服务端建 `.assistant-part`，逐块写入并累计；收满 `size` 后校验哈希，通过才 `rename`，失败删临时文件并回 `HASH_MISMATCH`。
- **Put 断线**：v1 不做跨连接续传（服务端删临时文件），整文件重传；后续可加 `resumeToken`。
- **背压（必经实现，不是优化）**：PutAck 只在整文件收完发一次，若服务端磁盘慢、客户端发得快，数据会在内存里堆积。服务端必须限制入站队列（例如未落盘块数 > 4 就暂停读取 / 收紧 `setReadBufferSize`），客户端在写入阻塞时停止发块。缺了这条，快网 + 慢盘会把内存吃穿。
- 单文件上限暂定 **4 GiB**（`size` 用 u64）。

### 3.4 错误码

| code | 含义 |
|---|---|
| `AUTH_FAILED` | 配对密钥不对 / 未认证就发业务消息 |
| `CERT_MISMATCH` | 对端证书指纹与配对记录不符 |
| `BUSY` | 另一台设备持有写锁 |
| `NOT_FOUND` | `relPath` 不存在 |
| `PATH_REJECTED` | 越界/非法相对路径 |
| `DISK_FULL` | 服务端磁盘写失败 |
| `HASH_MISMATCH` | 文件校验失败 |
| `SOURCE_CHANGED` | Get 途中源文件 mtime 变了，本次作废 |
| `PROTOCOL` | 帧非法 / 状态不允许 |
| `TLS_FAILED` | 握手失败（版本/证书/算法） |
| `TIMEOUT` | 超时 |

### 3.5 超时与并发

| 项 | 值 |
|---|---|
| TLS 握手 | 5 s |
| Hello → Auth | 10 s |
| 空闲 | 30 s 断开 |
| 单块传输 | 30 s |
| 最大并发连接 | 8（实际常态只有 1 条在同步，其余是重连残留） |
| 写会话 | 全局 1 个（`Lock`） |
| 读 | **不并发**，和写一样串行 —— 与 `SyncEngine` 的全局锁一致（§0 第 6 条） |
| 锁 TTL | 会话断开即释放；空闲 30 s 心跳超时视同断开并释放，不靠客户端主动 `Unlock` |

## 4. 安全

### 4.1 身份

- `deviceId`：128 位随机数，首次启动生成，存配置。
- **`deviceId` 必须绑定证书**：`devices` 表存 `(deviceId, fingerprint)` 二元组，每次握手都要求 `Hello.deviceId` 与「该证书指纹对应的 deviceId」一致，防止"借一张合法证书冒充另一台设备"。
- 密钥：ECDSA P-256；自签证书（`CN=deviceName`，SAN 含主机名），有效期 10 年，存 `%LOCALAPPDATA%/AssistantTeam/Assistant/identity/`。
- `fingerprint` = `SHA-256(DER)` 的十六进制小写。

### 4.2 配对（SAS）

1. Host 在设置页点「允许新设备配对」，**打开一个 5 分钟窗口**（关掉窗口就不再接受任何新证书）。
2. Host 显示 6 位配对码（或二维码 `assistant://pair?host=...&port=...&fp=...`）。
3. Client 输入配对码 → 双方各自算 `SAS = SHA256(clientFP ‖ serverFP ‖ code)[0..6]` 并显示，用户逐位比对。
4. 比对一致后，才把对端 `fingerprint + deviceId` 写进 `devices` 表。
5. **配对码一次性**：配对成功即作废；窗口内错 3 次 → 窗口关闭、冷却 60 s；`code` 不进任何持久化存储。

> SAS 兜的是"首次配对时的中间人"，挡不住"码被人看见、攻击者自己来连" —— 所以配对码必须一次性 + 限定在时间窗内，且窗口只在 host 主动开启时存在。
> 配对完成后**不保留长期共享密钥**：身份由 mTLS 证书 + 双向指纹固定承担（§4.3），`pairSecret` 这个概念整体删除。

### 4.3 认证

**双向 mTLS**：客户端与服务端都出示自签证书，双方都用「固定指纹」校验对端（§4.4）。删掉 HMAC、`Auth` 消息和 `pair_secret`：

- 原来的弱点是"服务端认客户端"——只有 HMAC，而 HMAC 的强度就是 6 位码的 `10^6`。换成客户端证书后，强度等于 ECDSA P-256。
- 服务端先按客户端证书指纹查 `devices`：未登记 → `AUTH_FAILED`（不进入业务状态机）；已登记 → 再核对 `Hello.deviceId` 与记录一致。
- 失败计数按 IP：5 次 → 锁 60 s，之后指数退避（内存表，重启清空）。
- 失败只回 `AUTH_FAILED` / `CERT_MISMATCH`，不回细节。
- 删掉 HMAC 之后，「`pair_secret` 用 DPAPI 加密存 `sync.db`」这条需求也就不存在了 —— 少一个安全面。

> 首配仍必须保留 SAS 比对：它是第一次见面对抗中间人的**唯一**手段，mTLS 本身不能证明"对面是我说的那台机器"。

### 4.4 证书固定

`devices` 表存对端 `(device_id, fingerprint, name, last_seen, last_error)`。握手时：

- 必须用 `QSslSocket::peerVerifyMode(QueryPeer)`。**不能用 `VerifyPeer`** —— 自签证书链一定验不过，`VerifyPeer` 会让握手直接失败。
- 握手后自己比对 `peerCertificate().digest(QCryptographicHash::Sha256)` 与 `devices` 里的指纹；不符 → `CERT_MISMATCH` 并断开，**不提供"仍然继续"**。
- 首次见面（`devices` 里没有该指纹）只在「配对窗口开启」时接受，否则一律拒绝。

### 4.5 传输层

- `QSslSocket`，TLS 1.2+（优先 1.3），禁压缩。
- 证书校验走**固定指纹**（`QueryPeer` + 手工比对 `peerCertificate()`），不依赖系统 CA（自签证书本来也过不了 CA）。
- 不做 TLS 会话票据持久化（每次全握手，v1 够用）。

### 4.6 服务端防护

- 所有 `relPath` 过 `PathGuard::resolveUnder(sharedRoot, relPath)`；拒绝绝对路径、`..`、保留名、符号链接穿越。
- 不向客户端暴露 `.assistant-sync/`（`List` 不列出，`Get/Put` 拒绝）。
- 单帧、单文件、文件名长度都设上限。
- 错误消息不回显完整本地路径。
- 建议（后续）：非默认端口、IP 白名单、失败告警。

## 5. 服务端实现（SyncServer）

### 5.1 类与职责

```cpp
// include/core/net/SyncServer.h
class SyncServer : public QObject {
    Q_OBJECT
public:
    bool start(quint16 port, const QString &sharedRoot, QString *error);
    void stop();
    bool isListening() const;
signals:
    void sessionStateChanged(const QString &peerName, const QString &state);
    void clientFinished(const QString &peerName, bool ok, const QString &message);
    void serverError(const QString &message);
};
```

内部：`QSslServer` + 每连接一个 `Session`（持有 socket、状态、缓冲区）。`Session` 不碰 `SyncEngine`。

### 5.2 会话状态机

```
TlsHandshake → PeerVerified（证书指纹已在 devices 里）→ Ready → Locked → Closing
```

| 状态 | 允许的消息 | 超时 |
|---|---|---|
| TlsHandshake | — | 5 s |
| PeerVerified | `Hello` | 10 s |
| Ready | List/Get/Put/Delete/Lock/Ping | 空闲 30 s |
| Locked | Get/Put/Delete/Unlock/Ping | 空闲 30 s |
| Closing | — | 3 s |

任何非法消息 → `Error{PROTOCOL}` → 正常关闭（先 `disconnectFromHost`，3 s 后 `abort`）。

### 5.3 共享根布局

```
<sharedRoot>/
├── 用户文件…
└── .assistant-sync/
    ├── index.json      # 清单索引：relPath → size+mtime+hash，避免每次 List 全树重算
    ├── trash/          # Delete 移到这里，不真删
    └── sessions.log    # 可选：最近 100 条会话摘要
```

- `List` 的结果 = 共享根下除 `.assistant-sync/` 之外的全部普通文件（递归，跳过 junction / 符号链接）。**扫描规则必须与 `SyncEngine` 共用同一份实现**：把 `SyncEngine.cpp:57-89` 的 `scanDirInto`（只跳 `.sync` 与 junction/symlink）从匿名 namespace 提出来做共享 helper。**不要复用 `FileScanner` 的剪枝名单** —— 那是文件索引的剪枝（`node_modules`/`.git` 等，`FileScanner.cpp:157-160`），照搬会把用户目录直接剪掉，不是"顺手优化"。
- **清单索引**：`index.json` 以 `relPath` 为键，记 `size + mtime + hash`；`List` 只读索引，`size`/`mtime` 未变的文件不重算哈希，新增或变化只重算那一条。`Get` 前复核一次 `mtime`（对应 §3.3 的 `SOURCE_CHANGED`）。
  - 索引丢失或损坏 → 退回全量扫描并重建（`FolderTransport` 的 `.sync/manifest.json` 就是这种缓存，`FolderTransport.h:60-62`）。直连版必须自己补这份缓存，否则每次 `List` 都在算全树 SHA-256，而 `SyncEngine` 还有 CAS 二次 `List`（`SyncEngine.cpp:331-348`），代价直接翻倍。
- **trash 保留策略**：保留 7 天，或总量超过 1 GiB 时按最旧优先清理；默认不自动清空（误删还能捞回来）。

### 5.4 线程模型

- `SyncServer` 跑在**自己的 QThread**（**必须 `exec()`**，否则 `newConnection` / `readyRead` 永远不派发）；所有 socket 在该线程。
- 文件读写在 `QThreadPool` 任务里做，结果回到 server 线程发送，避免大文件阻塞事件循环（`QFile` 句柄留在使用它的线程里）。
- **客户端是同步阻塞模型**：`SyncBridge` 现在是 `QThread::create` 跑一个阻塞 lambda 直接调 `engine.sync()`（`src/ui/SyncBridge.cpp:494-519`），**那个线程没有事件循环**。所以 `NetTransport` 内部不能依赖 `connected` / `encrypted` / `readyRead` 信号，必须用 `waitForConnected()` / `waitForEncrypted()` / `waitForBytesWritten()` / `waitForReadyRead()` 这套阻塞 API —— 与 `ITransport` 的同步返回值天然吻合。
  - 将来若要改成信号驱动，必须给工作线程加局部 `QEventLoop`；v1 不这么做，两条路不要混着写。

### 5.5 启动与崩溃恢复

- 启动时清理共享根各目录下超过 24 h 的 `*.assistant-part`（§3.3 的临时文件），并校验/重建 `index.json`。
- `stop()`：停止监听 → 给所有会话发 `Error{SERVER_SHUTDOWN}` → 等 3 s → 强制断开。

## 6. 客户端（NetTransport）

```cpp
// include/core/net/NetTransport.h
class NetTransport : public ITransport {
public:
    NetTransport(const QString &peerAddress, quint16 port,
                 const QSslCertificate &clientCert, const QSslKey &clientKey,
                 const QByteArray &expectedFingerprint, const QString &deviceId);
    bool probe() override;                     // 连接 + TLS + 认证 + Ping，3 s
    QList<RemoteFileInfo> listRemote() override;
    bool fetch(const QString &relPath, const QString &destPath) override;
    bool push(const QString &localPath, const QString &relPath) override;
    bool removeRemote(const QString &relPath) override;
    bool tryLock(int waitMs) override;
    void unlock() override;
    QString probeError() const;                // 失败原因（给 UI）
};
```

| `ITransport` | 协议 |
|---|---|
| `probe` | TCP + TLS 握手 + 指纹比对 + `Hello`/`HelloAck` + `Ping` |
| `listRemote` | `List` |
| `fetch` | `Get(offset=0)` 循环，直到 `End` |
| `push` | `Put` + 连续 `PutChunk` |
| `removeRemote` | `Delete` |
| `tryLock` / `unlock` | `Lock` / `Unlock` |

- `listRemote()` 内部翻页：按 `limit=200` 循环 `List{cursor}` 直到 `hasMore == false`，拼成完整 `QList<RemoteFileInfo>` 返回，对 `SyncEngine` 完全透明。
- `tryLock()` 变成**几乎恒真**：`SyncEngine` 已经在入口用全局锁保证同一时刻只有一个同步在跑（`SyncEngine.cpp:245-255`），直连侧再锁一次没有收益，只有代价（多一条连接、多一次往返、多一个死锁面）。v1 让 `tryLock()` 直接返回 `true`、`unlock()` 空实现，并在注释里写明"串行性由引擎保证；协议层的 `Lock` 留给将来多客户端"。
- 一次同步复用一条连接；断开后重连 1 次，仍失败则本轮 `failed`。
- 所有失败的 `probeError()` 都要能落到 UI（`FolderTransport` 已有这套形状，`NetTransport` 照抄）。

## 11. 风险与非目标

### 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| CGNAT 用户无法直连 | 相当一部分家庭宽带不可用 | UI 明确判定与提示；文档写清；不做中继是已定决策 |
| 公网端口暴露 | 扫描、爆破 | TLS + 指纹固定 + 失败限速；建议非默认端口 |
| 动态公网 IP / IPv6 前缀变化 | 客户端连旧地址失败 | DDNS 或手改；错误提示区分“超时/拒绝” |
| Windows 防火墙 / UAC | 监听无入站 | 提供"一键防火墙规则"（提权，复用 `Os::runElevated`，与 qianju 上的现成实现同一套）+ 首次监听时 Windows 自身的授权框 |
| TLS 后端缺失（打包） | `QSslSocket` 不可用，N1/N2 直接卡死 | 本机已实测 Schannel 可用、**不需要 OpenSSL**；但打包必须带 `Qt6/plugins/tls/qschannelbackend.dll`。启动时打印 `supportsSsl()` / `activeBackend()` / 版本，缺失就报错，不静默降级 |
| 主机常开 | 主机离线即不可同步 | 明确产品语义；多主机列为后续 |

### 非目标

中继服务器、STUN/TURN、UDP 打洞、UPnP/NAT-PMP 自动映射、对称 P2P、多主机、传输层之外的元数据保护。

## 13. 按现有代码核对出的缺口（实施前置条件）

> 这一节是评审结论，不是新设计。**N1 开工前必须先定 §13.1 的四条**，否则协议写完了照样会被现有代码的结构挡住。

### 13.1 真 P0（N1 前必须定）

| # | 缺口 | 为什么是 P0 | 决定 |
|---|---|---|---|
| 1 | **线程模型**：`SyncBridge` 的工作线程没有事件循环（`src/ui/SyncBridge.cpp:494-519`） | `QSslSocket` 的信号在阻塞线程里永远不派发，握手完就卡死 | `NetTransport` 全程用 `waitFor*()` 阻塞 API（§5.4） |
| 2 | **List 撞 64 KiB 帧上限**（§3.1/§3.2） | 几百个文件就超，接收端按"长度非法"断连 | `List` 分页 `cursor/limit`，`NetTransport` 内部翻页 |
| 3 | **List 全树重算 SHA-256** | 每次同步算两遍全树（`SyncEngine.cpp:331-348` 还有 CAS 二次 List），目录一大就不可用 | `.assistant-sync/index.json`（`size+mtime` 失效），§5.3 |
| 4 | **锁语义**：`SyncEngine.cpp:245-255` 的全局 `tryLock` 包住整个同步 | 原文档写"读可并发"，与代码直接矛盾 | 改成全局串行；`NetTransport::tryLock()` 恒真（§6） |

### 13.2 P1（N2–N4 之间补，但要有明确归属）

| # | 缺口 | 处理 |
|---|---|---|
| 1 | 投递区在直连模式下退化成"本地队列" | §13.3 |
| 2 | `ITransport.h:22` 契约与 `.part` 续传冲突 | §3.3 已写清：正式路径只出现完整文件 |
| 3 | `scanDirInto` 不可直接复用（`FileScanner` 的剪枝方向相反） | 提成共享 helper（§5.3、§7） |
| 4 | Get 途中源文件被改 | `SOURCE_CHANGED`（§3.3） |
| 5 | trash 无保留策略 | 7 天 / 1 GiB（§5.3） |
| 6 | 双版本字段（帧头 `ver` 与 `Hello.protocolVer`） | 两个都留，但分工固定：帧头管字节布局，`protocolVer` 管能力协商 |
| 7 | `reqId` 并发语义未定义 | v1 串行，字段留给将来（§3.1） |

### 13.3 投递区（需要产品决定）

现状是「拖进同步页 → 落到共享目录 `_投递/` → 对端每 3 秒轮询领取」。直连之后**这个"信箱"没了**：

- 对端离线时文件无处可放 → 必须有本地 outbox（持久化，重启不丢）。
- 接收方要有归属：落到 `_delivery/<recipient>/`，`List` 只返回自己的目录，领取即 `Delete`（进 trash）。
- 保留策略：未领取的保留 7 天，之后进 trash。
- 表结构补"已发送未确认"状态，启动与重连时扫一遍补发。

**这一条不补，直连版会比共享目录版更弱**（共享目录至少能在对端离线时先把文件放进去）。建议排在 N5 之前。

### 13.4 打包与部署清单（不是设计风险，是清单）

- TLS 走 Schannel：打包必须包含 `Qt6/plugins/tls/qschannelbackend.dll`（连 `qcertonlybackend.dll` 一起）。
- 启动日志打印 `supportsSsl()` / `activeBackend()` / `sslLibraryVersionString()`；缺失时明确报错，不静默退化成明文。
- 私钥目录 `%LOCALAPPDATA%/AssistantTeam/Assistant/identity/` 首次生成，失败要能给出可读原因（别只留一个 `QSslKey::isNull()`）。

### 13.5 本机实测环境（N4 的现实基线）

- WLAN 只有链路本地 IPv6（`fe80::`），**没有公网 GUA**；WLAN IPv4 是 `10.252.103.167`（私网段）。
- 已装并在跑 Tailscale（`100.116.234.107`，Windows 服务 Running）→ 跨网段验证优先用它，不必等公网 IPv6。
- 已有共享 `SyncHub → E:\SyncHub`（旧通道仍在）。
- 当前 shell 非管理员 → 监听、防火墙、`net share` 都要 UAC，只能人工点。
- `Test-Path '\\[::1]\SyncHub'` 会报 "path's format is not supported"（PowerShell 路径提供程序不认方括号），验证 IPv6 UNC 要用 `cmd /c dir` 或程序自身。

### 13.6 落地顺序

N0（帧编解码 TDD）→ N1（回环 TLS，先把 §13.1 四条定死）→ N2（mTLS + 配对窗口）→ N3（局域网真机 + 多根同步）→ N4（公网：先 Tailscale，再 IPv6，最后 IPv4 映射）→ N5（outbox + 移除默认共享目录通道）。
