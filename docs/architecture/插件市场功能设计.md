# 插件市场功能设计（Assistant v0.6.0 前置）

> 日期：2026-10-05
> 目标：给 Assistant 加一个"插件市场"——用户能在主面板里浏览、安装、启用/停用、卸载插件。
> 参照物：DeepSeek Harness（下称 DSH）当前的插件管理功能。
> 定位：GUIDE Phase 4「插件系统 + 发布」的**实现级设计（LLD）**。上层模块框架（分层/边界/依赖方向/数据流）见 `插件市场-模块框架.md`；本文只负责填细节（字段 Schema / 状态机 / 错误码 / 分期）。
> 前置依赖：核心扩展点 `ISearchProvider`（`docs/architecture/文件检索重构方案.md` §5.1 / 实施清单 A7）。

## 0. 一页纸结论

| 项 | 结论 |
|---|---|
| 插件形态 | **QML/JS 插件包**（`plugin.json` + `main.qml`），**不做 C++ DLL 作为 v1 主路径**（理由见 §3 D1） |
| 分发方式 | 静态索引 `index.json` + zip 包（HTTPS），**没有依赖解析器**（插件只依赖 Qt 与宿主 API） |
| 真源文件 | `%LOCALAPPDATA%/AssistantTeam/Assistant/plugins/plugins.json`（原子写），**不入 SQLite** |
| 安装管线 | `inspect → resolve → download → verify → extract → validate → commit → enable`，逐阶段可失败、可回滚 |
| UI 位置 | 主面板左侧导航第 4 项「插件市场」，右侧 `Loader` 承载动态页面 |
| 先做哪块 | **M0 本地插件包 + 管理页（无网络）** 可以立刻开工，不依赖 A7；网络市场 M1 起 |
| 工作量 | M0–M3 约 2500–3500 行（含 QML），拆成 6 个里程碑（§14） |

## 1. 先澄清：DSH 的"插件市场"其实不是商店

调研了 DSH 安装目录下的实现（`node_modules/@deepseek-ai/` 里的 `dsh-plugin-manager`、`dsh-client-ui-plugin-manager`、`dsh-package-manifest`、`dsh-host-plugin-inventory`、`dsh-plugin-package-inventory-deepseek`），它的实际形态是：

**它是一个"插件管理器"，不是应用商店。** 没有远程商品目录、没有分类、没有评分、没有"发现"页。它做的是：

1. **分组列表**：`Official`（随安装包一起发、默认关闭、可开启但不可卸载、实验特性打 `Experimental` 标）+ `Installed`（当前 profile 装了的包）。卡片按名字排序，开关状态变了也不换位置。
2. **按 spec 安装**：一个输入框，接受 npm 包名（可带版本）、git 地址、tarball、本地绝对路径；旁边有 registry 选择器（官方 npm / npmmirror 镜像 / 自定义地址）和一段**信任提示**（明确说"插件装了不会自动更新"）。
3. **安装过程可见可取消**：`inspect` 先问清楚"这个 spec 指向什么"（不存在/已装/不是插件/网络失败都提前拒绝），然后流式打印 pnpm 输出，有阶段状态 `installing / cancelling / applying`，可以取消，响应丢了还能 `waitForInstall` 找回结果。
4. **失败即回滚**：安装失败或被取消，把 `package.json` 和 lockfile 恢复到快照；**下载下来的文件不删**（这点它明说了）。
5. **启用/停用粒度到"行"**：一个插件包内部可以有多个子插件（row），每行单独开关；能给它自己的配置页。
6. **加载失败不崩**：装上了但加载失败的包还留在列表里，带 `problem` 标签、不能启用、可以卸载。

对我们要紧的结论：

> **照抄它的"机制"，另外补一个它没有的"目录页"。**
> 机制 = 三态列表（官方/已装/可装）+ 分阶段安装 + 回滚 + 进度日志 + 问题标签。
> 目录页 = 我们额外做（因为 C++ 桌面端没有 npm 可以按名字装，用户必须先能"看见"有什么可装）。

### 1.1 概念映射表

| DSH | 本项目 | 说明 |
|---|---|---|
| profile bundle | **插件包**（`plugins/<id>/`） | 一对一 |
| `package.json` + `dsh` 字段 | `plugin.json` | 字段精简，见 §5.1 |
| `cordis.patch.yml` 的 row | `plugin.json` 的 `contributes.*` | 贡献点见 §8 |
| npm registry / `pnpm add` | 市场 `index.json` + zip 下载 | **最大差异**：无依赖解析、无 lockfile |
| Loader entry | `PluginHost` 注册的贡献项 | — |
| row 开关 | 贡献项开关 | v2 再拆细，v1 只有包级开关 |
| `PluginManager`（Host 服务） | `PluginManager`（C++ 门面） | 同名，语义对齐 |
| `plugins` 侧栏页 | `PluginsPage.qml` | 主面板导航 |
| install dialog | `PluginInstallDialog.qml` | — |
| `ManagementError.code` / `failedAt` | 同构错误码表 | 见 §7.3 |
| `application: applied / restart-required` | 同构 | 我们更新插件一律 `restart-required` |

### 1.2 DSH 明确承认的安全事实（我们也得承认）

DSH 文档原文意思是：**装上的插件在宿主进程内执行，在 workspace 沙箱之外**；`plugin_manager` 工具的每次操作还要求 `danger-full-access` 或人工审批，但那只是"改配置"的审批，不是运行沙箱。

我们照抄这个诚实度：**QML 插件在应用进程内跑，JS 拿得到 `host` 对象，理论上能读写文件。** 所以设计里不做"假沙箱"，只做：来源校验（sha256）+ 版本门控 + 权限声明（**仅用于展示和确认，不是强制隔离**）+ 卸载二次确认。§11 展开。

## 2. 目标与边界

### 2.1 做

- 主面板新增「插件市场」入口；列表页分 `官方` / `已安装` / `可更新` 三组。
- 市场目录：从 HTTPS 静态索引拉取，带缓存、ETag、离线降级（用本地缓存 + 随包预置的 seed 索引）。
- 搜索框 + 分类筛选（全部 / 搜索 / 工具 / 网络 / 界面）。
- 安装：分阶段进度、实时日志、取消、失败回滚、错误码。
- 管理：启用/停用、卸载（二次确认）、打开插件目录。
- 插件贡献点：**页面**（加进左侧导航）、**命令**（进搜索框）；**搜索 provider** 留接口但等 A7。
- 本地安装：`installFromZip` / 扫描 `plugins/` 下手工放入的目录（开发期必需，不然每次测试都要发版到索引）。

### 2.2 不做（v1 明确不做，写下来避免越界）

- ❌ 不做依赖解析（插件不能声明"我需要另一个插件"）。
- ❌ 不做自动更新（检查更新 + 手动升级有，后台静默升级没有 → 与 DSH 一致）。
- ❌ 不做插件签名（Ed25519）——只做 sha256；签名留 v2，理由见 §11。
- ❌ 不做插件间 IPC / 沙箱进程隔离。
- ❌ 不做 C++ DLL 插件（v2 再评估，见 D1）。
- ❌ 不做评分/评论/下载统计上报（隐私 + 无后端）。

## 3. 关键决策

### D1 插件形态：QML/JS 包，而不是 C++ DLL ★最关键

GUIDE Phase 4 原写的是「纯虚基类 `init()/name()/shutdown()` + `QLibrary` 动态库」。**建议改掉 v1 主路径**：

| 维度 | C++ DLL | QML/JS 包 |
|---|---|---|
| ABI 稳定性 | ❌ MSVC 版本/Debug-Release/STL 版本都要对齐，`std::string`/`QList` 跨 DLL 传都是雷 | ✅ 无 ABI |
| 与现有架构契合 | 中（要发明一套 C ABI + 版本门） | ✅ 项目本来就是 QML 驱动 |
| 装/卸/热切 | ❌ DLL 一旦 LoadLibrary 基本卸不干净（同 DSH：替换包需重启） | ✅ 组件对象可删，页面可撤 |
| 用户能否审阅 | ❌ 二进制 | ✅ 纯文本，学生项目教学价值高 |
| 出问题的代价 | 段错误直接崩进程 | QML 异常可捕获，标 `problem` 不崩 |
| 能力上限 | 高（任意 Win32） | 中（Qt 能做的都能做，含 Win32 需另包） |

**结论**：`plugin.json` 里留 `"runtime": "qml"`（默认）/ `"native"`（预留）。`native` 在 v1 直接**拒绝安装**并提示"本版本暂不支持原生插件"。`QLibrary` 那条路留到真有人需要时，且要求 `ISearchProvider` 已经 A7 稳定。

> 这不是偷懒，是让"插件市场"这条链路（索引→下载→校验→安装→回滚→加载→卸载）先跑通。ABI 是另一条独立的、更难的线，混在一起会两头都做不完。

### D2 分发源：静态 JSON + zip，无包管理器

- 索引：HTTPS 上一个 `index.json`（GitHub Pages / raw / 自建静态站都行）。
- 包：`<id>-<version>.zip`，索引里给 `url + sha256 + size`。
- 多源：`pluginMarketUrl`（主）+ `pluginMarketMirrors`（备），主源不可达时按顺序降级——照抄 DSH 的 `registry` / `fallbackRegistries` 语义。
- 缓存：`market-cache.json` 存最后一次成功响应 + `etag`，`pluginCatalogTtlMs` 默认 6 小时。

**为什么不用 git 克隆仓库**：要带 libgit2 或调 `git.exe`，还得处理子模块/大文件，对"一个 QML 包的 zip"是过度设计。

### D3 状态存储：JSON 原子写，不入 SQLite

项目约定是"每个功能一个 DB"，**这里故意破例**：

| 理由 | 说明 |
|---|---|
| 数据量小 | 几十个插件、每行 5 个字段，SQLite 的迁移成本 > 收益 |
| 语义要原子 | 安装是"文件落盘 + 状态登记"两步，需要 `QSaveFile` 的整文件原子替换；和 SQLite 事务混用反而要处理两套失败回滚 |
| 可人工修复 | 插件装坏了，用户能手改 `plugins.json`；用 DB 就只能开 SQLite 工具 |
| 与 DSH 同构 | DSH 的真源就是 `package.json`（纯文本清单），不是数据库 |

DB 只在"要查询历史/统计"时才值得；插件清单不需要查询。

### D4 隔离与信任：不假装沙箱，只做门控

见 §11。一句话：**sha256 + 版本范围 + 权限声明展示 + 二次确认**。不承诺"插件不能读你的文件"。

### D5 更新策略：手动升级，且必须重启

- 有更新时卡片打 `更新` 标 → 点开是"卸载后装新版"（DSH 同样是"升级 = 卸载再装"）。
- 更新后 `application: "restart-required"`，UI 明说重启生效。
  原因：QML 引擎会缓存组件编译结果，同进程替换 `main.qml` 后再加载不保证拿到新版本；`engine.clearComponentCache()` 会连带把宿主自己的 QML 缓存清掉，代价太大且时序难控。**不要在这个问题上挣扎，重启是正确解**（DSH 也承认）。

## 4. 目录布局

```
%LOCALAPPDATA%/AssistantTeam/Assistant/
└─ plugins/
   ├─ plugins.json                 # 已安装状态（唯一真源）
   ├─ market-cache.json            # 索引缓存（含 etag / fetchedAt）
   ├─ .cache/                      # 下载中：<requestId>.zip.part
   ├─ .tmp/                        # 解压中：<requestId>/
   ├─ .logs/                       # <requestId>.log（安装日志全文）
   ├─ .trash/                      # 卸载暂存：<id>-<timestamp>/（删失败时下次启动重试）
   ├─ com.assistant.weather/       # 一个插件一个目录
   │  ├─ plugin.json
   │  ├─ main.qml
   │  └─ data/                     # 插件自己的可写目录（宿主创建）
   └─ com.assistant.weather.bak/   # 更新时旧版本暂存（成功后删）
```

要点：

- **插件目录名 = 插件 id**，不做 `@`/`/` 这类 npm 风格命名（id 用反向域名，`[a-z0-9._-]`，`plugin.json` 里校验）。
- `.cache` / `.tmp` / `.trash` 都以 `.` 开头 → 扫描"手工放入的插件"时跳过。
- 每个插件有独立 `data/`，宿主在 `PluginHost::dataDir()` 暴露；插件不得往自己安装目录写（升级时会被整个替换）。

## 5. 数据模型

### 5.1 `plugin.json`（插件清单，随包分发）

```json
{
  "manifestVersion": 1,
  "id": "com.assistant.weather",
  "name": "天气",
  "version": "1.2.0",
  "description": "输入 w 北京，直接看天气",
  "author": "AssistantTeam",
  "homepage": "https://github.com/xxx/assistant-weather",
  "license": "MIT",
  "icon": "icon.png",
  "runtime": "qml",
  "engines": { "assistant": ">=0.6.0 <1.0.0" },
  "main": "main.qml",
  "permissions": ["network", "clipboard.read"],
  "contributes": {
    "pages": [
      { "id": "weather", "title": "天气", "icon": "🌤", "source": "Page.qml" }
    ],
    "searchProviders": [
      { "id": "weather", "title": "天气", "trigger": "w ", "priority": 40 }
    ],
    "commands": [
      { "id": "weather.now", "title": "天气：当前城市", "keyword": "weather" }
    ],
    "settings": { "source": "Settings.qml" }
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `manifestVersion` | ✅ | 固定 `1`，独立于插件 `version`（DSH 同款做法） |
| `id` | ✅ | `^[a-z0-9][a-z0-9._-]{2,63}$`，装完不可改名 |
| `name` / `version` | ✅ | `version` 必须是 SemVer（§16.1 说的子集） |
| `engines.assistant` | 建议 | 缺失视为"不声明兼容"，装时警告不算失败（DSH：省略即不声明，读取方不臆测默认） |
| `main` | ✅（runtime=qml） | 相对插件根，不得含 `..` |
| `permissions` | 建议 | 仅展示用：`network` / `fs.read` / `fs.write` / `clipboard.read` / `clipboard.write` / `hotkey` / `shell` |
| `contributes.pages` | — | 进左侧导航 |
| `contributes.searchProviders` | — | **依赖 A7**；A7 之前宿主登记但不生效（§8.3） |
| `contributes.commands` | — | 进搜索框结果 |
| `contributes.settings` | — | 插件自己的设置页（v2 才有入口，v1 只解析） |

校验规则（`PluginManifest::parse` 里一律硬校验，失败就是 `invalid-manifest`）：
`id` 正则、SemVer 可解析、`main` 存在且在插件根内、`pages[].id` 唯一、`source` 反斜杠改成 `/` 后不得以 `/` 开头或含 `..`。

### 5.2 `index.json`（市场目录，服务端）

```json
{
  "schemaVersion": 1,
  "generatedAt": "2026-10-01T00:00:00Z",
  "appMinVersion": "0.6.0",
  "plugins": [
    {
      "id": "com.assistant.weather",
      "name": "天气",
      "summary": "输入 w 城市 查看天气",
      "description": "Markdown 长描述…",
      "author": "AssistantTeam",
      "categories": ["搜索", "网络"],
      "tags": ["官方"],
      "icon": "https://…/weather.png",
      "screenshots": ["https://…/shot1.png"],
      "latest": {
        "version": "1.2.0",
        "url": "https://…/com.assistant.weather-1.2.0.zip",
        "sha256": "9f2c…",
        "size": 48213,
        "minAppVersion": "0.6.0",
        "changelog": "修复城市名含空格时解析失败"
      },
      "versions": [ { "version": "1.1.0", "url": "…", "sha256": "…", "size": 47000 } ],
      "downloads": 1234,
      "updatedAt": "2026-09-30T12:00:00Z"
    }
  ]
}
```

| 字段 | 用途 |
|---|---|
| `latest` | 安装/更新都用它；`versions` 只为"装旧版"留位，v1 UI 不暴露 |
| `minAppVersion` | 与插件 `engines.assistant` 双保险：索引侧能挡掉明显不兼容的，省一次下载 |
| `tags` | `官方` / `实验` / `需重启`，映射成卡片角标 |
| `categories` | 分类筛选的来源，**由索引定义**而不是硬编码在 QML 里（放 `index.categories` 更规范，v1 先从插件聚合） |

**离线 seed**：`resources/market/seed-index.json` 编译进 qrc。首次启动没网也能看到内容（标 `离线`），这也是"演示给别人看"的最低保障。

### 5.3 `plugins.json`（本地已安装状态）

```json
{
  "schemaVersion": 1,
  "plugins": {
    "com.assistant.weather": {
      "version": "1.2.0",
      "installedAt": "2026-10-05T12:00:00Z",
      "enabled": true,
      "origin": { "kind": "market", "url": "https://…/weather-1.2.0.zip", "sha256": "9f2c…" },
      "problem": null
    },
    "com.example.broken": {
      "version": "0.1.0",
      "enabled": false,
      "origin": { "kind": "local", "path": "D:/tmp/broken.zip" },
      "problem": { "code": "load-failed", "detail": "main.qml:12 Unexpected token '}'" }
    }
  }
}
```

- `origin.kind`: `market` / `local`（手工 zip）/ `bundled`（随包内置的示例插件，默认关闭、不可卸载——对应 DSH 的 `official`/`optional`）。
- `problem` 非空时：卡片打红标、`enabled` 强制 false、不能启用、可以卸载。**这就是 DSH 的"加载失败的包仍在列表里"语义**。
- 写入一律 `QSaveFile`（原子替换），成功后 `QFile::remove` 旧 `.bak`。

## 6. C++ 分层

```
include/core/plugin/          src/core/plugin/
├─ PluginManifest.h/.cpp      解析 + 校验 plugin.json
├─ SemVer.h/.cpp              版本解析/比较/range 匹配（不引三方库）
├─ PluginSpec.h/.cpp          解析"装什么"：id / id@ver / https url / 本地路径
├─ PluginRegistry.h/.cpp      plugins.json 读写 + 目录布局
├─ PluginCatalog.h/.cpp       index.json 拉取/缓存/降级/过滤
├─ PluginInstaller.h/.cpp     安装状态机（网络+解压+校验+回滚）
├─ PluginLoader.h/.cpp        QQmlComponent 加载/卸载 + 贡献登记
├─ PluginHost.h/.cpp          插件可见的宿主 API（context property `host`）
└─ PluginManager.h/.cpp       门面：把上面几个黏起来，给 Bridge 用

include/ui/
├─ PluginBridge.h/.cpp        QML↔C++ 桥
└─ PluginListModel.h/.cpp     QAbstractListModel（卡片数据）
```

为什么要有 `PluginManager` 这层：DSH 的做法是 service（`PluginManager`）对外只暴露 `listBundles / inspect / installBundle / cancelInstall / removeBundle / setBundleEnabled`，UI 不碰文件系统。照抄这个边界——`PluginBridge` 只做类型转换 + 信号转发，业务判断全在 `PluginManager`，这样才能写单测（§13）。

### 6.1 关键签名（设计，不是最终代码）

```cpp
// SemVer.h — 只支持我们需要的子集
namespace semver {
struct Version { int major = 0, minor = 0, patch = 0; QString pre; };  // pre 仅比较"有/无"
std::optional<Version> parse(QStringView text);
int  compare(const Version &a, const Version &b);
bool satisfies(const Version &v, QStringView range);   // ">=0.6.0 <1.0.0"
}

// PluginManifest.h
struct PageContribution    { QString id, title, icon, source; };
struct ProviderContribution{ QString id, title, trigger; int priority = 100; };
struct CommandContribution { QString id, title, keyword; };

struct PluginManifest {
    int manifestVersion = 1;
```

### 6.2 线程与模块依赖

- 网络：`QNetworkAccessManager`（主线程异步），**不要**自己开线程做 HTTP。
- sha256 / 解压：放 `QtConcurrent::run` 或 `QThreadPool`，结果用信号回主线程。CMake 要加 `Qt6::Concurrent`。
- zip：Qt6 没有公开的 zip 读取 API（`QZipReader` 是私有头，别用）。选 **vcpkg `miniz`**（单文件、MIT、无依赖），备选 `libzip`。解压时**必须**做 zip-slip 校验：每个 entry 的规范化路径必须在目标目录内，且拒绝绝对路径/盘符/`..`/符号链接 entry。
- 日志：走现成的 `spdlog`（`Logger::get()`），另外把安装日志全文落 `.logs/<requestId>.log`——照抄 DSH 的"截断的诊断 + 完整日志文件路径"双轨。

## 7. 安装状态机

### 7.1 阶段

| 阶段 | 干什么 | 失败码 | 可取消 |
|---|---|---|---|
| `Inspecting` | 解析 spec；装 id 时先查索引；已装/不存在/不是插件提前拒绝 | `invalid-spec` `not-found` `already-installed` `not-a-plugin` | ✅ |
| `Resolving` | 版本选择 + `engines.assistant` / `minAppVersion` 门控 | `incompatible-version` `no-matching-version` | ✅ |
| `Downloading` | 流式下载到 `.cache/<rid>.zip.part`（分块写、有进度） | `network` `http-status` | ✅ |
| `Verifying` | sha256 + size 比对 | `checksum` | ✅ |
| `Extracting` | 解到 `.tmp/<rid>/`，zip-slip 校验 | `zip-slip` `disk-full` | ✅ |
| `Validating` | 解析 `plugin.json`、校验 `main` 存在、版本与索引一致 | `invalid-manifest` `version-mismatch` | ✅ |
| `Committing` | 旧版本挪 `.bak` → `.tmp` 原子 rename 到 `plugins/<id>` → 写 `plugins.json` | `permission` `disk-full` | ❌（过了这里就是"已安装"） |
| `Enabling` | `PluginLoader::load()`，成功则 `enabled=true` | `load-failed` | ❌ |

**回滚规则（对齐 DSH 语义）**：

| 失败点 | 文件 | 状态 |
|---|---|---|
| `Committing` 之前 | 删 `.cache` / `.tmp` 里这次的东西 | `plugins.json` 一个字节都没动 |
| `Committing` 之中 | `.tmp` 删掉，`.bak` 还原回 `<id>` | `plugins.json` 不动 |
| `Enabling` 失败 | **保留安装好的文件** | 写 `plugin.json` 状态 + `problem{load-failed}`，`enabled=false` |

> 最后一条是重点：**"装上了但加载不了"不等于"安装失败"**。DSH 也是这个语义（安装完成不因启用失败而撤销）；把它合成一个"失败"会让用户重装一遍再失败一遍。

### 7.2 `install_from_spec` 与取消

- `cancel(requestId)`：`Committing` 之前 → 置取消标志、删临时文件、`finished(ok=false, code="cancelled")`；之后 → 返回 `false`，前端显示"已进入安装最后一步，无法取消"（DSH 的 `too-late`）。
- 安装期间**同一时刻只允许一个安装**（`isBusy()` 挡住第二个），但**允许多个卸载**？不，也串行——文件操作串行化，逻辑简单得多。DSH 也是 profile 级写锁（`lockWaitMs`）。

### 7.3 错误码表（`ManagementError.code` 同构）

| code | 触发 | UI 文案（QML 词条） |
|---|---|---|
| `invalid-spec` | spec 解析不了 | 安装源格式无法识别 |
| `not-found` | 索引里没有 / 404 | 市场里找不到这个插件 |
| `already-installed` | 已装同版本 | 已安装该版本 |
| `not-a-plugin` | zip 里没 `plugin.json` | 这不是一个 Assistant 插件包 |
| `incompatible-version` | 版本范围不满足 | 该插件要求 Assistant {range}，当前 {version} |
| `no-matching-version` | 索引里没有满足范围的版本 | 没有兼容当前版本的发行版 |
| `version-mismatch` | 包内版本 ≠ 索引声明 | 包内容与索引不符，已拒绝安装 |
| `network` | 连不上 / 超时 | 网络不可用，可稍后重试 |
| `http-status` | 非 2xx | 下载失败（HTTP {code}） |
| `checksum` | sha256 不符 | 文件校验失败，可能被篡改或不完整 |
| `zip-slip` | 解压路径越界 | 压缩包路径非法，已拒绝 |
| `invalid-manifest` | 清单字段非法 | 插件清单格式错误：{detail} |
| `disk-full` | 写失败 | 磁盘空间不足 |
| `permission` | 无写权限 | 没有写入权限（被杀软/策略拦截？） |
| `load-failed` | QML 编译/实例化失败 | 插件加载失败：{detail} |
| `not-removable` | 内置/管理插件 | 该插件不可卸载 |
| `cancelled` | 用户取消 | 已取消安装 |
| `too-late` | 取消晚了 | 安装已进入最后一步 |
| `unknown` | 兜底 | 未知错误，日志见 {logPath} |

QML 只拿 `code` 做分支、`detail` 做补充展示；**文案在 QML 里**（和 `Style.qml` 集中色值同一个思路，避免文案散在 C++ 里）。

## 8. 插件宿主 API 与贡献点

### 8.1 插件拿到的对象

`PluginLoader` 在加载 `main.qml` 时新建一个 `QQmlContext`，`setContextProperty("host", hostForPlugin)`：

```cpp
class PluginHost : public QObject {
    Q_OBJECT
    Q_PROPERTY(QString pluginId   READ pluginId   CONSTANT)
    Q_PROPERTY(QString pluginName READ pluginName CONSTANT)
    Q_PROPERTY(QString version    READ version    CONSTANT)
    Q_PROPERTY(QString appVersion READ appVersion CONSTANT)
    Q_PROPERTY(QString dataDir    READ dataDir    CONSTANT)   // 可写目录
    Q_PROPERTY(bool     isDark    READ isDark     NOTIFY themeChanged)

public:
    Q_INVOKABLE void log(const QString &level, const QString &message);
    Q_INVOKABLE QVariant setting(const QString &key, const QVariant &fallback = {});
    Q_INVOKABLE void     setSetting(const QString &key, const QVariant &value);   // 存 data/settings.json
    Q_INVOKABLE void     toast(const QString &text);            // 走宿主 toast，插件不用自己画
    Q_INVOKABLE bool     openPath(const QString &path);          // QDesktopServices，受权限点约束

signals:
    void themeChanged();
};
```

设计原则：**宿主只给"数据 + 动作"，不给"控件"**。插件的 UI 是它自己的 QML，用 `Style` 单例取色（`Style` 已是 qmldir singleton，插件目录加载时同样能 `import "."`？不能——插件目录不在同一个 import path。方案：加载插件前把 `qrc:/qml` 加进 engine 的 import path，或者把 `Style.qml` 复制进插件包。**选前者**：`engine->addImportPath("qrc:/qml")`，插件里 `import "qrc:/qml" as Style`… 实际可行做法是 `engine->addImportPath` + 插件 `import AssistantTheme 1.0`——这需要建一个 QML module（`qmldir` + `module` 行）。v1 简化：**插件不用宿主 Style，自己写色值**，宿主在 README 里给出推荐色板。少一个坑。）

### 8.2 贡献点生效方式

| 贡献 | 生效 | 撤销 |
|---|---|---|
| `pages` | `PluginLoader::loaded` → `PluginBridge` 发出 `navigationChanged` → `MainPanel` 的 `Repeater` 重算 | `unload` → 同样信号 |
| `commands` | 注册进 `AppBridge` 的命令表（前缀匹配 `keyword`） | `unload` 时移除 |
| `searchProviders` | 见 §8.3 | — |
| `settings` | v2 | — |

### 8.3 `searchProviders` 与 A7 的关系（重要）

**A7 没落地之前，`registerProvider` 只登记不生效。** 原因：`ISearchProvider`（`QString providerId() const` + `QList<SearchResult> query(std::string_view, int)`）还没有，`AppBridge` 现在还是"拼大 list 再全排序"。

A7 落地后接上：

```cpp
// 插件侧（JS）
function query(text, limit) {
    return [{ title: "北京 晴 18°C", subtitle: "天气", path: "", type: "weather", score: 0 }];
}

// 宿主侧：把 QJSValue 包成 ISearchProvider
class JsSearchProvider : public ISearchProvider {
    QString providerId() const override { return m_id; }
    QList<SearchResult> query(std::string_view text, int limit) override;  // 调 JS，转 QVariantList
};
```

这条路径让"插件只是给搜索框加一路结果"变成**纯数据约定**（JS 返回数组），不需要 C++ ABI——这也是选 QML 形态的额外收益。

## 11. 安全模型（诚实版）

| 层 | 做什么 | 不做什么 |
|---|---|---|
| 传输 | 仅 HTTPS（`http://127.0.0.1` 例外，仅 Debug 构建，供本地测试服务器） | 不校验证书钉扎 |
| 完整性 | 索引声明的 sha256 必须匹配 | 不做签名（见下） |
| 结构 | zip-slip 校验、路径必须落在插件目录内、拒绝符号链接 entry | 不限制插件代码行为 |
| 兼容 | `engines.assistant` + `minAppVersion` 双门控 | 不做"装了不兼容版本仍可用"的豁免机制（DSH 有 `compatibility.json` 豁免，我们 v1 不做，太复杂且助长误用） |
| 运行 | 进程内执行，**无沙箱** | 不承诺隔离 |
| 认知 | 权限声明 + 信任提示 + 二次确认卸载 | 不把权限声明伪装成强制拦截 |

**为什么不做签名（v1）**：需要一套密钥分发 + 公钥内置 + 逐版本签名，而且签名只解决"这个包是谁发的"，不解决"这个作者可信吗"。在单作者（学习者本人）项目里，sha256 + HTTPS 已经把"传输被篡改"和"索引被换"这两类风险压到很低；把复杂度留给更值得的地方。**v2 若要开放第三方提交，签名是准入条件**——这一点写进 `docs/features/` 的待办。

**权限声明的真实作用**：用户装之前的知情同意 + 出问题时的排障线索。文档里必须明说这个，否则是虚假安全感。

## 12. 已知限制（写下来，别以后当 bug）

1. **更新需重启**（QML 组件缓存 + 已实例化对象）。UI 用 `restart-required` 明示。
2. **无依赖解析**：插件不能依赖另一个插件；共享代码只能各自复制或由宿主提供 API。
3. **单安装串行**：同时只能跑一个安装任务。
4. **插件不能改宿主内置页面**（只能新增页面/命令/provider）——比 DSH 的 patch 能力弱，换来的是宿主不被插件改坏。
5. **卸载失败会留在 `.trash`**：下次启动重试，最多 3 次后提示手动删除。
6. **手工放入 `plugins/` 的插件**：扫描到就登记（`origin.kind = "local"`），但没有 sha256 记录，详情页标「未校验」。
7. **安装日志会一直攒**：`.logs` 加个"保留最近 20 个"的清扫（启动时做）。

### 14.1 建议插入点：M0 可以现在就做

GUIDE 要求"插件系统等核心架构稳定后再做"，指的是**插件接口**（`ISearchProvider`）不能早定。但 M0 的装载/卸载/状态/UI 完全不碰 provider 接口——它只做"文件夹 ↔ 进程内对象"的搬运。

所以两条线可以并行：

```
主线：Phase A（A2 结构 → … → A7 ISearchProvider）
副线：插件市场 M0（纯本地、不碰 provider）
汇合：A7 落地 → M4 的 provider 桥 → 插件能实现 ISearchProvider
```

这样做还有个好处：M0 就在练 `PluginLoader` 的 QML 生命周期管理，A7 之后接 provider 只是加一个"注册回调"，接口一次定型。

## 15. 示例插件包（M5 的第一个产物，也用来验证清单设计）

```
weather/
├─ plugin.json
├─ main.qml            // 只有 host 引用和初始化逻辑
├─ Page.qml            // contributes.pages[0].source
└─ icon.png
```

`main.qml` 长这样（这就是我们承诺给插件作者的 API 全部）：

```qml
import QtQuick

QtObject {
    Component.onCompleted: host.log("info", "weather plugin loaded, data=" + host.dataDir)

    // A7 之后才被调用
    function query(text, limit) {
        if (!text.startsWith("w ")) return []
        return [{ title: "北京 晴 18°C", subtitle: "天气", type: "weather", score: 0 }]
    }
}
```

三个示例覆盖三种形态：
- **天气**：`searchProviders` + `pages`（要网络 → 验证 `permissions: ["network"]` 展示）
- **翻译**：`commands` + `clipboard.read`（读剪贴板，验证权限提示）
- **文本工具**：纯本地计算，无权限（验证 0 权限插件的路径，也最容易写）

## 16. 附录

### 16.1 SemVer 子集（明确边界，避免"我们自己发明版本语法"）

支持：
- 版本：`MAJOR.MINOR.PATCH`，可选 `-pre`（`1.2.0-beta.1`）——比较时**有 pre < 无 pre**，pre 之间按字符串比（够用，不做完整 SemVer 优先级规则）
- 范围：比较符 `>= > <= < =` + 空格分隔的 AND + `||` 分隔的 OR；`^1.2.3` 等价 `>=1.2.3 <2.0.0`；`~1.2.3` 等价 `>=1.2.3 <1.3.0`；`1.x` / `1.2.x` 通配
- 不支持：`*` / `latest` / URL 作为版本 / 预发布排除规则

### 16.2 决策记录（为什么这么定，便于以后推翻时有据可查）

| # | 决策 | 备选 | 为什么不选备选 |
|---|---|---|---|
| D1 | QML 插件形态 | C++ DLL | ABI 脆弱、卸不干净、不可审阅（§3） |
| D2 | 静态索引 + zip | git 克隆 / 自建 API | 要引入 git 或后端；zip 静态托管零运维 |
| D3 | `plugins.json` | SQLite | 数据小、要原子整写、要能手改（§3） |
| D4 | 不假装沙箱 | 独立进程 + IPC | 工作量翻倍，v1 收益低；但 API 设计已隔离，未来可换（`PluginHost` 就是天然边界） |
| D5 | 更新必须重启 | 同进程热替换 | QML 组件缓存不可靠，`clearComponentCache` 副作用大 |
| D6 | 破例不用 DB | 遵循"一功能一 DB" | §3 已论证；**这条破例要写进 CLAUDE.md 的 DB 约定旁边**，否则以后自己会困惑 |

### 16.3 与 DSH 的差距（明确"我们是有意简化"）

| DSH 有 | 我们 v1 没有 | 后果 |
|---|---|---|
| npm 生态 / 依赖解析 / lockfile | 无 | 插件不能复用第三方 npm 包；但我们是 C++/Qt，本来也不需要 |
| 包级 + 行级双开关 | 只有包级 | 一个插件想关掉部分功能只能自己写设置页 |
| 版本豁免机制（`compatibility.json`） | 无 | 不兼容就装不了，简单直接 |
| 多 registry 逐个降级 | 有（主 + 镜像） | 对齐 |
| `waitForInstall` 找回丢掉的响应 | v1 不做（同步等待 + 本地状态重算足够） | 网络抖动极端情况会显示"未知"，重进页面刷新即可 |
| 卸载失败保留部分变更 | 我们回滚到干净态 | 我们的操作更少，回滚更容易做对 |
