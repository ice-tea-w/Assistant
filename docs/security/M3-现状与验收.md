# 安全模块（M3）现状与验收

> 定位：主程序（C++/Qt6）通过 **`SecurityBridge`** 调用 `file_guard.exe`
> （`tools/file_guard_cpp`，C++20，v1.0.0），在「安全中心」页展示审计链、备份库、
> 保险箱、敏感扫描四类状态。
>
> **C++ 是唯一主线**：`src/security` 的最小移植已删除；
> Python 版（`tools/file_guard`）保留为参考实现/验收基准，不参与运行时。

## 1. 整体项目里怎么体现（四层）

| 层 | 位置 | 现状 |
| --- | --- | --- |
| 主程序界面 | 主面板左侧「🛡 安全防护」→ `resources/qml/SecurityPage.qml` | 已接：四张状态卡 + 体检/扫描/打开报告/打开数据目录 |
| 主程序桥 | `include/ui/SecurityBridge.h`、`src/ui/SecurityBridge.cpp` | 已接：异步 QProcess + `--json`、30s 超时、失败降级 |
| 可执行模块 | `tools/file_guard_cpp/`（v1.0.0，58 条测试） | 已接：加密/扫描/审计/备份/保险箱/监听/服务/完整性 |
| 权威数据与网关 | `security.db` / `FileOpGateway` / 策略审批 | **未做**，M3 下一阶段（设计见 `docs/architecture/四模块完整架构.md` §6） |

## 2. 数据流

```
SecurityPage.qml
   └─ security.refresh()/runSelfCheck()/runScan(path)
        └─ SecurityBridge（GUI 线程，异步）
             └─ QProcess: file_guard.exe <cmd> --json --home <AppConfig>/security
                  ├─ version                        → 1.0.0
                  ├─ doctor --json                  → 体检（checks[]）
                  ├─ log verify --json              → 审计链（records/head/ok）
                  ├─ backup list --json             → 备份库（items[]）
                  ├─ vault info --json              → 保险箱（files/containers/dpapi）
                  └─ scan <path> --min-risk medium --json → 敏感扫描（summary/files[]）
```

约束：

- 只调用**白名单**子命令，参数数组交给 QProcess，不拼 shell；
- 超时 30s，失败只影响卡片状态，不影响主程序；
- 数据目录固定 `%LOCALAPPDATA%/AssistantTeam/Assistant/security`，不碰用户真实 `~/.file_guard`；
- `file_guard.exe` 查找顺序：`ASSISTANT_FILE_GUARD` → 主程序同目录 → 仓库内各构建目录；
- 找不到 exe 时卡片显示「未找到 C++ 安全模块」，主程序照常启动。

## 3. 验收

### 3.1 C++ 主线（主验收）

```powershell
# 根构建（会把 tools/file_guard_cpp 作为子工程，并把 file_guard.exe 拷到 Assistant.exe 旁）
cmake --build build --config Debug --target Assistant file_guard fg_tests
ctest -C Debug -R fg_tests          # 58/58
```

CLI 冒烟（不需要主程序）：

```powershell
$exe = "build\Debug\file_guard.exe"
& $exe version
& $exe doctor --json --home "$env:LOCALAPPDATA\AssistantTeam\Assistant\security"
& $exe log verify --json --home <同一个目录>
& $exe vault info --json --home <同一个目录>
& $exe scan $env:USERPROFILE\Downloads --min-risk medium --json
```

预期：未初始化时 `log verify`/`backup list` 返回
`{"ok":false,"error":{"type":"PasswordError",…}}`（退出码 3），卡片显示「未初始化」而不是报错。

## 4. 主程序里怎么演示（构建后）

1. 启动 `build\Debug\run.bat`，主面板左侧 → **安全防护**；
2. 四张卡：审计链（记录数 + 链头）、备份库（文件数/体积）、保险箱（文件数/DPAPI）、敏感扫描；
3. 点 **运行安全体检** → 卡片刷新，头部摘要更新；
4. 点 **扫描下载目录** → 敏感扫描卡给出高危/中危数量；
5. 点 **打开验收报告** → 本文档。

首次使用前初始化（交互设密码，DPAPI 缓存后续免密）：

```powershell
build\Debug\file_guard.exe init --home "$env:LOCALAPPDATA\AssistantTeam\Assistant\security"
```

未初始化时卡片显示「未初始化」，不会报错。

## 5. 诚实边界（答辩口径）

- **已做**：静止态加密容器（AES-256-GCM）、审计链（HMAC + 随机 nonce + 高水位）、
  备份（内容寻址 + 加密索引 + 冲突保护）、保险箱（DEK + 恢复码 + 名称加密）、
  本地回环服务（token + Host/Origin）、敏感扫描（规则 + 校验位 + Office 抽取）。
- **未做（M3 下一阶段）**：`FileOpGateway` 受控操作网关、`IFilePolicy` 策略与审批、
  `security.db` 权威库、驱动级实时阻断、运行期无明文承诺。
- 安全模块**不联网**；本地服务只绑 `127.0.0.1`；恢复码 = 第二把钥匙，泄露即泄露保险箱。
- Python 与 C++ 的审计日志不共享密钥派生参数，**不要混读**；保险箱也不承诺互相读取。

## 6. 已知限制

| 限制 | 说明 |
| --- | --- |
| exe 部署 | 主构建会拷贝 `file_guard.exe`；单独跑 `Assistant.exe` 时需保证它同目录 |
| 同步阻塞边界 | 所有探针异步，但 `scan` 大目录可能 20–30s（超时上限 30s） |
| 自动刷新 | 启动后 800ms 自动刷新一次；运行期点按钮刷新，不做定时轮询 |
| 数据迁移 | C++ 是原生格式，不读 Python 版审计/保险箱；需要时写一次性迁移工具 |

## 7. 构建前置条件

- **C++ 安全模块**：只依赖 MSVC + Windows SDK，不需要 Qt/vcpkg；
- **主程序**：需要 vcpkg 的 Qt6 / spdlog / nlohmann_json / miniz（见 `CLAUDE.md` 的构建命令）；
- 根 CMake 会自动 `add_subdirectory(tools/file_guard_cpp)` 并拷贝 `file_guard.exe`；
- 单独构建安全模块：`cmake -B build/fg-cpp -S tools/file_guard_cpp -G "Visual Studio 17 2022" -A x64`。
