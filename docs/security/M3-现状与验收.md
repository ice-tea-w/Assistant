# 安全模块（M3）现状与验收

> 定位：主程序（C++/Qt6）通过 **`SecurityBridge`** 调用 `tools/file_guard`（Python，v0.6.0），
> 在「安全中心」页展示审计链、备份库、保险箱、敏感扫描四类状态。
> 安全能力本身不搬进 C++：M3 设计要求"Python 原型 → C++ 落地"，当前阶段 Python 模块是
> **可执行规格 + 验收基准**，C++ 侧先做集成与展示。

## 1. 整体项目里怎么体现（四层）

| 层 | 位置 | 现状 |
| --- | --- | --- |
| 主程序界面 | 主面板左侧「🛡 安全防护」→ `resources/qml/SecurityPage.qml` | 已接：四张状态卡 + 体检/扫描/打开报告/打开数据目录 |
| 主程序桥 | `include/ui/SecurityBridge.h`、`src/ui/SecurityBridge.cpp` | 已接：异步 QProcess + `--json`、30s 超时、失败降级 |
| 可执行模块 | `tools/file_guard/`（v0.6.0，160 条测试） | 已同步：加密/扫描/审计/备份/保险箱/本地服务 |
| 权威数据与网关 | `security.db` / `FileOpGateway` / 策略审批 | **未做**，M3 下一阶段（设计见 `docs/architecture/四模块完整架构.md` §6） |

## 2. 数据流

```
SecurityPage.qml
   └─ security.refresh()/runSelfCheck()/runScan(path)
        └─ SecurityBridge（GUI 线程，异步）
             └─ QProcess: python -m file_guard <cmd> --json --home <AppConfig>/security
                  ├─ doctor --json          → 体检（checks[]）
                  ├─ log verify --json      → 审计链（records/head/ok）
                  ├─ backup list --json     → 备份库（items[]）
                  ├─ vault info --json      → 保险箱（files/containers/dpapi）
                  └─ scan <path> --json     → 敏感扫描（summary/files[]）
```

约束：

- 只调用**白名单**子命令，参数数组交给 QProcess，不拼 shell；
- 超时 30s，失败只影响卡片状态，不影响主程序；
- 数据目录固定 `%LOCALAPPDATA%/AssistantTeam/Assistant/security`，不碰用户真实 `~/.file_guard`；
- Python 解释器探测顺序：`ASSISTANT_PYTHON` → `<repo>/.venv` → `tools/file_guard/.venv` → `PATH` 里的 `python`。

## 4. 主程序里怎么演示（构建后）

1. 启动 `build\Debug\run.bat`，主面板左侧 → **安全防护**；
2. 四张卡：审计链（记录数 + 链头）、备份库（文件数/体积）、保险箱（文件数/DPAPI）、敏感扫描；
3. 点 **运行安全体检** → 卡片刷新，头部摘要更新；
4. 点 **扫描下载目录** → 敏感扫描卡给出高危/中危数量；
5. 点 **打开验收报告** → 本文档（`docs/security/M3-现状与验收.md`）；
   端到端 52 项的可执行证据见 `scripts/security-demo.ps1` 与 `tools/file_guard/scripts/run_acceptance.py`。

首次使用前建议在 `tools/file_guard` 下跑一次 `python -m file_guard init --home <数据目录>`；
未初始化时卡片会显示「未初始化」，不会报错。

## 5. 诚实边界（答辩口径）

- **已做**：静止态加密容器（AES-256-GCM）、审计链（HMAC + 随机 nonce + 高水位）、
  备份（内容寻址 + 加密索引 + 冲突保护）、保险箱（DEK + 恢复码 + 名称加密）、
  本地回环服务（token + Host/Origin）、敏感扫描（规则 + 校验位 + Office 抽取）。
- **未做（M3 下一阶段）**：`FileOpGateway` 受控操作网关、`IFilePolicy` 策略与审批、
  `security.db` 权威库、驱动级实时阻断、运行期无明文承诺。
- 安全模块**不联网**；本地服务只绑 `127.0.0.1`；恢复码 = 第二把钥匙，泄露即泄露保险箱。

## 6. 已知限制

| 限制 | 说明 |
| --- | --- |
| Python 依赖 | 主程序侧探测 `python`；发布版需要随包带解释器或 .venv（答辩用开发机即可） |
| 同步阻塞边界 | 所有探针异步，但 `scan` 大目录可能 20–30s（超时上限 30s） |
| 未构建验证 | 本目录代码未在 CI 编译；首次构建请重新 configure（`file(GLOB_RECURSE)` 新增源文件） |
| 自动刷新 | 启动后 800ms 自动刷新一次；运行期点按钮刷新，不做定时轮询 |

## 7. 构建前置条件（本机实测）

主程序依赖 **vcpkg 提供的 Qt6 / spdlog / nlohmann_json / miniz**。当前这台机器：
`cmake` 有（VS2026 自带，未在 PATH），但 **vcpkg 与 Qt6 未安装**，所以主程序无法在本机构建。
安全模块本身不受影响：`scripts/security-demo.ps1` 已 11/11 通过。

两条路任选：

**A（验收优先）**：不构建主程序，用 Python 模块验收 + 本文档 + `SecurityPage.qml`/`SecurityBridge.*` 代码讲解；
主程序截图/演示放到组内已有 vcpkg 的机器上完成。

**B（本机装工具链）**：

```powershell
git clone https://github.com/microsoft/vcpkg E:\vcpkg
E:\vcpkg\bootstrap-vcpkg.bat
E:\vcpkg\vcpkg.exe install qtbase qtdeclarative qtquickcontrols2 spdlog nlohmann-json miniz sqlite3 --triplet x64-windows
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
```

`scripts\build.ps1` 会自动找 cmake（含 VS2026 自带）与 vcpkg，缺依赖时打印上面的命令；
构建完成后运行 `build\Debug\run.bat`。

> 注意：不装 vcpkg 直接 configure 会报 `VCPKG_INSTALLED_DIR 未定义`——这是 CMakeLists 的显式保护，
> 不是集成代码的问题。
