# 怎么展示：插件接口如何暴露给别人

> 面向：要给老师/同学/评委演示这个插件市场的人（也就是你自己）
> 配套工具：`tools/demo-market.ps1`（一条命令起本地市场）
> 配套文档：`docs/plugins/README.md`（发给对方看的那份）

---

## 0. 一句话版本

**接口不是一个文件，是四个面。** 演示时按这四个面各说一句话，听众就懂了：

| 面 | 暴露的是什么 | 在哪 |
|---|---|---|
| **清单** | 插件怎么描述自己 | `plugin.json`（schema 见 README §3） |
| **宿主 API** | 插件能调什么 | QML 里的 `host` 对象，6 属性 5 方法，契约在 `include/contract/IHostApi.h` |
| **市场协议** | 插件怎么被分发 | `index.json` + zip + sha256 |
| **作者工具** | 别人怎么开始 | `tools/plugin-new.ps1`、`tools/plugin-pack.ps1`、`examples/text-tools/` |

## 1. 演示前 5 分钟准备

```powershell
# 1. 编译（一次就够）
cmake -B build -S . -G "Visual Studio 17 2022" -A x64 `
      -DCMAKE_TOOLCHAIN_FILE=D:/STUDY/vcpkg/scripts/buildsystems/vcpkg.cmake `
      -DVCPKG_TARGET_TRIPLET=x64-windows
cmake --build build --config Release

# 2. 先把示例插件从宿主里清掉，保证"演示时是第一次装"
#    （插件市场 → 文本工具 → 卸载；或删 plugins\com.assistant.texttools）

# 3. 起本地市场（保持这个窗口开着）
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\demo-market.ps1
```

它会打印两行，复制到**另一个终端**执行：

```powershell
$env:ASSISTANT_MARKET_URL = 'http://127.0.0.1:18730/index.json'
.\build\Release\run.bat
```

> 为什么要本地市场而不是真机联网：**演示不能依赖网络**，而且真实索引还没托管（见 §6）。
> 这个本地服务是 `TcpListener` 起的，不需要管理员权限。

## 2. 五分钟分镜

| 时间 | 你做什么 | 你说什么 | 观众看到什么 |
|---|---|---|---|
| 0:00 | 打开主面板 → 左侧「插件市场」 | "插件是 QML 包，宿主只认一个 `plugin.json`" | 已安装组（内部示例）+ **可安装组里有「文本工具」** |
| 0:40 | 点「文本工具」卡片的安装 | "安装前会先让用户看清楚：它要什么权限" | **确认框**：权限清单 + 信任提示 |
| 1:10 | 指着信任提示念一遍 | "说的是实话——插件在我的进程里、和宿主同权限，我们没做沙箱" | 观众记住的是诚实，不是"安全" |
| 1:30 | 点「安装」 | "下面是安装器的真实阶段：校验 → 下载 → 校验哈希 → 解压 → 校验清单 → 提交" | 进度条 + 滚动日志（含 sha256 校验） |
| 2:10 | 等完成，关闭对话框 | "装上后默认会启用，失败会标红而不是回滚——装上了但加载不了，是两件事" | 卡片变"已安装" |
| 2:30 | **重启程序** | "没有热重载：QML 对象已经在内存里了，改插件必须重启" | 左侧导航多出「文本工具」 |
| 3:00 | 点进「文本工具」，粘一段文字，点「去重行」 | "这个页面是插件自己画的，宿主只给它一个内容区和 `host` 对象" | 页面能跑，结果正确 |
| 3:40 | 回到「插件市场」 | "现在换一台装了 1.0.0 的机器，市场里出了 1.1.0" | 卡片出现**「更新」**角标 |
| 4:00 | 重跑 `.\tools\demo-market.ps1 -Phase 2 -Launch`，重启后看 | "更新是覆盖装、保留插件数据（`data/` 不丢）、并且不会把你停用的插件重新打开" | 版本变 1.1.0，开关状态没变 |
| 4:40 | 收尾 | "整条链路里，宿主没有为这个插件改过一行代码" | —— |

**收尾那句是重点**：证明"接口"不是"我为你定制的集成"，而是"任何人按文档都能做"。

## 3. 想再硬一点：现场证明"没改宿主代码"

```powershell
# 1. 这个插件包完全由工具生成
.\tools\plugin-new.ps1 -Id com.demo.hello -Name "Hello" -OutDir $env:TEMP
#    改两行 QML（比如把标题改成你的名字）

# 2. 打包
.\tools\plugin-pack.ps1 -PluginDir "$env:TEMP\com.demo.hello" -OutDir .\dist

# 3. 侧载安装（不走市场，直接选 zip）
#    插件市场 → 「从文件安装」→ 选 dist\com.demo.hello-0.1.0.zip
```

全程没碰 `src/`。这比口头说"可扩展"有力得多。

## 4. 现场改代码的三个安全动作

都不会导致翻车（改错最多是插件标红，宿主不崩）：

| 动作 | 改哪 | 预期 |
|---|---|---|
| 改界面 | `examples/text-tools/Page.qml` 里按钮的 `label` | 重启后按钮文字变了 |
| 加日志 | `main.qml` 里加 `host.log("warn", "hello")` | 日志文件里出现 `plugin[com.assistant.texttools]: hello` |
| 故意写坏 | `plugin.json` 的 `version` 改成 `1.0`（不是 SemVer） | 卡片标「不可用」，**程序不崩**，能卸载 |

第三个动作最能说明设计立场：**坏插件是数据问题，不是崩溃**。

## 5. 高频提问与标准回答

**Q：插件能读我的文件吗？**
能。它和宿主同进程、同权限，`permissions` 只是声明、宿主不拦截。所以安装确认框里明写了"没有沙箱"。
> 别说成"有权限系统"——那是虚假安全感，一被追问就崩。

**Q：为什么不用 DLL 插件？**
ABI。MSVC 下跨 DLL 传 `QString`/`std::string` 要求工具链、STL 版本、Debug/Release 全对齐，而项目 Debug/Release 是两套 vcpkg 路径。QML 包没有 ABI，还能"加载失败不崩进程"。`plugin.json` 留了 `runtime: native` 的口子，v1 直接拒装。

**Q：为什么不热更新？**
QML 把组件编译结果缓存在引擎里，已实例化的对象还在内存里。同进程替换 `main.qml` 后不保证拿到新版本，清引擎缓存又会把宿主自己的界面一起清掉。重启是正确解。

**Q：怎么保证插件不是恶意的？**
保证不了。只保证**包没被改过**（sha256）和**版本对得上**。签名（证明作者是谁）是 v2 的事。

**Q：别人怎么知道该怎么写？**
`docs/plugins/README.md` 是完整的接口文档；`examples/text-tools/` 是可以直接抄的活的参考；`tools/plugin-new.ps1` 一条命令出骨架；金丝雀插件（`tests/fixtures/plugin-full/`）保证我改接口时会先红。

**Q：这套接口稳吗？**
有版本号：`manifestVersion`（清单格式）、`engines.assistant`（宿主版本）、`host.apiVersion`（API 面）。承诺是"只增不改，改语义就升版本"。

## 6. 现场别做的事

| 别做 | 为什么 |
|---|---|
| 演示真实联网下载 | 网络不稳；而且真实索引还没托管，`ASSISTANT_MARKET_URL` 是唯一入口 |
| 演示签名/沙箱 | 都没有，讲清楚"没有"比演示一个假的强 |
| 演示卸载失败 | `.trash` 里残留是已知行为，会被当成 bug |
| 讲"自动更新" | 没有，而且我们明确说不做 |
| 现场改 C++ 再编译 | 编译 1–3 分钟，节奏会断 |

## 7. 结束后发什么给对方

一个文件夹就够：

```
给作者的包/
├─ README.md              ← docs/plugins/README.md（接口文档）
├─ examples/text-tools/   ← 参考插件
└─ tools/
   ├─ plugin-new.ps1      ← 生成骨架
   └─ plugin-pack.ps1     ← 打包 + 算 sha256 + 出索引条目
```

对方只要装了 Assistant（或自己编译一份），把插件目录放进
`%LOCALAPPDATA%\AssistantTeam\Assistant\plugins\<id>\` 重启，就能看到自己的插件。

**一句话交代边界**：插件跟宿主同权限、没有沙箱、没有签名、升级要重启——这四条先说，比事后解释便宜。

## 8. 现在的短板（被追问时用得上）

| 短板 | 现状 | 补上的代价 |
|---|---|---|
| 真实市场没托管 | 只有 `ASSISTANT_MARKET_URL` 指向本地/任意静态站 | 1–2 天 + 一个 GitHub 仓库 |
| 权限不拦截 | 只声明 | 2–3 天（要真加网络/文件能力时才值得） |
| 无签名 | 只有 sha256 | 另开一条线 |
| `commands`/`searchProviders` | 解析了但没消费方 | 等搜索融合层（A7） |
